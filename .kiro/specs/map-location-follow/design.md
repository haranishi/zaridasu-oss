# 地図の現在地追従の設計

要件は [requirements.md](requirements.md)。ここには、コードを読んでも分からない理由と、捨てた案を書く。

## 方式：Leafletの `locate` を使わず、位置の監視を自前で持つ

Leafletの `map.locate({ watch: true, setView: true })` なら数行で済むが、`setView` が位置の更新のたびに効く。利用者が地図を動かしても次の更新で戻され、止める手段は `stopLocate`（点も消える）しかない。
そこで、位置の取得（`watchPosition`）・状態・地図の動かし方を分け、Reactの状態で持つ。点はreact-leafletの `CircleMarker` と `Circle` で描く。

状態は `LocateControl` の中に閉じる。位置が届くたびに再描画されるのは、このコンポーネントだけで、位置の状態で `MapView` が再描画されることはない。地図が動いたとき（追従の自動移動を含む）は、既存の `BoundsWatcher` が表示範囲を更新するので、`MapView` は再描画される。

## 構成

`src/features/` に置かず、層ごとの置き場所に分ける。`features/<名前>/` に置いてよいのは「自分のDBの表を持つ」などの3条件をすべて満たす機能だけ（[構造規約](../../../docs/project-structure-conventions.md)）で、追従は表を持たない。

| ファイル | 役割 |
|---|---|
| `src/lib/maps/locationFollow.ts` | 状態遷移（純関数）、位置の変換、定数。ブラウザにも地図にも依存しない |
| `src/hooks/useLocationWatch.ts` | `watchPosition` の開始・停止。ページが隠れたら止め、戻ったら取り直す |
| `src/hooks/useFollowCamera.ts` | 地図を動かす規則と、利用者が動かしたことの検出 |
| `src/hooks/useScreenWakeLock.ts` | 画面を点けたままにする（非対応でも黙って続ける） |
| `src/components/features/map/LocateControl.tsx` | ボタン、点と円の描画、通知、追従中の絞り込みオフ。`MapView` の旧 `LocateButton` を置き換える |

## 状態遷移

| 今 | 押す | 位置が届く | 地図を動かされる | エラー |
|---|---|---|---|---|
| 停止 | 取得中 | 無視 | 無視 | 許可なし・非対応は通知して停止のまま |
| 取得中 | 停止 | 追従（最初の位置で寄せる）。動かされていれば一時停止（寄せない） | 動かされたことを覚える | 通知して停止 |
| 追従 | 停止 | 点を更新し、必要なら寄せる | 一時停止 | 許可なしは通知して停止。取得不能・時間切れは無視 |
| 一時停止 | 追従（現在地へ寄せる） | 点だけ更新 | 無視 | 追従と同じ |

停止に戻るとき、保持している位置を捨てる。取得中・追従・一時停止の間だけ、取得と画面ロックが動く。
取得中に利用者が地図を動かしたら、位置が届いても追従にせず一時停止にして、地図を引き戻さない（位置を待つ間に見ていた場所を奪わない。体験評価で見つかった）。その場で一時停止にしないのは、位置がまだ無く、点を出せないから。「最初の寄せ」は、そのあと押して追従になったときに行う。

## 位置の取得

`enableHighAccuracy: true, maximumAge: 5000, timeout: 20000`。網による測位は数百m〜数kmずれ、車の追従にならない（電池を使うのは追従中だけ）。5秒は、開始直後に古い位置を出さないため。起動直後のGPSは10秒を超えることがあるので20秒（Leafletの既定は10秒）。

エラーはコード1を「許可なし」、2を「取得不能」、3を「時間切れ」にする。ブラウザは静止中でも時間切れを繰り返すことがあるので、最初の位置が来たあとの2と3は無視する。

## 地図を動かす規則

- 最初の位置：`setView(位置, max(今のズーム, 14))`。旧実装は `maxZoom: 14` で、ズームしていても14へ引き戻していた。
- 以降：点が画面の中心から8px以上離れたときだけ `panTo`（ズームは変えない）。小さい縮尺では、車が動いても点はほとんど動かない。毎秒動かすと、`HomePage` の境界の再計算を無駄に増やす。
- 滑らかさ：`duration 1秒, easeLinearity 1`。位置は約1秒ごとに届くので、連続して流れて見える。「視覚効果を減らす」では `animate: false`。

**利用者が動かしたことの検出**は、`movestart` で行う。自分の `panTo` には `noMoveStart: true` を付けるので、自分の移動は `movestart` を出さない。だから `movestart` は、利用者（またはほかの部品）の移動だけを表し、一時停止にする。
「自分の移動の印を立てて `moveend` で降ろす」作りにはしない。滑らかな動きの最中に次の位置が届くと、Leafletが前の動きを止める `moveend` が、新しい動きの `movestart` より先に出て、印が先に消える。位置は約1秒ごと、動きも1秒なので、車での連続した移動では毎回起きる（独立レビューで見つかり、試験で再現した）。同期で終わる最初の `setView` だけは、実行中の印（`ownCall`）で見分ける。
ズームの最中（`zoomstart`〜`zoomend`）の `movestart` は、その場では判定しない（Leafletは `zoomstart` を先に出す）。終わったときに中心が48px以上ずれていたら、一時停止にする。ボタンやピンチのズームは中心がほとんど動かず、ほかの部品の `setView`・`flyTo` や、遠くのダブルタップ拡大は大きく動く。
`dragstart` は、ズームの最中でも必ず利用者の操作として止める。途中で止められた `flyTo` は `zoomend` を出さないので、次の `moveend` でもズーム中の印を降ろす。
ズームのアニメーション中、Leafletは `setView` を黙って捨てる（`_tryAnimatedZoom` が先に `true` を返す）。そのあいだに届いた位置は、`zoomend` のあとで寄せる。
画面サイズの変化（`MapResizer` の `invalidateSize()`）は `movestart` を出さないので、止まらない。

## 画面を点けたままにする

追従中に画面が消えると、ブラウザが位置の更新を止める。取得中・追従・一時停止の間は `navigator.wakeLock.request('screen')` を持つ。ページが隠れるとOSが解放するので、見える状態に戻ったら取り直す。失敗（非対応・省電力・拒否）は無視する。

## 描画

- 点：`CircleMarker`（半径9、`#3B82F6`、白い縁3px）。吹き出しは「現在地（誤差 約Nm）」。従来は半径8・縁2pxだったが、視覚評価3人が「まとまり（約34px）に埋もれる」と指摘した。
  その下に、押せない暗い半透明の輪（縁取り）を置く。明るい地図で白い縁が溶けず、赤いまとまりに乗っても別の物と分かる。影（CSSのfilter）はSVGの内側の図形でブラウザごとに差が出るので使わない。
  **専用の層（`zari-user-location`、z-index 620）に描く。** Leafletの標準では、図形（400）は投稿のマーカーやまとまり（600）の下に描かれ、投稿の多い場所で現在地がまとまりの下に隠れる。マーカー（600）より上、ツールチップ（650）・吹き出し（700）より下に置く。スクショの確認で見つけた。
- 札：ボタンの左の小さな説明（`useLocateHint`）。取得中は3秒で「取得しています」、10秒で「時間がかかっています」（時間切れの通知は20秒）。追従と一時停止は、最初の1回だけ6秒、止め方・戻り方を出す（毎回は運転中に邪魔）。
  文は1文ごとに改行（翻訳の `\n` と `whitespace-pre-line`）し、語の途中で折れないようにする。共通のトーストは閉じる手段が無く、位置が届いたあとも残るので使わない。読み上げのため `role="status"` の領域は常に残す。
- 円：`Circle`（半径＝精度m、薄い塗り）。**`interactive: false`**。押せる円だと、地図のクリック・長押し・ピン立てを円が受けてしまう。
- ボタン：停止は白地・灰色の輪郭の矢印（従来のまま）。取得中は黒地・輪郭の矢印（脈動）、追従は黒地・塗りつぶしの矢印、一時停止は白地・3pxの黒枠・十字（`LocateFixed`）。
  取得中と追従は脈動だけで分けない（静止画や「視覚効果を減らす」で同じに見える）。取得中は内側に点線の輪を描く（`outline` は使えない：Leafletが地図の中の `mousedown` ごとに、押した要素の `outline` を消す）。一時停止は停止と枠だけの違いだと「押すと戻る」が読めないので、形も変える。
  名前は常に「現在地を表示」。名前が変わるボタンに `aria-pressed` を付けると読み上げが食い違うので、押下状態（取得中・追従で true）だけを `aria-pressed` で伝え、押すと起きることは `title` で変える。

## 位置の扱い

追従のために取った座標は、Reactの状態（メモリ）にだけ置く。当サイトのサーバー・計測・ログ・ストレージには自動では書かない。`console` も使わない。利用者が押した機能（投稿・「非公開で保存」・「近くの水域を探す」）は、その機能に必要な座標を使う（独立レビューの指摘で、文面を限定した）。
地図の背景画像は、表示している地域の分を提供元（OpenStreetMap・国土地理院）から取る。追従中は現在地の周辺の地域が、IPアドレスとともに提供元に伝わる。手で動かしても同じ仕組みで避けられない。座標そのものは送られないので、プライバシーのページに事実として書く（独立レビューの指摘）。

**抜け道が1つあった。** 「現在の地図範囲内のみ」がオンだと、地図を動かすたびに範囲（南北・東西の座標）が検索条件として送られる（`usePostList` の `buildQuery`）。追従中は範囲が現在地を中心に動くので、オンのまま追従すると、移動の軌跡がログイン中の利用者のIDと一緒にサーバーのログに残る。
そこで、取得中・追従中はこの絞り込みをオフにして知らせる（`LocateControl` が `onBoundsFilterOff` を呼ぶ）。一時停止中は、利用者が見る場所を選んでいるので使える。
追従中にオンにされても、`HomePage` の検索は300msのデバウンスつきで、同じ描画のうちに絞り込みが切れて予約が取り消されるので、範囲つきの検索は送られない。
ほかの経路（近くの水域・調査・クイック保存）は、利用者がボタンを押したときだけ、中心や現在地を使う。

## 捨てた案

| 案 | 捨てた理由 |
|---|---|
| `locate({ watch: true, setView: true })` | 上のとおり、動かしても戻される |
| `setView: false` で `dragstart` だけで一時停止 | 矢印キー・吹き出しの自動移動・ほかの部品の移動では止まらず、追従が戻して邪魔する |
| 移動の印を「時間の窓」で判定 | 窓の中で利用者がドラッグを始めると自分の移動と誤判定し、地図を動かせなくなる。開始と終了の印なら誤判定しない |
| 位置をContextで全体に配り、投稿・調査と共有 | 依頼の範囲外。位置の寿命と同意の扱いが広がる |
| 位置の平滑化 | 点が実際の位置より遅れる。端末の測位がすでに平滑化している |
| 追従中は、範囲を粗い格子に丸めて検索に送る | 一覧の意味（見ている範囲の記録）が追従中だけ変わる。`MapView` と `HomePage` の両方を変えることになる |
| 軌跡が残ることを、文面で開示するだけにする | 軌跡がログに残る事実は変わらない |
| 追従を止めたら、絞り込みを元のオンに戻す | 利用者が選んだ状態を、こちらが勝手に動かし続けることになる。通知は「オフにしました」と事実だけを書く |
| 位置を待つ間の説明を、3秒後のトーストで出す | 共通のトーストは閉じられず、位置が届いたあとも「取得しています」が残る |

## 落とし穴

- 地図は `HomePage` の横スライドの中にあり、リストへ切り替えても作り直されない。追従は保たれ、リストを見ている間も取得は続く。`MapView` の `key`（初期範囲）が変わると作り直され、停止に戻る。
- iOSの許可ダイアログは、操作の直後でないと出ないことがある。初期表示で呼ばない（REQ-324）のはこのためでもある。
- 画面ロックやアプリ切替でブラウザが止まる間は、取得できない。戻ると `visibilitychange` で取り直す。
