# マイページに、活動した日を「草」で見える化する

2026-10-19、本人（音声）の依頼。GitHubの貢献グラフのように、自分が活動した日をマイページで見られるようにしたい。投稿や活動が活発な人ほど、草が生える（濃くなる）イメージ。
同日、本人が方針を決めたので、実装に進んだ（決定は下の「本人の決定」）。本番反映は、本人の合図から。

## 設計の方向

- 場所：マイページ（`/dashboard`）。公開プロフィールには出さず、本人だけが見る。
- 活動した日：本人が記録を投稿した日。審査待ちも投稿した日に数え、却下は数えない。「見つからなかった」の記録も同じ1件。日付は観察日（なければ投稿日）を日本時間で区切る。
- 濃さ：その日の件数で5段階（0〜4）。5件以上は同じ濃さ（頭打ち）。
- 出さないもの：連続日数、途切れの表示、他人との比較・順位、いいねやコメントによる加点。

## なぜこの方向か

現行の方針は「いいねを報酬にしない」「量産で稼ぐ動機を断つ」（`docs/current/gamification.md`。XPは1日120まで）。濃さを件数に比例させず頭打ちにするのは、この方針に合わせるため。
「見つからなかった」の日も草になるので、調べた日そのものが積み上がる。不在の記録は研究で足りていない種類でもある（10/19時点で公開記録のうち5件）。
既存のクエストは「任意・無罰」で、喪失ベースのストリークを持たない（REQ-251）。連続日数を出すと、休んだ日が罰に見えるので出さない。
本人だけに見せるのは、最初から比べ合う場にしないため。公開は、あとから「公開してよい」の設定を足して選べる。

## ユーザーストーリー

| ユーザー | 欲しいこと（理由） | 受け入れ条件 |
|---|---|---|
| 続けて記録する人（本命） | 自分が記録した日が積み上がるのを見たい（続けている実感がほしい） | 過去1年のカレンダーに、記録した日が濃く出る。件数が多い日ほど濃い |
| しばらく空いて戻った人 | 空白を責められたくない（また始めやすくしたい） | 連続日数も途切れの表示もない。記録ボタンが近くにある |
| 初めての人 | 草がまだ無くても寂しくならない（最初の1日を置きたい） | 空のカレンダーと一言、「記録する」ボタン |
| 調査する研究者（このアプリが救う相手） | 量より、通った日数・探した日数が増えてほしい | 不在の日も草。1日の濃さは頭打ち。順位・比較はない |

## UXの5階層

| 階層 | 決めたこと |
|---|---|
| 戦略 | 目標は、30日以内の再調査と、続けている実感。差別化は、濃さが「量」でなく「調べた日」に寄ること |
| 要件 | 載せる：1年分のカレンダー、日の詳細、合計、一覧。対象外：連続日数、比較、公開、共有、通知 |
| 構造 | マイページの進捗の下。日を選ぶと詳細が開く。一覧（開閉）が同じ内容の別の入口 |
| 骨格 | 週を列、曜日を行にする（月曜始まり）。いちばん大きい要素はカレンダー1つ。凡例は下に小さく |
| 表層 | 緑の明るさの5段階。セルに枠線をつけ、色だけに頼らない。赤と緑を対にしない。ダーク対応 |

## 本人の決定（2026-10-19）

1. 活動は「投稿」だけ。いいね・コメントでは草を生やさない。
2. 濃さはGitHubと同じ段階で、**5件で頭打ち**。
3. 置き場所は、進捗の下・バッジの上。
4. 連続日数は出さない。本人だけに見せる。（おすすめのまま。異論なし）
5. 審査待ちの扱いは、本人が明言しなかった。そこで「投稿した日に数える（却下は数えない）」で実装した（「活動は投稿だけ」という決定に沿う解釈）。変えるときは `src/lib/data/posts-own.ts` の `ACTIVITY_STATUSES` の1行と、カードの注記・テスト。**本人の確認待ち**。
