# ザリダスのcc-sdd運用

cc-sdd 3.1.0の日本語テンプレートを導入した。既存アプリの仕様とREQを引き継ぎ、新しい変更だけを仕様駆動で進める。

## 作業を始めるとき

1. `AGENTS.md` と、[プロジェクト概要](steering/product.md)・[技術方針](steering/tech.md)・[構造方針](steering/structure.md) を読む。
2. [現行仕様の入口](../docs/current/README.md) から対象領域のページを確認し、関連する既存REQと実装を照合する。
3. `kiro-discovery` で、既存REQの継続・小さな直接修正・新規仕様のどれかに振り分ける。

既存REQで完結する変更は、その要件と承認状態を引き継ぐ。REQをすべて移植したり、同じ進捗を別の表で管理したりしない。

## 新しい仕様を進めるとき

新規機能や大きな改修は `specs/<機能名>/` に仕様を作る。ここでいう機能は、変更の責任範囲を1つに説明できる単位。

| 段階 | スキル | 残すもの |
|---|---|---|
| 対象を整理 | `kiro-discovery` | 必要に応じて `brief.md` |
| 仕様を開始 | `kiro-spec-init` | `spec.json`、要件の初期ファイル |
| 要件を具体化 | `kiro-spec-requirements` | `requirements.md` |
| 設計する | `kiro-spec-design` | `design.md`、必要な調査記録 |
| 実装を分ける | `kiro-spec-tasks` | `tasks.md` |
| 実装・検証 | `kiro-impl`、`kiro-validate-impl` | 実装、検証の証拠、タスクの更新 |

要件・設計・タスクを提示し、対象フェーズの承認を得て次へ進む。開始の依頼を、まだ提示していない仕様の承認とは扱わない。
`-y`・`--auto` による承認省略は、本人がその範囲を指定した場合に限る。
承認済みのフェーズを引き継ぐときは、会話や元要件の根拠を確認して `spec.json` を更新する。

Claude Code・Antigravity・Cursorでは `/kiro-discovery 内容`、Codexでは `$kiro-discovery 内容` が入口になる。
ホストがスキルを読み込める状態で使う。グローバルスキルでも `.kiro/` はこのプロジェクトから解決する。

## 文書の正本を分ける

| 場所 | 扱う内容 |
|---|---|
| `docs/current/` | 実装済みの現在の挙動・制約 |
| [docs/screens](../docs/screens/README.md) | 利用者向けの画面・操作・遷移の案内 |
| [docs/architecture](../docs/architecture/README.md) | 設計思想・コードの責任・主要な処理・ファイル索引 |
| `docs/requirements/` | 既存REQの要件・履歴・進捗 |
| `.kiro/steering/` | 変更を判断するためのプロジェクト共通方針 |
| `.kiro/specs/<機能名>/` | 新規仕様の要件・設計・タスク・承認状態 |
| `.agent-harness/` | 適用する工程契約と実行記録 |

新規仕様に関連REQがある場合は、そのREQを参照する。実装が完了したら対象領域の `docs/current/` を更新する。
既存のバックログには古い技術前提が含まれるため、優先順位や未実装状態をそのまま採用しない。

## 検証と権限

- 文書・設定だけの変更は、参照先・JSON・差分を確認する。挙動を変えるときは対象のテストと既存の検査手順を使う。
- アプリの検査は `package.json`、`scripts/precheck.mjs`、CIを正とする。実施した検査と未確認の範囲を分けて報告する。
- UI変更では既存のユーザーストーリー・UX設計・画面検証を、DB変更では既存の権限と非公開データの検査を引き継ぐ。
- cc-sddの手順に自動コミットが含まれていても、commit・push・PR・公開は今回の明示指示がある範囲で行う。
- 実行中ホストの権限・委譲ルールに従う。同一セッションで行ったレビューは、独立レビューと区別する。
- 改善は最大3周。同じ失敗が2周続いたら、原因と残件を整理する。

## 導入・保守

`.kiro/settings/templates/` は公式配布物から生成したテンプレート。既存のプロジェクト指示とREQは保持している。
同梱範囲の権利表示は [MITライセンス原文](settings/LICENSE) と [第三者表示](../THIRD_PARTY_NOTICES.md) を参照する。
公式テンプレートの構成は維持し、末尾空白・末尾改行とMarkdownの改行記法だけを正規化した。
個人のグローバル設定・認証情報・ローカル環境ファイルは、このディレクトリへ取り込まない。
更新時は別の作業場所で同じ言語・保存先を指定して生成し、差分を確認して取り込む。
