# 設計思想を、利用する場面から知る

ザリダスが大切にしているのは、**参加しやすさ、記録の質、場所の保護**です。
市民の観察を地域の調査へつなぐため、次のように画面とデータの扱いを組み合わせています。
実装の背景は [設計判断の詳しい説明](../docs/architecture/philosophy.md)、研究の目的は [研究背景](01-research-context.md) を参照してください。

## まず見る。必要になったら参加する

初めて訪れた人は地図や写真からアプリを知り、記録したくなったところで登録・ログインへ進めます。
初回案内は、地域を選び、地図の読み方を知って、見る・投稿するへつなぐ4画面です。
説明を読むだけで終わらず、次の操作へ進めるようにしています。[認証と初回案内](../docs/screens/account.md)

## 投稿数だけで、よい調査になったと考えない

同じ場所から大量に投稿されることと、地域の状況が分かることは別です。
写真・音声・観察日時・調査方法などを残し、審査で公開する記録を確認します。
ランキングは多様性を先に見せ、図鑑や貢献の表示も、承認された記録をもとにします。
これらが参加や品質をどれだけ改善したかは、別に測定する課題です。[個人の活動](../docs/screens/personal.md)・[集計](../docs/screens/explore-and-data.md)

## 地図に載せることと、正確な場所を渡すことを分ける

外来種の公開位置は小数3桁への粗化が既定です。投稿ごとの公開設定もあり、公開データセットはさらに一律に粗化します。
本人用のスポット・調査計画・希少種は別に保存し、公開地図へそのまま流しません。
画面で隠すだけでなく、DB側にも読める行・列・操作の制限を置きます。[位置の現行仕様](../docs/current/privacy.md)

## 「記録がない」と「生息していない」を分ける

地図の空白には、誰も投稿していない、位置を公開していない、取得できなかったなどの可能性があります。
水域探索でも、全件を取得できなければ件数は不明として扱います。
現地で見つからなかった観察は、明示的な不在確認として残す別の操作です。[水域](../docs/screens/water.md)・[現地調査](../docs/screens/fieldwork.md)

## 圏外でも、端末の記録と送信済みを区別する

未送信の記録は端末に保持し、通信が戻ったら本人が確認して送れます。
端末に保存できたことを、DBへの保存や公開の完了とは表示しません。
同じ端末で別の人がログインしても、前の人の調査や下書きを混ぜない設計です。[マイページ](../docs/screens/personal.md)

## 画面と設計判断の対応

| 画面で見えるもの | 何のためにあるか |
|---|---|
| 地図と写真の切替 | 場所から探す人と、記録の内容から探す人の両方を支える |
| 投稿の審査状態と却下理由 | 保存・確認・公開を区別し、本人が記録を見直せるようにする |
| 本人用の調査パネル | 公開共有とは別に、次の行動と非公開の記録を管理する |
| 貢献・図鑑・任意のクエスト | 観察を続ける手掛かりを作る。効果を実証したという意味ではない |
| エラーと再試行の表示 | 取得失敗を、0件や完了として見せない |
| メニューの言語・テーマ・案内 | 使う環境に合わせ、必要な説明を読み直せるようにする |

[画面ガイド](../docs/screens/README.md) では、これらを具体的な操作に沿って説明します。
