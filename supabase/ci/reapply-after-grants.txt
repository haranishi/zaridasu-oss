# REQ-282 C-2: 「Supabase 既定の一括 GRANT の“後”に再適用しないと効かない」migration の宣言リスト。
#
# 背景: rls-tests ジョブは schema.sql 適用 → Supabase 既定の一括 GRANT（GRANT SELECT ... ON ALL
#   TABLES / GRANT EXECUTE ON ALL FUNCTIONS）を再現する。この一括 GRANT は
#   (1) テーブルレベル SELECT を復活させて列レベルの REVOKE（reporter_ip / lat / lng / accuracy 等の
#       PII 保護）を上書きし、
#   (2) 関数レベルの EXECUTE REVOKE（anon から剥がした RPC）も同時に打ち消す。
#   そのため該当 migration を既定 GRANT の「後」にもう一度流して最小権限を再確定する必要がある
#   （本番でも同じ理由で該当 migration が既定 GRANT 後に効く前提）。
#
# 運用ルール（追加漏れ防止）:
#   - 列レベル REVOKE / 列保護トリガー / **関数の EXECUTE REVOKE**（anon・authenticated から剥がす）を
#     新設・改訂する migration を追加したら、このファイルにも追記する
#     （CI がこの順に psql -f で再適用する）。
#   - 1 行 1 ファイル。'#' 始まりはコメント、空行は無視。パスは supabase/migrations/ からの相対。
#   - **順序が重要**: 上から順に適用される。後段が前段の関数を CREATE OR REPLACE で上書きする
#     依存があるため、並べ替えないこと（例: 000002 は 000001 が定義した protect_post_insert_columns
#     を完全版へ上書きする）。
#
# 注: storage RLS（20260513000007_storage_owner_folder_upload.sql）は storage スキーマスタブを
#   前提とする別ステップのため、この宣言リストには含めない（CI 側で個別に適用）。
