# 設計思想と判断の根拠

ザリダスは、市民の小さな観察を地図と記録に集約し、秋田の外来種の調査・管理へつなぐ。
目的の正本は [プロジェクト背景](../philosophy/background.md) と [研究上の位置づけ](../../README/01-research-context.md)。以下は、それを現在の実装でどう支えているかの案内。

## 参加・継続・データ品質を分けて考える

記録を増やすだけでは、観察場所の偏りや写真の不足を解決できない。
研究の説明は参加率・継続率・データ品質を別々に評価し、実装にも多様性、調査依頼、貢献レベル、研究KPIの経路がある。
図鑑やランキングの役割は [参加機能](participation.md)、集計の役割は [研究データ](data-model-research.md) を参照する。
これらの効果が実証済みである、という意味ではない。効果の検討には [KPI運用](../runbooks/kpi-weekly-review.md) の観測が必要。

## 公開する価値と、場所を守る必要を両立する

公開地図は承認済み記録の公開用座標を使う。正確な位置、粗化した位置、非公開を区別し、本人や管理者の経路を分ける。
非公開スポット・調査計画・希少種は、一般公開する投稿と別のデータモデルで扱う。
「公開画面で隠す」だけで成立させず、DBのRLS・列権限・RPCまで境界を置く。根拠は [privacy](../current/privacy.md)、[認可](authorization.md)。
写真は保存前に画像へ変換し直すが、これで写り込んだ人や風景を消せるわけではない。データ公開の条件も別途確認する。

## 未知と不在を混同しない

地図で記録が見つからないことは、その水域に生きものがいない証拠ではない。
水域探索は集計の切詰めや取得失敗を扱い、件数を確認できない状態を0件として示さない。
調査で「見つからなかった」を残す場合は、[フィールドワーク](fieldwork.md) の明示的な確認と位置条件を通す。
根拠：[水域の契約](../../src/features/water/README.md)、[非公開調査の現行仕様](../current/fieldwork.md)。

## 画面の都合から、公開の定義を切り離す

[posts.ts](../../src/lib/data/posts.ts) は、承認状態・公開列・公開座標の選択を共有する。
同ファイルのコメントは、公開判定と座標選択の散在を解消した経緯、汎用のselectラッパーが型展開を悪化させた理由を記録している。
そのため用途ごとのリテラルなselectを保ち、画面固有の並びや絞り込みは呼び出し側が加える。
構造をそろえる変更でも、ホームの容量予算や型検査への影響を確かめる。すべての呼び出しを機械的に共通化する方針ではない。

## 端末の操作を止めず、結果の確実さを分けて伝える

地図の幾何計算や画像変換はWorkerへ逃がし、重い機能は必要なときに読み込む。
オフライン記録は端末の未送信状態として保持し、サーバーへ保存できたことと区別する。
通知は本体処理から分離されるが、[通知ごとに失敗の返し方と購読設定の扱いが異なる](notifications-ai.md)。
権限の拒否、審査待ち、未知の判定は成功へ読み替えない。更新結果の0行検査などは [投稿の契約](../current/posts.md) を守る。

## 単独運用で扱える境界を保つ

[proxy.ts](../../src/proxy.ts) には、外部KVを追加せず、インスタンス内の制限とDB側の強制を分けた理由が記録されている。
Rust/Wasmも水域の計算部分だけを受け持ち、通常ビルドは同梱成果物を検証する。[水域設計](water-geometry.md) を参照する。
これらは現在の選択。将来の負荷や要件にも十分だと保証するものではない。

## 利用者に伝える言葉

サービスの表現は [ブランドメモ](../brand/brand-memo.md) を正本とし、平易な言葉と4言語の一貫性を重視する。
開発・研究文書の説明と、利用者向けのコピーの方針を混同しない。
