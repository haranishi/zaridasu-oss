## 4. 一次連絡 文面テンプレート

> 事実確認の前に **原因・影響範囲・賠償を確約しない**。「確認中であること・追って続報すること」を伝えるに留める。秘密値・PII は本文に書かない。

### 4-1. 利用者向け（サービス障害・初報）

```
件名: 【ザリダス】サービスに関するお知らせ（確認中）

現在、ザリダスの一部機能（<例: 投稿 / 地図表示 / 種判定>）について不具合を確認しており、
原因の確認と復旧対応を進めています。
ご不便をおかけし申し訳ございません。状況が分かり次第、改めてお知らせいたします。

<連絡手段 / 続報の出し方>
```

### 4-2. 利用者向け（個人データ漏洩の疑い・初報）※公表前に内容と要否を慎重に判断

```
件名: 【ザリダス】お客様の情報に関する重要なお知らせ（調査中）

このたび、<概要: 何が・いつ確認されたか（事実のみ）> の事象を確認し、現在、影響範囲を調査しています。
判明している事実と、対象となる可能性がある情報の種別、推奨される対応については、
確認が取れ次第、速やかにお知らせいたします。
ご心配をおかけし誠に申し訳ございません。

<問い合わせ先 / 続報予定>
```

> 上記は**初報の雛形**。実際の本人通知・公表は、影響範囲が固まり、個人情報保護委員会への報告要否・記載事項を確認した上で行う。**断定表現・補償の確約は入れない**。文案に迷う場合は専門家に相談。

### 4-3. 各社サポートへの問い合わせ（要点）

```
- 事象種別      : セキュリティ / 不正利用 / 課金異常 / データ復旧（該当を明示）
- 発生日時(TZ)  : 
- 対象          : プロジェクト ID / リソース名（秘密値は書かない・末尾数文字のみ）
- 現象（事実）  : 
- 既に取った対応: 失効 / 公開停止 / kill switch 等
- 依頼内容      : 調査 / 復旧 / ログ提供 など
```
