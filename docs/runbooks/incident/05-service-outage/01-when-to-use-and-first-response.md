## いつ使うか

- 本番（`zaridasu.com`）が**ダウン**している / 大幅に遅い
- 主要機能が動かない: **投稿 / 地図表示 / AI 種判定 / 認証（ログイン）**
- 表示が壊れている（白画面・エラー画面・データが出ない）
- **データ損失の疑い**（投稿 / 写真 / 音声が消えた・件数が激減した）

> セキュリティ起因（攻撃・乗っ取り・漏洩キーによる破壊）と**区別がつかないことがある**。データ損失や不審な削除が絡む場合は、本 runbook と並行して [02-account-takeover.md](./02-account-takeover.md) / [01-secret-leak.md](./01-secret-leak.md) を疑う。

## 初動チェックリスト（この順で）

```
[1] 記録      何が・いつから動かないか。自分だけか全体か（→ evidence-preservation.md）
[2] 保全      エラー画面・Sentry イベント・各社 Status・直近デプロイをスクショ（特にデータ損失の疑い時）
[3] 範囲特定   どの機能が・どこまで落ちているか（下の切り分け表）。プロバイダ障害か自分の変更か
[4] 一次連絡   利用者向けに「確認中」を出す（→ contacts.md §4-1）。確約しない
[5] 暫定回避   直近デプロイのロールバック / 機能の一時停止 / プロバイダ復旧待ち
[6] 復旧      原因を直して本番を戻す。データ損失なら backup-restore.md へ
[7] 検証      主要フロー(投稿/地図/AI/認証)が通ることを確認
[8] 事後      タイムライン・原因・恒久対策を記録（→ 終了条件）
```

### やってはいけないこと

- **データ損失が疑われるのに、確認 / 保全せず復旧操作（再デプロイ・再作成）を急ぐ**（上書きで復元不能になり得る）。
- 攻撃 / 乗っ取りの可能性を**検討せず**「ただの障害」と決めつける。
- 原因不明のまま本番を何度も再起動 / 再デプロイして状態を悪化させる。
- 利用者に復旧時刻を**安請け合い**する。
