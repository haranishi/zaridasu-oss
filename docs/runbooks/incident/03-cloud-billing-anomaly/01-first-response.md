## 初動チェックリスト（この順で）

```
[1] 記録      何が急増(どのサービス/リソース)・いつから・現在の額をメモ（→ evidence-preservation.md）
[2] 保全      ★請求内訳・利用量グラフ・監査ログ・デプロイ履歴を「削除せず」スクショ/エクスポート
[3] 封じ込め   暴走源を止める = 段階的 kill switch（下表）。AI なら AI_ANALYSIS_ENABLED=false 等
[4] 範囲特定   不正利用 / バグ(リトライ暴走) / 正当な増加 のどれかを切り分け
[5] 一次連絡   高額・不正の疑いが強ければ各社サポート（課金異常として）（→ contacts.md）
[6] 通報相談   秘密漏洩起因なら 01、不正アクセス起因なら 02 / 公的窓口（→ contacts.md）
[7] 復旧      原因を塞いだうえで停止した機能を戻す。クォータ/上限を残す
[8] 再発防止   予算アラート/Spend Mgmt/キー制限/リトライ設計の見直し（→ 終了条件）
```

### やってはいけないこと（特に重要）

- **いきなり billing（請求）アカウントを無効化する。** プロジェクトの課金を切ると、**プロジェクトやデータが復旧不能になる破壊性**がある（REQ-218 AC-04）。billing 無効化は「専用プロジェクト + バックアップがある」前提の**最終手段**。まずは機能・キー・クォータで止める。
- 請求明細・利用量・監査ログを**確認 / 保全する前に**リソースを削除する（原因究明できなくなる）。
- 原因（漏洩キー / バグ / 攻撃）を塞がずに機能だけ再開する（また暴走する）。
