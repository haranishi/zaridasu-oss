## いつ使うか

- 秘密（API キー / service-role / トークン / 秘密鍵）を **GitHub にコミット / push してしまった**
- 秘密を **チャット・Slack・CLI 履歴・ログ・スクショ・チケット**に貼ってしまった
- **GitHub Secret scanning アラート**が出た（REQ-210）/ 第三者から「秘密が見えている」と連絡が来た
- 公開すべきでない秘密が **ブラウザ / クライアントバンドル / `NEXT_PUBLIC_` に混入**しているのを見つけた

> **最重要原則: push / 送信した秘密は「漏洩済み」とみなす。**「private リポジトリだから」「すぐ消したから」は理由にならない。**まず発行元で失効 / ローテーション → 次に履歴削除**。順序を逆にしない。

## 初動チェックリスト（この順で）

```
[1] 記録      何の秘密が・どこに(GitHub/チャット/ログ)・いつ出たかをメモ（→ evidence-preservation.md の記録テンプレ）
[2] 保全      該当箇所のスクショ（秘密値そのものは写さない / 末尾数文字・キー ID のみ）。Secret scanning アラートを保存
[3] 封じ込め   ★まず発行元で当該秘密を失効 / ローテーション（下の「対象シークレット表」の順）
[4] 範囲特定   その秘密で何ができたか・悪用の痕跡（課金・不正アクセス・不正送信）を確認
[5] 一次連絡   悪用痕跡があれば各社サポートへ。課金や個人データに波及していれば 03 / 04 へ
[6] 通報相談   不正アクセス / 課金被害があれば公的窓口・各社へ（→ contacts.md）
[7] 復旧      新しい秘密で本番が正常動作することを確認。その後に Git 履歴の対応
[8] 再発防止   .env 運用・スキャナ・キー権限の見直し（→ 終了条件）
```

### やってはいけないこと

- **失効より先に Git 履歴を書き換える**（force push / `git filter-repo` / BFG）。履歴を消しても、push 済みの秘密は既にクローン / キャッシュ / scanning bot に渡っている前提。**先に失効**してから履歴対応。
- 「private だから大丈夫」と失効を後回しにする。
- 新しい秘密を**またチャット / CLI 引数 / コミット**に貼る（同じ事故の再生産）。
- `NEXT_PUBLIC_` に秘密を入れる（クライアントに必ず露出する。`VAPID_PRIVATE_KEY` 等は**サーバー専用**）。
