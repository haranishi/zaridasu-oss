## いつ使うか

- 自分（管理者）または利用者のアカウントに **身に覚えのないログイン / 操作 / 設定変更**がある
- パスワードリセットメールが**勝手に届く**・ログインできなくなった
- `admin_login_attempts` に**連続失敗 / ロック**、見知らぬ IP からのログイン試行
- `audit_logs` に**身に覚えのない admin 操作**（投稿削除・ロール付与・公式化など）
- GitHub / Vercel / Supabase / Google など**運用基盤アカウント**の乗っ取り疑い

> **管理者アカウントは別格に重い。** `app_metadata.role = 'admin'` を持つアカウントは、投稿 / コメント削除・ロール付与剥奪・公式化・承認却下などの**全 admin 操作**ができ、PII を含むデータにも広く触れる。管理者侵害の疑いは「最悪ケース」として扱う。

## 初動チェックリスト（この順で）

```
[1] 記録      どのアカウントに・どんな異常が・いつ（→ evidence-preservation.md の記録テンプレ）
[2] 保全      不審ログイン / 操作の画面・audit_logs・admin_login_attempts を書き出す（消す前に）
[3] 封じ込め   ★パスワード変更 → 全セッションからログアウト → MFA 再設定 → 連携 OAuth 見直し → 使い回し先も変更
[4] 範囲特定   乗っ取り中に何をされたか（操作・データ閲覧/改ざん・送信・課金）を確認
[5] 一次連絡   復旧不能ならプラットフォームの復旧フォーム。利用者影響があれば一次連絡（→ contacts.md）
[6] 通報相談   不正アクセスは犯罪相談の対象になり得る。個人データ閲覧/流出なら 04 へ（→ contacts.md）
[7] 復旧      乗っ取り由来の変更を巻き戻す。管理者なら不正に付与された admin ロールを剥奪
[8] 再発防止   MFA 必須化・パスワード使い回し解消・連携アプリ棚卸し（→ 終了条件）
```

### やってはいけないこと

- パスワードだけ変えて**セッション破棄（全ログアウト）を省く**（攻撃者の既存セッションが生き残る）。
- 乗っ取り中の操作ログ（`audit_logs` 等）を**確認 / 保全する前にデータを消す**。
- 復旧を焦って、攻撃者が仕込んだ**連携 OAuth アプリ / 新規セッション / メール転送設定**を見落とす。
- 不正に付与された **admin ロールの剥奪を後回し**にする（侵害が継続する）。
