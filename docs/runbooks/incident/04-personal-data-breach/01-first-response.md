## 初動チェックリスト（この順で）

```
[1] 記録      何が・いつ・どう漏れた(疑い含む)かを事実ベースでメモ（→ evidence-preservation.md）
[2] 保全      ★消す・上書きする前にまず記録。漏洩経路の画面・ログ・該当データを保全
[3] 封じ込め   公開設定の修正・共有リンク無効化・漏れた経路を塞ぐ（拡大を止める）
[4] 範囲特定   どの種別のデータが・誰の分が・何件・どの期間、外部に出たか（下の漏洩区分表）
[5] 一次連絡   関係者へ「調査中」を共有（確約しない）。重大なら早めに準備を開始
[6] 通報・相談  ★個人情報保護委員会への報告義務の判断（下のトリガ表）＋本人通知の判断
[7] 復旧      経路を塞ぎ、再発しない状態にしてから通常運用へ
[8] 再発防止   原因(RLS/公開設定/誤送信/漏洩キー)の恒久対策（→ 終了条件）
```

### やってはいけないこと

- **証拠を保全する前に、漏れたデータ / ログ / 公開物を消す。**「消せばなかったことになる」ではない。記録 → 保全が先（→ [evidence-preservation.md](./evidence-preservation.md)）。
- 事実確認の前に、利用者へ「漏れていません」「補償します」等を**断定する**。
- 報告義務の判断を一人で抱えて**期限を逸する**。**迷ったら早めに個人情報保護委員会・専門家に相談**（相談は無料）。
- 本人通知 / 公表を、影響範囲と記載事項が固まる前に独断で出す（誤情報の拡散）。
