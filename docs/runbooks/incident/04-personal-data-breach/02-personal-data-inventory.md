## ザリダスが保持する個人データ（漏洩区分の一覧）

> 漏洩したデータがどれに当たるかをまず特定する。**「誰の分が・何件・どの期間」**を埋める。

| データ種別 | 保持場所 | PII としての性質 / 機微度 | 取得経路（漏れやすい所） |
|---|---|---|---|
| **メールアドレス** | `auth.users.email`（`get_admin_*` / view が参照: `supabase/schema.sql:448`/`:463`/`:475`/`:778`） | 直接的な識別子。連絡先 | 管理者ビュー / RPC、Resend 誤送信 |
| **IP アドレス** | `posts.reporter_ip`（`:31`）/ `reports.reporter_ip`（`:259`） | **PII として保護対象**（REQ-179 / REQ-211）。匿名投稿時に自動記録（`set_post_reporter_ip` `:134-146`） | 公開投稿フォーム経由で自動取得される |
| **位置情報** | `posts.lat/lng`（`:16-17`）/ `survey_requests.lat/lng`（`:1191-1192`） | 自宅・行動圏の推定につながり得る。地図上で可視化 | 投稿 / 調査依頼。公開地図の精度設定 |
| **投稿写真 / 音声** | Supabase Storage `post-photos` / `post-audio` | 背景・話者から個人特定の可能性 | バケットの公開設定・署名 URL |
| **プロフィール** | `user_profiles`（`:1099-`：display_name / avatar / bio） | 自己開示情報 | 公開プロフィール |
| **ログイン試行** | `admin_login_attempts`（`email_hash`・`ip`。`:1067`） | ハッシュ済みだが ip は PII | 監査・管理系 |

> **複合リスクに注意**: 単体では弱くても「メール + 位置情報 + 写真」が**紐付いて**漏れると特定性・機微度が跳ね上がる。区分は単独でなく**組み合わせ**で評価する。
