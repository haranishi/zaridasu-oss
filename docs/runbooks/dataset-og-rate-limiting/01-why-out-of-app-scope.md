## 背景：なぜこれらはアプリ内レート制限の対象外なのか（設計どおり）

`src/middleware.ts` の matcher は **`/dashboard/:path*` と `/admin/:path*` のみ**（REQ-212）。
`/dataset/*` と `/api/og` は意図的に matcher 外＝エッジのインメモリ・レート制限（REQ-212）を受けない。

- 公開 GET・閲覧系であり可用性を優先（fail-open）。認証必須経路と違い、誤検知で正規利用（研究者の
  データ DL・SNS の OGP プレビュー取得）を巻き込みたくない。
- 公開**書き込み**はブラウザから Supabase PostgREST を直接叩く構成で Next.js を経由しないため、
  書き込みの上限は DB トリガー + CAPTCHA が担う（middleware matcher を広げても書き込みは守れない）。
- インメモリのトークンバケットはインスタンスごとに揮発する「粗いふるい」であり、分散アクセスや
  CDN 手前での増幅には本質的に無力。**正確な上限はプラットフォーム側（Vercel / Cloudflare）が適所**。

したがって `/dataset/*`・`/api/og` の真の緩和は **プラットフォーム側レート制限**で行う（＝運用設定であり
コードではない）。本 PF は「重いアプリ内レートリミッタや新規依存は入れない」方針（REQ-245）。
