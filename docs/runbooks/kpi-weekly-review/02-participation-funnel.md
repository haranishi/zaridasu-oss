## 2. 参加ファネルの定義（AC-03）— GA4 と Supabase の役割分担

「閲覧 → 投稿開始 → 投稿完了 → 承認」のうち、**どこが漏れているか 1 段を特定**できる粒度で持つ。

| 段 | 見る場所 | 指標 | 備考 |
|---|---|---|---|
| 閲覧 → 投稿開始 | **GA4 ファネルデータ探索** | `lp_view`/ページ閲覧 → 投稿開始イベント | イベント名・パラメータは **REQ-232** が主管（未確定なら確定後に接続） |
| 投稿開始 → 投稿完了 | **GA4 ファネルデータ探索** | 投稿開始イベント → 投稿完了イベント | 同上 |
| 投稿完了 → 承認 | **Supabase**（`get_kpi_quality_funnel.funnel`） | `posts` 完了行 → `status='approved'`（承認率） | `/admin/kpi` の「③承認ファネル」 |

GA4 探索の作り方（探索 → ファネルデータ探索）:
1. ステップ 1=ページ閲覧、ステップ 2=投稿開始イベント、ステップ 3=投稿完了イベント
2. 「開いた手順」をオンにし、各段の離脱率を確認
3. 完了以降（承認）は Supabase 側で見るため GA4 には入れない（二重計測回避・REQ-107 方針）
