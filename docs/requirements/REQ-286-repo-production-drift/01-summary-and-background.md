## 0. 要件サマリー

**本番 DB に適用済みの migration が 1 本、git にコミットされていない。** そのため「リポジトリを clone して構築した環境」と「本番」が一致しない状態にある。同時に、REQ-282 で新設した migration 索引（`supabase/migrations/README.md`）が実体と食い違っており、索引としての信頼性を失っている。

さらに根本の問題として、**この種の乖離を検知する仕組みが存在しない**。今回は手作業の棚卸しで気づいたが、次も気づける保証はない。

本要件は、(1) 現に発生している乖離の解消、(2) 索引の是正、(3) 乖離を機械的に検知する仕組みの導入、を扱う。

---

## 1. 背景

### 1.1 なぜ起きたか

2026-07-28 の本番データクリーニング作業中に、Supabase ダッシュボードの Database Webhooks で作られた旧トリガー `analyze-image-on-insert`（リポジトリ管理外・service_role JWT がリテラル埋め込み）が発見された。これを削除する migration を作成し、`supabase db push` で**本番へ先に適用**したまま、コミットに至らずセッションが終了した。

作業ログには「**このマイグレーションファイルはまだコミットしていない**」と明記されており、意図的な保留ではなく**やり残し**である。

### 1.2 なぜ問題か

- **本番を再現できない**: clone 直後のリポジトリには当該 migration が無い。CI も新規環境も、旧トリガーが残った前提のスキーマで動く
- **CI が検証していない**: 当該 migration は一度も CI を通っていない
- **索引が嘘をつく**: `supabase/migrations/README.md` は「全 58 本 本番適用済み」と書いているが、本番は 59 本適用済みである。索引は「迷ったらここを見る」ための文書であり、実体とずれた時点で価値が反転する
- **要件定義そのものも未コミット**: REQ-283・REQ-284 も未追跡のままで、ローカルの iCloud / このマシンにしか存在しない
