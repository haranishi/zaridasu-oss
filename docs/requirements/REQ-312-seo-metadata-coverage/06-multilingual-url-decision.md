### 判断事項: 4言語UIに対して hreflang / ローカライズURLが無い — Low・**意思決定待ち（2026-07-31 時点も未決）**

事実として確認できていること:

- `src/lib/i18n.ts:14` に `SUPPORTED_LANGS = ['ja', 'en', 'zh', 'ko'] as const`。`DrawerMenu.tsx:15-20, 256-269` に4言語の切替UIが常設されている。
- `src/locales/{ja,en,zh,ko}/translation.json` は**4言語 1277キーが完全一致**（`npm run i18n:check` 緑・UX監査で実測）。つまり翻訳は既に揃っている。
- `src/app` 配下に `[locale]` セグメントは**存在しない**（`find` で0件）。`alternates.languages` / `hreflang` / `x-default` はリポジトリ全体で**0件**。
- 言語切替は完全にクライアント（localStorage）のみ。したがって **en / zh / ko の翻訳コンテンツには固有URLが存在せず、検索エンジンがインデックスできない**。

意味するところは「**4言語分の翻訳コストが検索流入に一切結びついていない**」ということである。ただし対応は工数が大きく、プロダクト判断を要する。

| 判断 | やること | 判断材料 |
|---|---|---|
| 多言語SEOを**取りに行く** | `/[locale]` ルーティング導入 ＋ 全ページの `alternates.languages` ＋ `x-default` ＋ sitemap の言語別エントリ ＋ SSR段階での `html lang` 決定（A-13 / REQ-304 と接続） | 秋田県の外来生物情報という主題に対し、en/zh/ko の検索需要が実在するか。在住外国人・研究者・訪日者のどれを想定読者にするか。全ページのルーティング変更は canonical / sitemap / middleware / OG生成すべてに波及する |
| **取りに行かない** | 現状維持で問題なし（UI多言語対応としては機能している）。判断記録だけ残す | 翻訳は既に4言語揃っているため、後から取りに行く余地は失われない |
