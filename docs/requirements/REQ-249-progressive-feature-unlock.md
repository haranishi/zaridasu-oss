# REQ-249: 段階的機能解放（レベル連動の機能アンロック）

## 背景
現状、ログイン済みユーザーは全機能を最初から使える（地図・ヒートマップ・フィルタ・投稿・音声・写真・定点調査・CSV エクスポート・ランキング・プロフィール編集はすべて非ゲート）。ユーザーは「投稿するほど、どんどん使える機能が解放される」ゲーム的進行を求めている。本 REQ は REQ-248 の貢献レベルを入力として、**機能を段階的に解放する仕組み**を定義する。

**設計の最重要原則（市民科学ファースト）**: 本 PF の価値は投稿データそのものにある。したがって**中核の貢献機能（投稿・写真添付・位置取得・種選択・地図閲覧）を進行の壁の後ろに隠してはならない**——それはデータ収集を減らし本末転倒になる。解放対象は「体験を豊かにする拡張・見た目（コスメ）・高度な分析・コレクション」に限る。データ品質を上げる機能（定点観察・GPS 精度）はむしろ**早期に解放**し「基本を覚えたユーザーへの強力な道具」として位置づける（習熟の報酬であって、参入障壁にしない）。

## 現状の問題（機会）
（ファイルパス:行番号つき）

1. **アンロック機構が皆無**: 「N 回投稿したら解放」の概念が存在しない（REQ-248 背景の grep 実証）。進行の達成感・再訪動機に接続できていない。
2. **ゲート可能な機能の棚卸し（解放候補）**——現状すべて非ゲート:
   - 地図/ヒートマップ（`src/components/features/map/MapView.tsx`・`leaflet.heat`）、高度フィルタ（`FilterBar`）、トレンド（`/trends`）。
   - 定点観察モード（`survey_method='structured'`・`survey_sites`・REQ-174。※フックは半実装＝REQ-247 で去就判断）。
   - 自分のデータ CSV エクスポート（`src/components/features/dashboard/CSVExportSection.tsx`）。
   - プロフィールのコスメ: `avatar_emoji`（既定 🦞・`user_profiles`・`EditProfileModal`）＝**現存する唯一の見た目報酬レバー**。表示名・bio。
   - コレクション/水槽（REQ-250）・演出テーマ（REQ-251）。
3. **既存のゲーティング土台**（本 REQ が乗る基盤）:
   - クライアント認可: `src/context/AuthContext.tsx`（`useAuth()` の `user`/`isAdmin`/`isEmailConfirmed`）。ページ層の慣用ゲートは `if (!user) return null`（`DashboardPage.tsx:172`）。
   - middleware matcher は `/dashboard`・`/admin` のみ（`src/middleware.ts:166-168`）。サーバー保護が必要な新ゲートルートは matcher 追加が要る。
   - DB: RLS＋`SECURITY DEFINER` RPC（ロール anon/authenticated/admin）。

## 目的
REQ-248 のレベルに連動して、拡張・コスメ・高度分析・コレクション機能を段階的に解放する宣言的な仕組みを作る。中核貢献機能は常時開放し、品質向上機能は早期解放、長期の報酬はコスメ/コレクションに寄せる。ロックは「壊れた UI」ではなく「解放予告（あと少しで解放）」として見せ、進行の動機に変える。

## 要件

### 機能要件
- [ ] FR-249-01: **宣言的アンロック定義**を単一ソースで持つ（`src/lib/constants.ts` に `FEATURE_UNLOCKS`＝レベル→機能キーの表。i18n ラベル付き）。REQ-248 の `get_user_progress` と組み合わせ、`useUnlocks()` フック（or `useProgress` 拡張）で「この機能は解放済みか／解放レベル」を判定できるようにする。
- [ ] FR-249-02: **アンロック段階の設計**（初期案・運用調整可。中核貢献は常時開放＝表に載せない）:
  - 早期（品質向上・習熟の道具）: ヒートマップ表示 → 高度フィルタ/期間比較 → 定点観察モード（REQ-174）→ 自分データ CSV エクスポート。
  - 中盤（コスメ・自己表現）: `avatar_emoji` の選択肢拡張 → プロフィールの称号/フレーム → 地図テーマ/マーカースキン。
  - 長期（コレクション・演出）: 図鑑スロット/水槽容量（REQ-250）→ 水槽デコレーション → 解放演出テーマ/マスコットボイス（REQ-251）。
- [ ] FR-249-03: **ロック時の見せ方**: ロック機能は非表示にせず「Lv N で解放」ティーザー＋進捗（あと XP/あと承認 n 件）を表示し、解放を目標化する（REQ-251 の可視化と連携）。ロックによって既存 UI が壊れない（グレースフルデグレード）。
- [ ] FR-249-04: **enforcement の粒度**: コスメ/UI 系の解放はクライアント判定（`useUnlocks` による条件レンダリング）で足りる（改竄されても実害＝見た目のみ）。**データ保護や課金に関わる解放**（例: エクスポート量・特別 API）は DB/RLS/RPC もしくは middleware で二重に強制する。「どの解放がサーバー強制を要するか」を定義に明記する。
- [ ] FR-249-05: **中核貢献の非ゲート保証**: 投稿・写真・位置・種選択・地図閲覧・通報は**レベルに関わらず常時利用可能**であることを設計原則としてドキュメント化し、レビュー観点に含める。
- [ ] FR-249-06: **i18n**: 解放機能名・ティーザー文言を 4 言語に追加し `i18n:check` を通す（ブランド声・禁止語遵守）。

### 非機能要件
- [ ] NFR-249-01: アンロック判定は性能バジェット（size-limit `/`=10KB・`/trends`=5KB 等、`.size-limit.json`）を悪化させない。定義は軽量な定数、判定はクライアントメモ化。
- [ ] NFR-249-02: サーバー強制が必要な解放は RLS/RPC/middleware で担保し、クライアント改竄で保護境界を破れないこと（REQ-214 サーバー認可と整合）。
- [ ] NFR-249-03: 既存ユーザー（本機能導入時点で高レベル相当）には、これまで使えていた機能を剥奪しない移行方針（既存機能はグランドファーザー化 or 初期レベルを実績から算定）。
- [ ] NFR-249-04: アクセシビリティ: ロック/解放状態はテキストでも判別可能（色/アイコンのみに依存しない）。REQ-224（色 a11y）・Lighthouse a11y≥0.9 を維持。

## 受入条件
- [ ] AC-01: 低レベルのユーザーには一部拡張機能がロック表示（Lv N で解放のティーザー＋進捗）され、レベル到達で解放される。
- [ ] AC-02: 投稿・写真・位置・地図閲覧などの中核貢献がどのレベルでも利用可能。
- [ ] AC-03: コスメ解放はクライアント判定で機能し、データ/課金に関わる解放はサーバーでも強制される（改竄で破れない）。
- [ ] AC-04: ロックによって既存 UI が壊れず、既存ユーザーの利用可能機能が減らない。
- [ ] AC-05: 解放関連文言が 4 言語に存在し `i18n:check` が通る。ロック状態がテキストで判別可能。

## 影響範囲
- `src/lib/constants.ts`（`FEATURE_UNLOCKS`）、`src/hooks/`（`useUnlocks`/`useProgress`）、`src/context/AuthContext.tsx`（進行の供給）
- ゲート対象 UI: `MapView`/`FilterBar`/`CSVExportSection`/`EditProfileModal`/定点調査/`/trends` ほか（条件レンダリング）
- サーバー強制が要る場合: `src/middleware.ts`（matcher）・該当 RLS/RPC
- `src/locales/*/translation.json`（4 言語）
- 関連 REQ: REQ-248（レベル供給）、REQ-250（コレクション/水槽解放）、REQ-251（ティーザー/演出）、REQ-174（定点）、REQ-214（サーバー認可）、REQ-224（色 a11y）。

## 優先度
- **緊急度**: Low / **重要度**: Medium
- **理由**: ユーザー要望の中核（段階的機能解放）だが、REQ-248（レベルエンジン）に依存する。中核貢献を非ゲートに保つ制約さえ守れば、継続動機と機能理解（オンボーディング）を同時に高められる。既存の認可土台に薄く乗せられ、実装リスクは中程度。
