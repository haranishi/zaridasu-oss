## 3. 目的

1. リポジトリと本番の Edge Function を一致させる（または「意図的に未デプロイ」を明示管理する）
2. `enrich-place` の欠損データをバックフィルし、研究データとしての地理属性を回復する
3. 同じ故障モード（未デプロイ・呼び出し失敗）が**次回は自動で検知される**状態にする
4. 通知系の配信開始を、意図しないメール送信なしに安全に行う

---

## 4. スコープ外

- Web Push の運用開始（`send-push` のデプロイは行うが、購読導線・VAPID 運用は REQ-237 の範囲）
- `social-announce` の実運用（SNS 自動投稿の可否判断はマーケ側の意思決定。本要件では dry-run 維持）
- ライフサイクルメールの**文面・訴求内容**の改訂（本要件は配信経路の疎通まで）
- pg_cron のジョブ設計そのものの見直し
