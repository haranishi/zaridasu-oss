## 0. 要件サマリー

リポジトリには Edge Function が **14 本**あるが、本番にデプロイされているのは **7 本**だけである。残り **7 本**は一度もデプロイされていないか、削除された状態にある。にもかかわらず、DB のトリガーと pg_cron は**未デプロイの関数を呼び続けており**、その HTTP 呼び出しは**すべて 404 で失敗している**。

pg_net は非同期であるため cron ジョブ自身は「成功」を返し、Edge Function 側は `fail-soft`（失敗しても no-op）で設計されているため、**壊れていることが誰にも通知されない**状態が継続している。

本要件は、(1) 未デプロイ関数の解消と欠損データのバックフィル、(2) 同じ見落としが再発しない CI ガードへの是正、(3) pg_net 呼び出し失敗の可視化、の3点を扱う。

> [!important] 通知系の扱い
> 未デプロイ関数のうち 3 本は**実ユーザーへメールを送る**（休眠再エンゲージ・週次ダイジェスト・AI 異常通知）。デプロイした瞬間に配信が始まるため、**宛先・文面・配信停止導線を確認してからデプロイする**。本要件では「デプロイすること」と「配信を有効化すること」を別の要件として分離する。
