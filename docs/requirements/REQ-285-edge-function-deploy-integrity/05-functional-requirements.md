## 5. 要件

### 5.1 機能要件

#### FR-285-01（即時・通知を伴わない）: `enrich-place` のデプロイとバックフィル

- `supabase functions deploy enrich-place` を実行する
- デプロイ後、新規投稿で `geo_enriched_at` / `locality` が埋まることを 1 件で確認する
- 既存 18 件（少なくとも `approved` 12 件）に対してバックフィルを行う。トリガーは INSERT 時のみのため、**再 INSERT ではなく明示的な再実行**（管理用 RPC もしくは 1 件ずつの直接呼び出し）で行い、`updated_at` や監査ログを不用意に汚さないこと
- Nominatim の利用規約（レート制限）を遵守する。`src/lib/geocodeCache.ts:8` のキャッシュ方針と整合させる

#### FR-285-02: `notify-ai-anomaly` のデプロイ

- デプロイ前に通知先（管理者メール）を確認する
- デプロイ直後に 15 分 cron が発火するため、**過去分の異常が一斉通知されないこと**を確認する（閾値判定が「直近ウィンドウ」であることの確認）

#### FR-285-03: ライフサイクル系 2 本のデプロイと配信有効化の分離

`notify-dormant-reengage` / `notify-weekly-digest` について、次を**この順で**行う。

1. cron ジョブ 1・2 を一時的に `active=false` にする
2. 関数をデプロイする
3. 手動実行（dry-run 相当・自分宛て）で文面と配信停止リンク（`/u/unsubscribe`）を確認する
4. 宛先母集団を確認する（現在 `auth.users` は **9 名**。うち大学関係者・本人アカウントを含む）
5. 配信を有効化する場合のみ cron を `active=true` に戻す
6. **cron のタイムゾーンを確認する** — pg_cron の `schedule` は UTC 基準である。現行 `0 9 * * *` は JST 18:00、`0 0 * * 1` は JST 月曜 09:00 に相当する。意図と一致するか確認し、必要なら是正する

> [!warning] 判断が必要
> 登録ユーザー 9 名・承認済み投稿 12 件という現段階で、休眠再エンゲージメールと週次ダイジェストを実際に送るべきかは**プロダクト判断**である。送らないと決めた場合は、関数をデプロイせずに **cron を停止する**（404 を出し続けない）ことを選ぶ。FR-285-06 の検知はどちらの選択でも成立させる。

#### FR-285-04: 残り 3 本の方針決定と反映

`send-push` / `notify-research-adopted` / `social-announce` について、「デプロイする」か「意図的に未デプロイとして管理する」かを決め、次のいずれかを満たす状態にする。

- デプロイする場合: 本番に ACTIVE で存在する
- 未デプロイを維持する場合: 後述の許容リスト（FR-285-05）に理由付きで登録し、**DB 側の呼び出し経路（トリガー / cron / ラッパ）を無効化する**か、no-op であることを明示する

#### FR-285-05: deploy-lag ガードの対象を自動導出へ是正

- `scripts/check-edge-deploy-lag.sh` の `DEFAULT_TARGETS` を廃止し、**`supabase/functions/` 配下のディレクトリ（`_shared` 除く）から動的に生成**する
- 意図的に対象外とする関数は `supabase/functions/.deploy-ignore`（仮）に**理由コメント付き**で列挙し、スクリプトはこれを読む。リストに無い新規関数は自動的に監視対象になること

#### FR-285-06: 「本番に存在しない関数」を差分に関係なく常時検知

現行の deploy-lag（更新時刻の乖離）とは**別のチェック**として追加する。

- リポジトリに存在するが `supabase functions list` に現れない関数を列挙する
- `CHANGED`（git diff）によるフィルタを**適用しない**。差分の有無に関わらず毎回評価する
- `MODE=main` では 1 本でも該当すれば **exit 1**（CI を赤にする）。`MODE=pr` では warning
- FR-285-05 の許容リストに載っているものは除外する

#### FR-285-07: DB が参照する関数名との突合

トリガー / cron ラッパが `'/functions/v1/<name>'` の形で参照する関数名を抽出し、リポジトリの関数一覧・本番のデプロイ一覧と 3 者突合する。抽出元は `supabase/migrations/*.sql` の静的解析でよい（本番 DB へのアクセスを CI で必須にしない）。不一致は CI で報告する。

#### FR-285-08: pg_net 呼び出し失敗の可視化

- `net._http_response` の直近ウィンドウにおける 4xx / 5xx を集計する仕組みを設ける
- 閾値超過時に管理者へ通知する。ただし**通知経路自体が Edge Function に依存すると同じ穴に落ちる**ため、少なくとも 1 経路は Edge Function に依存しない手段（GitHub Actions のスケジュール実行から Management API 経由で照会し Issue 起票する等）で成立させること
- 併せて `docs/runbooks/` に「pg_net の失敗を調べる手順」を追記する
