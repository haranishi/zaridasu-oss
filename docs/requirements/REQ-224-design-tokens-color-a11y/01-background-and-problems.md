## 背景

ザリダス（秋田県の外来生物＝アメリカザリガニ／ウシガエルの市民科学情報マップ、卒研 PF）は Next.js 15 + Tailwind CSS 3 + TypeScript で、ダークモード（`dark:`）と i18n（ja/en/ko/zh）に対応する。市民科学アプリとして子ども・高齢者・幅広い住民が利用するため、見た目の「整合性」と「誰にでも読める／区別できる」ことの両立が品質に直結する。

しかし現状、デザインの基本値（色・余白・タイポ）が **トークンとして集約されておらず**、各コンポーネントに Tailwind ユーティリティとハードコード HEX で散らばっている。とくに **アメリカザリガニ＝赤（`#DC2626`）／ウシガエル＝緑（`#16A34A`）** という主役 2 種の色分け（`src/lib/constants.ts:78-79`）は、本アプリで最も頻出する識別であるにもかかわらず、色覚多様性において最も識別困難な **赤×緑** の組み合わせになっている。この色は地図マーカー・ドーナツ凸グラフ・進捗バーへ色だけの手がかりとして流れており、P 型／D 型色覚のユーザーには 2 種が区別しづらい。

本 REQ-224 は、Obsidian デザイン基礎ノート群を下敷きに、**(A) デザイントークンを CSS カスタムプロパティ（`:root` / `.dark`）として集約**（60-30-10 カラー・8pt グリッド・タイポ基準）、**(B) アクセントを主 CTA 1 色に絞る**、**(C) 色覚多様性対応（色だけに依存しない状態・種別表現）とコントラスト適合** を行う。下敷きノート：
- `02_notes/デザイン基礎/配色・カラー理論.md`（60-30-10、HSL での体系化、色付きグレーでのスケール生成）
- `02_notes/アート基礎/色彩理論と配色設計.md`（配色設計の原則）
- `02_notes/デザイン基礎/タイポグラフィ.md`（本文 16px 以上・行間 1.5・フォント 2 種・1 行 35-50 字・和文ゴシック）
- `02_notes/デザイン基礎/レイアウト・視覚的階層.md`（8 ポイントグリッド・近接＝内側 ≤ 外側）
- `02_notes/デザイン基礎/データ可視化の基礎.md`（色覚バリアフリー・Wong パレット）

> 配色の合意基準（メモ準拠）：ベース 60%（ニュートラル）／メイン 30%／アクセント 10%（＝主 CTA 専用 1 色）。完成 UI は①白黒変換で情報が残るか②WebAIM で 4.5:1③色覚シミュレータの 3 点でチェックし、状態（成功／警告／エラー）は **色＋アイコン＋テキストの 3 点セット**、赤×緑を避け **青×オレンジ** へ寄せ、データ可視化は **Wong パレット** を使う。

## 現状の問題

（ファイルパス:行番号、または「設定不在の事実」つき）

### 1. デザイントークンの土台（CSS カスタムプロパティ）が存在しない

- `src/app/globals.css` に `:root` で定義された設計トークンは **存在しない**（`grep -n ":root" src/app/globals.css` ヒットなし。`var(--…)` は LP 縁取り用 `--lp-stroke`（`globals.css:394,397`）の 1 件のみ）。色・余白・フォントサイズの単一情報源（single source of truth）が無く、変更時に全コンポーネントを追わねばならない。
- `tailwind.config.js` の色定義は `primary` の **5 段のみ**（`50/100/500/600/700`、`tailwind.config.js:12-20`）で、200/300/400/800/900 が欠落。`success`/`warning`/`error`/`info`/`neutral` といった **セマンティックカラーのトークンは未定義**。spacing のカスタム定義も無く（8pt スケールは Tailwind 既定まかせ）、`fontFamily` は `sans`（Inter 系）1 種のみで和文ゴシックの指定が無い（`tailwind.config.js:21-23`）。
- 結果、後述のとおり同じ意味の色が複数箇所で別々の HEX／ユーティリティとして重複定義され、ドリフトしている。

### 2. 主役 2 種が「赤×緑」で、色だけに依存して識別している（色覚多様性の事故）

- 種別カラーが `american=#DC2626`（赤）／`bullfrog=#16A34A`（緑）（`src/lib/constants.ts:78-79`）。これは色覚多様性で最も識別困難な赤×緑（データ可視化ノート「赤×緑は避ける」）。
- この色が **色だけの手がかり**として複数の可視化へ流れている：
  - 地図マーカー：`createSpeciesIcon(sp.color)`（`src/components/features/map/MapView.tsx:298`、SVG の `fill="${color}"` `:41`）。マーカーの形は種で共通の雫型で、**差は色のみ**。
  - ドーナツ凸グラフ：`DonutChart` の各弧 `stroke={arc.color}`（`src/components/ui/charts/DonutChart.tsx:35`）に種色をそのまま渡す（`src/views/TrendsPage.tsx:28-31`、`src/components/features/dashboard/KPISection.tsx:39`）。グラフ本体に数値・パターン等のテキスト無しの色面で、白黒変換すると 2 種が潰れる。
  - 進捗バー：`backgroundColor: s.color`（`TrendsPage.tsx:86`、`KPISection.tsx:84`）。
  - カード左罫：`borderLeft: 3px solid ${sp?.color}`（`MyPostsSection.tsx:126`、`PendingPostsSection.tsx:76`）。
- 凡例（legend）側はテキストと色丸が併記されている（`TrendsPage.tsx:75-79`）ため legend を読めば区別はつくが、**グラフ本体・地図マーカー単体は色のみ**で、メモの「色＋テキスト（＋形/アイコン）」を満たさない。投稿カードの種名はテキスト・画像で表示され色依存ではない（`PostCard.tsx:88-89,114`）のは良好。

### 3. 状態色が「色のみ」または重複定義で、トークン化されていない

- GPS 精度バッジは `level === 'good' ? 'text-emerald-500' : level === 'warn' ? 'text-yellow-500' : 'text-red-500'`（`src/components/features/posts/LocationSection.tsx:74`）と **緑/黄/赤** の色分け。テキストは併記されるが、ここでも緑（emerald）×赤の対比で、トークン化されていない（マジックなユーティリティ直書き）。
- セマンティックな状態色が箇所ごとにバラバラのユーティリティで表現されている：成功＝`bg-green-500`（`src/app/providers.tsx:112`）、警告＝`bg-amber-500`（`providers.tsx:105`）、情報＝`text-blue-400`（`src/components/ui/Toast.tsx:17`）など。同じ「成功」「警告」「情報」が共通トークンを持たず、`bg-green` と `text-emerald` のように緑系すら不統一。
- `Toast`（`src/components/ui/Toast.tsx:17`）はアイコン＋色＋テキストの 3 点が概ね揃っており、状態表現の良い既存例（横展開の基準にできる）。

### 4. アクセントカラー（10%）が CTA 1 色に絞られておらず、種の赤と CTA の赤が同居

- 主 CTA は赤グラデ `bg-gradient-to-r from-red-500 to-rose-600`（`src/lib/formStyles.ts` の `btnPrimaryCls`）で統一されているのは良い（共通化済み）。
- 一方、**主役種「アメリカザリガニ」も赤（`#DC2626` ≒ primary-600）** であり、ブランド／CTA の赤と種別の赤が **同じ色相帯で意味衝突**している。60-30-10 では「アクセント 10%＝主 CTA 専用 1 色」とすべきだが、赤がブランド・CTA・主要種で多重に使われ、「赤＝押すべき場所」という視線誘導が弱まる。
- `text-red-*` / `bg-red-*` 系ユーティリティと HEX 赤が全域に散在（`grep` 多数。例：`src/app/area/AreaListPageClient.tsx:57,60`、`src/components/ui/AudioPlayer.tsx:134,151,168`、`src/components/ui/CrayfishIllustration.tsx` の塗り多数）。どこまでが「ブランド色」でどこからが「種色／装飾」か境界が曖昧。

### 5. amber（`#F59E0B`）が 3 つの異なる意味に再利用され、トークンの意味が衝突

- `#F59E0B` が **種別「不明」**（`constants.ts:220`）・**緊急度「通常」**（`:230`）・**調査ステータス「募集中」**（`:242`）の 3 つに同一値で使われている。色から意味が一意に逆引きできず、凡例なしでは判別不能（「色＝意味」の原則が崩れている）。`#F97316`（緊急度「急ぎ」`:231`）・`#3B82F6`（ステータス「対応あり」`:243`）も近傍に並ぶため、トークン名（用途）で分離する必要がある。

### 6. コントラスト不足（4.5:1 / 3:1）が広域に残る

- `text-gray-400` の使用が **167 箇所**（`grep -rn "text-gray-400" src | wc -l`）。白／薄背景上で約 2.8:1 と本文・ラベルとしては 4.5:1 未満になりやすい（REQ-204 でも LP の英ラベル・FAQ アイコンで同様の指摘 → 本 REQ は LP 外の全域を対象に「faint トークン」を基準化）。共通ヘルパー `faint()` も `text-gray-400`（`src/lib/themeClasses.ts:18`）を返しており、薄すぎる既定が共通化されてしまっている。
- ドーナツ／グラフのトラック色 `stroke="#f3f4f6"`（`DonutChart.tsx:27`、`AdminDonutChart.tsx`、`AreaChart.tsx`）や軸ラベル `fill="#d1d5db"`（`AreaChart.tsx`）はダークモード非対応のハードコードで、ダーク時にコントラストが破綻する。
- 14px 未満の極小フォント（`text-[10px]` 等）が **34 箇所**（`grep` で `text-[8〜13px]` 概算）。本文 16px 以上・補助 14px 以上というタイポ基準（タイポグラフィノート）から外れ、コントラスト要件も厳しくなる（小さい文字ほど高コントラストが必要）。

### 7. タイポグラフィ・8pt グリッドの基準が言語化・トークン化されていない

- `tailwind.config.js` に `fontSize`（行間込みのタイポスケール）・`spacing`（8pt グリッド）のカスタム定義が無く、本文サイズ・行間 1.5・1 行字数・和文フォントといった基準が **どこにも明文化されていない**（設定不在の事実）。和文ゴシック（例：Noto Sans JP / Hiragino 系）の指定が無いため、日本語本文は OS 既定フォントまかせ。
- 余白は Tailwind 既定（4px 刻み）をそのまま使っており、8pt グリッド（8/16/24/32/48/64）への寄せや「近接＝内側余白 ≤ 外側余白」のルールが共有されていない（レイアウトノート）。
