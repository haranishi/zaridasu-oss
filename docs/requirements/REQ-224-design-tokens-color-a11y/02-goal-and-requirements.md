## 目的

- ザリダスのデザイン基本値（色・余白・タイポ）を **CSS カスタムプロパティのトークンに集約**し、`tailwind.config.js` から参照する単一情報源を作る。60-30-10（ベース／メイン／アクセント＝CTA 1 色）・8pt グリッド・タイポ基準（本文 16px・行間 1.5・和文ゴシック・フォント 2 種・1 行 35-50 字）を体系化する。
- **色覚多様性に配慮**し、主役 2 種と状態表現を「色だけに依存しない」（色＋アイコン／形＋テキストの 3 点セット）に改める。赤×緑・緑×黄の対比を避け、データ可視化は Wong パレット系へ寄せる。
- 主要テキスト／UI 部品の **コントラストを 4.5:1 / 3:1 以上**に底上げし、トークン化された `muted`/`faint`/状態色を再利用可能にする。
- これらは **CSS カスタムプロパティで実現し、ランタイムコストゼロ**（JS での再計算・再描画を伴わない）であることを担保する。

  - **ニュートラル（ベース 60%）**: 背景・サーフェス・ボーダー・本文・muted・faint（例 `--color-bg` `--color-surface` `--color-border` `--color-text` `--color-text-muted` `--color-text-faint`）。`.dark` で対の値を定義し、`src/lib/themeClasses.ts` の `pageBg/cardCls/heading/muted/faint/divider` をこのトークン参照に寄せる。

  - **アクセント（10%・CTA 専用 1 色）**: `--color-accent`（主 CTA に限定。`formStyles.ts` の `btnPrimaryCls` が参照）。FR-224-04 と整合。

- [ ] FR-224-03（種別を色だけに依存させない）: `src/lib/constants.ts` の `SPECIES`（`:77-80`）に、色に加えて **形・アイコン/パターンの区別子**を持たせる（例：`shape`/`pattern`/`iconKey`）。これを以下に反映する：

### 非機能要件

- [ ] NFR-224-01（ランタイムコストゼロ）: トークンは **CSS カスタムプロパティ（静的 CSS）** で実装し、テーマ切替も `.dark` クラス＋変数解決で行う。JS による色計算・スタイル再生成・追加の再レンダーを発生させないこと（ダークモード切替は既存 `ThemeContext` のクラストグルのまま）。ビルド成果物の CSS は実用的なサイズ増（目安 +数 KB 未満）に収めること。
- [ ] NFR-224-02（既存ダーク／i18n を壊さない）: 既存の `dark:` 利用（125 ファイル相当）・`prefers-reduced-motion` 全体ルール（`globals.css:63-69`）・i18n 構造に回帰を出さない。トークン移行は**段階的**（まず定義＋共通ヘルパーを置換、次に主要画面）で良く、置換漏れがあっても表示が壊れないフォールバック値を変数に持たせる。
- [ ] NFR-224-03（色覚・コントラストの検証手順）: 完成 UI を **①白黒（グレースケール）変換で情報が失われないか ②WebAIM Contrast Checker 等で 4.5:1（テキスト）/3:1（UI・グラフ）③色覚シミュレータ（P 型・D 型）で 2 種・状態が区別できるか** の 3 点でチェックする手順を定義し、結果を記録する。可能なら自動 a11y チェック（`vitest-axe` / Playwright + axe）でコントラスト違反を検出する。
- [ ] NFR-224-04（トークンの単一情報源）: 同一の意味（色・余白・サイズ）が二重定義されないこと。`tailwind.config.js` と `globals.css` の値がドリフトせず、色・サイズは CSS 変数を正本として Tailwind が参照する構造にすること。
