## ユーザーストーリー

### US-079-01: 開発者として同一素材の再判定を避けたい
**As a** 開発者,
**I want to** 同一音声/画像が複数投稿で使われた場合に、過去の AI 判定結果を再利用したい,
**So that** 無駄な Gemini API 呼び出しを削減できる.

**受け入れ条件:**
- [ ] AC-1: 投稿作成時にクライアントで音声/画像の SHA-256 ハッシュを計算し DB に保存
- [ ] AC-2: Edge Function 起動時に同一ハッシュの過去判定結果（直近 30 日）を検索
- [ ] AC-3: 過去判定が存在すれば再利用、存在しなければ通常判定
- [ ] AC-4: 再利用時は `ai_result.audio_analysis.copied_from_post_id` に元 post_id を記録（監査用）

**優先度:** 中
**見積もり:** M

### US-079-02: 運用者として reanalysis 連打を防ぎたい
**As a** 運用者,
**I want to** ユーザー操作による `reanalysis=true` を 1 投稿あたり 1 日 N 回までに制限したい,
**So that** 悪意ある連打や誤操作で API コストが急増するのを防げる.

**受け入れ条件:**
- [ ] AC-1: 環境変数 `AI_REANALYSIS_DAILY_LIMIT` で上限制御（デフォルト 3）
- [ ] AC-2: 上限超過時は 429 Too Many Requests を返す
- [ ] AC-3: ユーザー向けエラーメッセージに「明日再度お試しください」等を含む
- [ ] AC-4: 上限カウントは `audit_logs` から算出（追加テーブル不要）

**優先度:** 中
**見積もり:** S
