## 非機能要件

### コスト削減目標
- **dedup hit 率**: シナリオ依存（通常運用 5〜10%、スパム時 50% 超）
- **rate limit 効果**: 悪用シナリオで API 呼び出しを実質ゼロに抑止

### パフォーマンス
- ハッシュ検索クエリは **50ms 以内**（適切なインデックスあれば 10ms 以内）
- クライアント hash 計算は 500ms 以内
- rate limit チェックは 30ms 以内

### セキュリティ
- `audio_hash` / `image_hashes` は **REQ-034 同様の column-protection 対象**（user による直接編集禁止）
- ハッシュ衝突悪用対策: SHA-256 + ファイルサイズ併用検証（任意）
- rate limit 値はサーバ側で確定的に評価（クライアント詐称不可）

### 互換性
- 既存投稿（hash NULL）は dedup スキップ → 通常処理。後方互換完全
- フィーチャーフラグなしで段階的に enabled（hash 無し ＝ 自動的に dedup スキップ）
