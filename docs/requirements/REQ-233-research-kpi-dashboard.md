# REQ-233: 卒研KPIダッシュボード（North Star＋ガードレール＋コホート継続＋量×質カウンター指標）

## これは何か

卒論の主張（継続率・参加率・データ品質）に直結する KPI を **North Star Metric＋ガードレール＋KGI の3点セット**として定義し、コホート継続率・参加ファネル・量×質カウンター指標を管理画面の1枚で見られるようにする要件定義。本文は下記の部品ファイルに逐語のまま分割してある。

## 目的・背景の要約

ザリダスの卒論は最終的に「市民の参加と、集まったデータの品質を、どの介入でどれだけ改善できたか」に帰着する。REQ-175 が実験群×期間の DID 集計を、REQ-232 が GA4 行動イベント設計を整備するが、**一貫して追うべき KPI 体系と、それを1画面で見るダッシュボード、GA4 探索の前提（データ保持・PII・外部送信規律）は未整備**である。

現状は6つの欠落を抱える。①NSM/ガードレール/KGI の3点セットが定義もコードも存在しない（概念のヒットは Tailwind の `leading-*` のみ＝0件）、②コホート継続率カーブが無く全体平均しか出せない、③参加ファネルの段別歩留まりを出す経路が無い、④量×質のカウンター指標がペアになっていない、⑤KPI が3画面に分断されている、⑥GA4 のデータ保持14ヶ月・PII 非送出・外部送信規律が未確認。

## 主要な決定事項の要点

- **NSM は 1 つだけ・12ヶ月固定**で「顧客が受け取った価値の量」として定義する。累計DL等の虚栄指標にしない。
- **全体平均は使わない。** 新規が古い解約を覆い隠すため、**獲得月コホート × 経過月の保持率マトリクス**を返す RPC を新設する。既存の `get_experiment_metrics` のリピート率は「実験群×pre/post 区間内」の集計であってコホートカーブではない。
- **Goodhart 対策として量×質を必ずペアで並べる。** 完全率・正確率（精度30m 以内）・1提出あたり AI コストを、対になる投稿数・承認数と横並びで表示する。
- **ファネルは GA4 と Supabase で担当を切り分ける。** 閲覧→投稿開始→完了は GA4 探索（イベント定義は REQ-232 依存）、完了→承認は Supabase の `status` 別集計。**どこが漏れているか1段を特定**できる粒度にする。
- **GA4 のデータ保持を初期値2ヶ月から14ヶ月へ変更する。** IaC 化できないので runbook に記録する。設定漏れは後から遡及できない非可逆リスク。
- **集計は必ず DB 側で行い生行を流さない。** 新規 RPC は admin 限定・`SECURITY DEFINER SET search_path=public`・PII 列（`reporter_ip` 等）を返さない。
- **本格 BI（BigQuery/Looker）は範囲外。** 一人運用で週次に回せる現実性を優先し、Supabase 集計 RPC＋管理画面1ダッシュボード＋GA4 探索の正しい前提で成立させる。
- **境界**: 実験別 DID は REQ-175、GA4 イベント実装と PII リダクションは REQ-232、計測ツール統一は REQ-107 が主管。
