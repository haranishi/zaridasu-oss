# REQ-328: 質問に答え、選び直しながら地図へ進める案内にする

状態：実装・ローカル検証・独立レビュー済み。設計2026-09-19、検証2026-09-20。

## 現状と改善の目的

4画面化はREQ-327で完了したが、390pxでは挨拶と質問が縦長の吹き出しに混在し、質問へ視線が届きにくい。
回答後に前の画面へ戻れず、間違いを訂正するには案内を閉じてやり直す必要がある。
最終画面は同じ模式図に地域名を載せるため実地図に見え、「点が無い＝誰も調べていない」と言い切っている。
未選択で主ボタンが押せない理由と、回答保存中の状態も伝わりにくい。
さらに「地図を見る」の保存失敗後に「もう一度」を押すと投稿へ進み、選んだ行動が変わってしまう。

初回の成功は、2つの質問を自分の意思で答え、選んだ地域の実地図を開くこととする。投稿も引き続き選べる。

## ユーザーストーリー

- 初めて訪れた人は、サービスの役割と所要時間を知り、質問への回答を始められる。
- 回答を間違えた人は、入力を失わず前の質問に戻り、保存前に訂正できる。
- まだ投稿しない人は、地図の記号を理解して、登録せず地図を見る選択ができる。
- キーボードや読み上げで使う人は、質問の切り替わり、選択状態、保存中と失敗を把握できる。

## UX5階層と設計判断

| 階層 | 今回の判断 |
|---|---|
| 戦略 | 説明の読了だけでなく、地域の地図を迷わず開くところを成功とする |
| 要件 | 4画面、2問、回答修正、明確な保存状態、既存の離脱条件、4言語を維持する |
| 構造 | 地域→目撃経験→地図の読み方→地図または投稿。2画面目以降に戻る操作を加える |
| 骨格 | 小さなマスコットと短い挨拶、独立した質問見出し、選択肢、固定フッターの順で読む |
| 表層 | 既存の赤い主ボタンと種別色を維持し、選択はチェックと面の変化でも示す。装飾の絵文字への依存を減らす |

戻る操作は完了・離脱と分ける。閉じる操作を修正の代用にしないため、任意モードの×と併設する。
質問の切り替え時には本文スクロールを先頭へ戻し、新しい見出しにフォーカスを移す。
固定の外枠とフッターを維持し、本文だけスクロールする。小さな画面でも操作を隠さない。
入口シートは地図操作より前、通常モーダルより後へ置く。カード外の透明な余白はクリックを透過させる。

最終画面の図には「地図の見方（イメージ）」と明示し、実際の地域への案内は図と分けて書く。
点のない場所の説明は「記録がない場所にもいる可能性がある」とし、未調査・不在を断定しない。
既存の比較画像・環境省の引用・法令の説明は保持する。図の全面作成や本物の地図の埋め込みは今回行わない。

## 検証と変更しない範囲

ユニットテストは回答の保持・修正後の保存値・保存中の操作抑止・失敗復帰を確認する。
E2Eでは実際に前後移動して地域を変更し、地図を開いて保存値と再訪を確認する。
既存のaxe検査、認証モード別検査、画像コントラスト検査、主要導線のE2Eを維持する。
共有機能、OGP、canonical、認証方式、DBスキーマ、アプリ全体の配色トークンは変更しない。
