## 受け入れ基準

| ID | 受け入れ基準 |
|---|---|
| AC-081-01 | `next.config.ts` の Permissions-Policy で microphone=(self) が設定されている |
| AC-081-02 | デスクトップ Chrome で 「鳴き声を録音」 押下 → ブラウザの許可ダイアログが出る |
| AC-081-03 | 「許可」 押下後、即座に録音 UI に遷移する |
| AC-081-04 | 拒否時 → エラー UI に「許可方法を見る」リンク + 自動でファイル選択モードに切替 |
| AC-081-05 | 「許可方法を見る」 押下 → 利用中 OS/ブラウザ向け手順が冒頭にハイライト表示 |
| AC-081-06 | LINE 内ブラウザでアクセス → 「外部ブラウザで開いてください」 警告 + URL コピー機能 |
| AC-081-07 | iOS Safari 実機で AC-081-02〜04 が動作する |
| AC-081-08 | 単体テスト 7+ ケース（getUserMedia 各種エラー、Permissions API 各状態、UA 判定）が通る |

---

## リスク・トレードオフ

| リスク | 緩和策 |
|---|---|
| Permissions-Policy を緩めることで他の脆弱性 | `(self)` 限定で third-party からの横取り防止は維持される |
| Permissions API は Safari で部分対応（古いバージョンは未対応） | 非対応時は従来通り getUserMedia を直接呼ぶ |
| iOS Safari の WebKit 実装差で UA 判定が不安定 | UA 判定は補助的な「ヒント」止まりにし、決定的な弾きは避ける |
| In-App ブラウザの誤判定で正常ブラウザを除外 | 正規 UA との衝突がない確実な substring のみ使用 |
| ユーザーが手順モーダルを読まない | 手順は短く・スクリーンショット付きで誘導 |
