# REQ-175: 介入評価・実験計測基盤（4指標独立追跡＋段階ロールアウト/簡易A-B割付）

## これは何か

REQ-170〜174 の各種介入が投稿行動を実際に改善したかを、季節効果と分離して測定するための実験基盤の要件。全文は同名ディレクトリの部品ファイルへ逐語で分割してある（入口のみ新規要約）。

## 目的・背景の要約

ザリの活動・目撃は季節依存性が強く、単純な前後比較（pre/post）では介入効果と季節要因を分離できない。Notion の先行研究レビュー RQ1 は DID（差分の差分法）または段階的ロールアウトによる準実験デザインを推奨し、評価は 4 指標（投稿数・位置精度・写真添付率・リピート投稿率）を独立に追跡してトレードオフを検出すること、p 値の二値判定ではなく効果量と信頼区間で報告することを求めている。現状はフィーチャーフラグも群割付も存在せず（実験機構の実装ヒットなし）、投稿に「どの実験群で行われたか」を紐づける列も、群×期間の層別集計 RPC も、群間比較 UI も無い。

## 主要な決定事項の要点

- 群割付は**ユーザーID（未ログイン時は匿名安定ID）と実験 seed の決定的ハッシュ**で行い、再読み込み・端末間でブレない安定割付にする。段階ロールアウトは率を上げたとき追加分のみが treatment へ移る単調性を担保する。
- フラグ評価はサーバー側で確定して UI 出し分けのちらつきを防ぎ、SSR/RSC 経路でも同一の割付関数で評価できるようにする。
- 投稿時に実験群を `posts` へ記録し、位置精度指標のために**取得方法（EXIF GPS / 手動ピン / 端末 Geolocation）と accuracy 値**も保存する。
- 集計は DB 側 GROUP BY の RPC に集約し、DID に必要な pre/post × control/treatment の 4 セル値と、効果量・信頼区間の算出に必要な統計量（n・平均・分散または比率と分母）を返す。
- 研究用エクスポートは**集計値のみ**とし、user_id 原文・生の緯度経度・写真 URL を含めない。管理者権限限定で、実行は `audit_logs` に記録する。
- 倫理面では割付によって投稿の可否や安全性に差を生じさせない。フラグ機構が利用不能なときは安全側（control / 介入 OFF）へフォールバックし、通常投稿を阻害しない。
- 緊急度・重要度とも High。これが無いと REQ-170〜174 の評価が交絡で無効化されるため最重要要件として扱う。
