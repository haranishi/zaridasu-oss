## 要件概要

### 背景・目的
`analyze-audio` / `analyze-image` のプロンプトには **判定基準・出力フォーマット・Few-Shot 候補（将来）** といった **完全に固定の長文部分（~500 tokens）** が毎回含まれており、毎リクエストで同じトークンを Gemini に送り続けている。

Gemini API には **Context Caching API**（Cached Content）が提供されており、固定部分を事前にキャッシュ登録すると **入力トークンが 75% 割引** になる。本要件はこの機能を導入してさらなるコスト削減を行う。

### スコープ
**含む:**
- `analyze-audio` のプロンプト固定部分の Cached Content 登録ロジック
- `analyze-image` のプロンプト固定部分の Cached Content 登録ロジック
- TTL 管理（自動 refresh）
- Cache miss 時のフォールバック（フェイルオープン）
- キャッシュ生成・更新のオペレーション手順

**含まない:**
- プロンプト内容の改善（精度向上は別要件）
- 参照音声 Few-Shot 化（精度要件と一緒に検討）

### 前提条件・制約
- Gemini Context Caching API は **最低トークン数の制約あり**（モデルにより 1024〜32768 tokens）。要確認
- 現状プロンプトは ~500 tokens のため **最低トークン数を満たさない可能性あり** → 参照音声/画像を追加して合計トークン数を底上げする必要あり（要確認）
- キャッシュは TTL（デフォルト 1 時間、最大変動）後に消える → アプリ側で更新管理が必要
- Cached Content には **ストレージ保存料金**（小額）が別途発生する
- REQ-076 でモデル選定が確定していないとキャッシュ作成 → モデル変更で破棄になる
