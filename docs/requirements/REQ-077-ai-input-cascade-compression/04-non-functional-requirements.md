## 非機能要件

### パフォーマンス
- クライアント圧縮は **モバイル（iPhone 12 / Pixel 6 程度）で 3 秒以内**
- 圧縮中は UI に進捗表示（ボタン disabled + スピナー）
- ゲート判定は **100ms 以内**（録音終了直後にブロックしない）

### コスト削減目標
- **API 呼び出し回数**: 事前ゲートで 10〜20% 削減
- **入力トークン数**: 圧縮で 50〜70% 削減
- **総合**: Phase 1 残コストに対し **-30%**

### UX
- 警告は強制弾きではなく "それでも投稿する" ボタンを表示
- 圧縮処理中は `aria-live="polite"` で進捗を読み上げ
- Reduced motion 設定時はスピナー停止

### セキュリティ
- 圧縮処理は全てクライアント側で実施（追加のサーバ処理無し）
- AI バリアントの Storage アクセス権限は元データと同じ RLS

### 互換性
- MediaRecorder 非対応ブラウザでは圧縮スキップ（既存 fallback と整合）
- 旧 Safari は Opus エンコード非対応の可能性 → mp4/AAC へ fallback
