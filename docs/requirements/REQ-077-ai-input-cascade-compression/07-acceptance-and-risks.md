## 受け入れ基準

| ID | 受け入れ基準 |
|---|---|
| AC-077-01 | 無音音声録音後に警告バナーが表示され、強制弾きではない |
| AC-077-02 | 1024x1024 以上の画像が 1024x1024 以下にリサイズされてアップロードされる |
| AC-077-03 | 5 秒の音声録音が圧縮後 50KB 以下になる |
| AC-077-04 | フィーチャーフラグ off 時は既存挙動と完全互換 |
| AC-077-05 | Phase 1 完了時の月額コストに対しさらに -30% 削減（30 日経過時点） |
| AC-077-06 | 精度指標が REQ-074 AC-074-05 を満たす |
| AC-077-07 | モバイル実機（iOS Safari / Android Chrome）で圧縮処理が 3 秒以内に完了 |

## リスク・トレードオフ

| リスク | 影響 | 緩和策 |
|---|---|---|
| 過度な圧縮で AI 判定精度低下 | recall 低下 | 評価基盤で圧縮レベル別 A/B、段階的に適用 |
| Opus エンコードがモバイル Safari で動かない | 圧縮スキップ → 効果半減 | mp4/AAC fallback、もしくは圧縮無しで元データ送信 |
| ゲート閾値が厳しすぎて投稿率低下 | UX 悪化、コミュニティ衰退 | 警告のみで強制弾きしない、テレメトリで弾き率監視 |
| Storage 容量増（元 + AI 2 倍） | ストレージ料金増 | AI バリアントは元の 30% 以下なので合計は 1.3 倍程度。許容範囲 |
| Edge Function fetch リトライ増 | レイテンシ増 | AI バリアント無し時は即座に元 URL に fallback（リトライしない） |
