## 備考（要確認）

- **FR-315-04 のエラー表示手段**: 一般画面のサインアウトは `Header` → `DrawerMenu` の中で起きるため、Toast（`ToastContext`）がその位置で到達可能かを**要確認**（Provider の配置。REQ-314 問題H でサイレントフォールバックが指摘されている箇所と同一の懸念）。到達しない場合はドロワー内のインライン表示にする。
- **FR-315-05 の Escape 無効化**: `useEscapeKey` は document リスナで11モーダルが共有しているため、無効化の引数を追加すると全モーダルの API が変わる。**シグネチャ変更の影響範囲を確認してから**、引数追加とハンドラ側 early return のどちらにするかを決める。
- **FR-315-08 の `hnd1` 選定根拠**: Supabase プロジェクトの実リージョンを確認したうえで最も近い Vercel リージョンを選ぶ。`hnd1`（東京）は想定値であり、Supabase が別リージョンだった場合はそれに合わせる。**現在ダッシュボード側で既に何らかのリージョンが設定されている可能性があるため、`vercel.json` への明示が現行の挙動を変えないか（あるいは変える場合はそれが意図した変更か）を適用前に確認する。**
- **FR-315-08 の計測**: ISR ページの応答時間は初回生成とキャッシュヒットで大きく違うため、比較は同条件（キャッシュミス時 / ヒット時を分けて）で行う。1回の計測では有意差を主張できないため、**「記録を残す」ことを目的とし、効果の断定はしない**。
- **問題Aの `ReportModal`**: 重複送信時に「送信に失敗しました」という汎用エラーになる問題（重複通報を判別できない）は **REQ-299**（エラー分類の機械可読化）の対象。本REQの同期ガードは重複送信の**発生を減らす**が、判別できるようにするものではない。
