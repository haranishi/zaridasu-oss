## 背景（各問題の根拠）

### 問題A: 地図のクラスタマーカーが「裸の数字」で描画される 🔴

`MapView.tsx:493` の `<MarkerClusterGroup chunkedLoading>` は **`iconCreateFunction` を渡していない**。
一方 `globals.css:4` は `leaflet/dist/leaflet.css` のみを読み、**`leaflet.markercluster` のCSSを一切読んでいない**。
その結果クラスタは無スタイルの `div.marker-cluster` として描かれ、`home_768` では海岸線上に黒い「6」だけが浮く。

**「初期表示にピンが1件も見えない」という指摘（採点#1）も、この描画欠落が原因である可能性が高い。**
承認済み8件は由利本荘市に集中しており、県全体ズームでは1つのクラスタに集約される。
そのクラスタが不可視なら「何も無い地図」に見える。→ **先にAを直し、それでも見えないかを再評価で確かめる。
初期の中心座標・ズームは本周では変更しない。**

### 問題B: プロジェクト自身の色覚多様性ルールに違反している 🔴

REQ-224 で「赤×緑は P/D 型色覚で最も識別困難」として主役2種を**青 `#0072B2` × オレンジ `#D55E00`** に変更した
（`docs/brand/design-guide.md:16`・`constants.ts:128-129`）。しかし:

- `StatsBar.tsx:55-56`: アメリカザリガニ `#DC2626`（赤）／ウシガエル `#16A34A`（緑）＝**禁止した赤×緑そのもの**
- `RankingPage.tsx:129`: 選択中タブ `bg-emerald-500` に白文字。赤いボトムナビと同一画面に緑が並ぶ

### 問題C: コントラストがAA未満（設計基準が自分で決めた値を下回る） 🔴

`docs/brand/design-guide/02-color-accessibility.md` は **テキスト4.5:1／UI部品3:1** を基準と明記しているが、
検証手順が「WebAIM Contrast Checker等で確認」＝**人手のみで、自動テストが無い**。だから素通りした。

| 箇所 | 前景/背景 | 実測 | 必要 |
|---|---|---:|---:|
| `RankingPage.tsx:129` 選択中タブ | `#FFFFFF` / `#10B981` | **2.54:1** | 4.5:1 |
| ホーム モーダル「今後表示しない」 | `#9CA3AF` / `#FFFFFF` | **2.54:1** | 4.5:1 |
| ranking 市町村チップ | `#C8814B` / `#FFFFFF` | **3.14:1** | 4.5:1 |
| trends 棒グラフのバー | `#D6D9DF` / カード背景 | **1.1:1** | 3:1 |

コード全体の監査（`.agent-harness/runs/2026-08-16-uiux-loop/round0-contrast-audit.md`）では
**一般ユーザー向け画面で約189箇所**が不合格。ただし散発ではなく**6つの体系的パターン**に集約され、
`themeClasses.ts` の `faint()` / `muted()` ヘルパーは REQ-224 で是正済みのため、
**残る不合格は「ヘルパーを使わず生クラスを直接書いた箇所」**にほぼ限られる。
最多は `text-gray-400`（ライトのみ 2.54:1）79箇所、次いで `bg-red-500 text-white`（3.76:1）24箇所。

**189箇所を1周で直すとレビュー不能な巨大差分になるため、本周は次の2つに限定する**（残りは REQ-319 へ）:

1. **採点対象ページで実際に見えている不合格**（上表の4件）
2. **機能が使えなくなる重大な不合格**＝ラベルの無いアイコンボタンが事実上不可視なもの
   - `MyPostsSection.tsx:306,313`（投稿の編集・削除アイコン `text-gray-300` = **1.47:1**）
   - `PendingPostsSection.tsx:171`・`CommentSection.tsx:270`（同型）
   - `RankingPage.tsx:141`（sky-500 = 2.77:1）・`:152`（red-500 = 3.76:1）＝ 問題Cのタブ列と同じ行

### 問題D: 390px専用の破綻 🔴

- `/dataset` 収録項目表: `overflow-x-auto`（page.tsx:220）で横スクロールに逃がしているが、390pxでは
  「意味」列が全11行で文字の途中から不可視。**最も重要な列が既定で読めない**
- `ranking` セグメントコントロール: 3個目「🏆 投稿数（参考）」が絵文字とラベルで2行に折れ、トラック外へはみ出す
- ホーム右端の写真タブ（`HomePage.tsx:467-482`・`h-16 w-6`＝24px幅）: 390pxで「写真」が収まらず「真」だけ見える

### 問題E: LPマーキーの停止ボタンが流れる文字と重なる 🔴

`LandingPage.tsx:400-410` の一時停止ボタンが帯の上に重なり、390/768/1440の**3幅すべて**でボタン文字も
マーキー文字も判読不能。768/1440では右端が画面外に出る。**モーション配慮のための機能が最も読めない**という逆転。

### 問題F: `bullfrog.png` に透過チェッカー柄が焼き込まれている 🔴

`public/images/bullfrog.png` は 640×640・**8-bit RGB（アルファ無し）**で、市松模様が画素として保存されている。
`/about` と ダッシュボードの `StatsBar` に出る。`american.png` は正常（白背景）＝ウシガエルのみの問題。

### 問題G: 著作権表記が `© 2024` のまま ⚪

`src/locales/{ja,en,ko,zh}/translation.json` の `lp.footer.copyright`。今年は2026年。

  色をコンポーネント側にハードコードしない（**単一の正**にする）。
- **FR-318-03**: `RankingPage` の選択中タブから緑 `emerald` を廃し、AA を満たす配色にする。
- **FR-318-04**: 問題Cに挙げた**採点対象ページで見えている4件**と、**不可視なアイコンボタン**
  （`MyPostsSection.tsx:306,313` / `PendingPostsSection.tsx:171` / `CommentSection.tsx:270`）、

  既存ヘルパー（`faint()` / `muted()` 等）へ寄せる**のが本筋。admin画面と残り約180箇所は対象外（REQ-319）。

  WCAG相対輝度で比率を計算して閾値（テキスト4.5:1／UI部品3:1）を検証するユニットテストを

  色の出典は **`globals.css` の `@theme` が固定している hex**（Tailwind v4 の既定OKLCHではない）。
- **FR-318-06**: `/dataset` の収録項目表を、768px未満で「1項目＝1ブロック」の縦積みに切り替える。
  横スクロールに依存させない。REQ-310（列定義から導出）の方針は維持する。
- **FR-318-07**: `ranking` のセグメントコントロールが390pxでトラック内に収まるようにする。
- **FR-318-08**: ホームの写真タブが390pxで文字全体を表示できるようにする。
  REQ-203 の44pxヒットエリアは維持する。
- **FR-318-09**: LPマーキーの一時停止ボタンを帯に重ねず、独立配置する。不透明背景・12px以上・

- **FR-318-10**: `public/images/bullfrog.png` からチェッカー柄を除去する（透過PNGにするか白背景で焼き直す）。

## 実装時に判明した「要件の誤り」（記録・2026-08-16）

要件の側が間違っていた点。次に同種の要件を書くときの注意として残す。

| 要件の記述 | 実際 |
|---|---|
| `SPECIES_OPTIONS[].color` から色を引く | そのexportは存在しない。正しくは `constants.ts` の **`SPECIES`** |
| `© 2024` は `lp.footer.copyright` | 年が入っていたのは共通Footerの **`footer.copyright`**。`lp.footer.copyright` は `"© ザリダス"` で年なし。両方に年補間を入れた |
| ranking チップ 3.14:1（文字） | 文字は `text-amber-700` = 5.03:1 で**合格**。3.14はスクショのアンチエイリアス画素。**本物の違反は枠線 `border-amber-300` = 1.63:1**（UI部品3:1未満） |
| 写真タブは幅24pxで文字が入らない | 幅は足りている（1440では収まっている）。真因は**スライダーの`transform`が新しいスタッキングコンテキストを作り、内側の`z-410`が`fixed z-40`のバナーに負けていた**こと。幅を広げると逆に悪化する |

**教訓**: スクショから読んだ数値（コントラスト比・要素幅）は**アンチエイリアスと重なりで嘘をつく**。
是正前にCSS上の値と重なり順（z-index／スタッキングコンテキスト）を確認すること。
