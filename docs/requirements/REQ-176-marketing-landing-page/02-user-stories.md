## 2. ユーザーストーリー

### US-176-01: 広告・SNS流入の初回訪問者がサービスを理解する
**As a** 広告やSNS投稿からリンクを踏んだ秋田県の住民,
**I want to** ザリダスが何のサービスで、自分に何ができて、何の役に立つのかを30秒で理解したい,
**So that** 安心してアプリを使い始められる（怪しいサイトではないと確信できる）.

**受け入れ条件:**
- [ ] AC-1: ファーストビュー（スクロールなし）でサービス名・一行価値提案・主CTAが視認できる
- [ ] AC-2: スクロール初期領域で「誰が・何を」（サービス名・価値提案・課題共感）が伝わり、「どうやって」（使い方3ステップ）はページ前半のセクション（SC-176-01 レイアウト④）で図解される。
  - ※ REQ-206 (FR-206-09) で修正。旧記述「スクロール1画面以内に3ステップが理解できる」は SC-176-01 のレイアウト定義（3ステップは④番目のセクション = ヒーロー→課題共感→特徴→使い方）と矛盾していたため、実装（`src/views/LandingPage.tsx` の Hero → Marquee → Problem → Features → HowItWorks の順）を正として整合させた。
- [ ] AC-3: モバイル（375px）でレイアウト崩れなく全セクションが閲覧できる

**優先度:** 高 / **見積もり:** M

### US-176-02: 興味を持った訪問者が会員登録する（主CV）
**As a** LPを読んでザリダスに興味を持った訪問者,
**I want to** その場で迷わず会員登録を開始したい,
**So that** 目撃情報の投稿やバッジ獲得などの参加機能をすぐ使える.

**受け入れ条件:**
- [ ] AC-1: LP内の主CTA（複数箇所）から1クリックで登録フロー（AuthModal のサインアップタブ）に到達する
- [ ] AC-2: 登録CTAクリックが GA4 イベント `lp_cta_signup` として記録される
- [ ] AC-3: LP経由の登録が UTM/参照元パラメータ付きで識別できる（`?from=lp` 維持）

**優先度:** 高 / **見積もり:** M

### US-176-03: 登録に抵抗がある訪問者がまず地図を見る（副CV）
**As a** 登録までは踏み切れないが興味はある訪問者,
**I want to** 登録なしでまず実際の地図・投稿データを見たい,
**So that** サービスの実態を確認してから参加を判断できる.

**受け入れ条件:**
- [ ] AC-1: 「登録せずに地図を見る」相当のセカンダリCTAが主CTA近傍に常に存在する
- [ ] AC-2: クリックで `/`（地図アプリ）へ遷移し、GA4 イベント `lp_cta_map` が記録される

**優先度:** 高 / **見積もり:** S

### US-176-04: 運営者がLPの効果を計測する
**As a** 運営者（卒研実施者）,
**I want to** LPの閲覧数・スクロール率・CTAクリック率・登録CVRを把握したい,
**So that** LPの改善（将来のA/Bテスト含む）と研究報告に使える.

**受け入れ条件:**
- [ ] AC-1: `lp_view` / `lp_scroll`（25/50/75/100%）/ `lp_cta_signup` / `lp_cta_map` / `lp_faq_open` が GTM dataLayer に送出される
- [ ] AC-2: LP経由のサインアップが流入元として区別できる

**優先度:** 中 / **見積もり:** S
