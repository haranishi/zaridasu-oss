## 5. 画面仕様

### SC-176-01: ランディングページ
- **URL:** `/lp`
- **用途:** 広告・SNS・チラシ（QRコード）流入の受け皿。価値訴求 → 会員登録/地図閲覧へ誘導
- **レイアウト:**
  ```
  +-----------------------------------------------+
  | LP専用ヘッダー [ロゴ]      [ログイン] [参加する] |
  +-----------------------------------------------+
  | ① ヒーロー                                     |
  |   キャッチコピー（h1）                          |
  |   サブコピー                                    |
  |   [無料で参加する(主CTA)] [地図を見てみる]       |
  |   ヒーロービジュアル（地図スクショ）              |
  +-----------------------------------------------+
  | ② 課題共感（なぜ外来生物情報が必要か ×3）        |
  +-----------------------------------------------+
  | ③ 特徴カード ×4                                |
  |   [地図] [AI判定] [調査依頼] [バッジ/ランキング] |
  +-----------------------------------------------+
  | ④ 使い方3ステップ                              |
  |   ①見つける → ②撮って投稿 → ③地図に載る        |
  |   [無料で参加する(中間CTA)]                     |
  +-----------------------------------------------+
  | ⑤ 実績（投稿数/ユーザー数/25市町村）＋運営表記   |
  +-----------------------------------------------+
  | ⑥ FAQ（アコーディオン ×5-7）                   |
  +-----------------------------------------------+
  | ⑦ 最終CTA                                     |
  |   「あなたの1枚が、秋田の生態系を守る」(仮)      |
  |   [無料で参加する] [地図を見てみる]              |
  +-----------------------------------------------+
  | LP専用フッター (/about /terms /privacy)        |
  +-----------------------------------------------+
  | [モバイルのみ] 追従CTAバー [無料で参加する]      |
  +-----------------------------------------------+
  ```
- **コンポーネント一覧:**
  > 当初の「種別」欄は RSC/Client の理想分割を示していたが、実装は `src/views/LandingPage.tsx` 内の関数として**全て client 配下**で構成される（REQ-206 FR-206-10 で逸脱を正式許容。理由は FR-176-07 の方針注記を参照）。「種別（当初）」は記録として残し、「種別（実装）」を実態として併記する。データ取得・JSON-LD・metadata は `src/app/lp/page.tsx`（RSC）が担当する。

  | コンポーネント | 説明 | 種別（当初） | 種別（実装） |
  |---|---|---|---|
  | `LpHeader` | 簡易ヘッダー（ロゴ/ログイン/CTA） | RSC | client（同ファイル内関数） |
  | `LpHero` | ヒーロー（コピー/CTA/ビジュアル）。ビジュアルは `next/image`+`priority`（REQ-206 FR-206-01/02） | RSC | client（同ファイル内関数） |
  | `LpProblem` | 課題共感 | RSC | client（同ファイル内関数） |
  | `LpFeatures` | 特徴カード×4 | RSC | client（同ファイル内関数） |
  | `LpHowItWorks` | 3ステップ | RSC | client（同ファイル内関数） |
  | `LpStats` | 実績数値（ISRデータ受け取り） | RSC | client（同ファイル内関数・props 受け取り） |
  | `LpFaq` | FAQアコーディオン | Client | client（同ファイル内関数） |
  | `LpFinalCta` | 最終CTA | RSC | client（同ファイル内関数） |
  | `LpStickyCta` | モバイル追従CTAバー | Client | client（同ファイル内関数） |
  | `LpAnalytics` | lp_view/lp_scroll 送出 | Client | client（同ファイル内関数） |
- **画面遷移:**
  - [無料で参加する] → `/?auth=signup&from=lp`（SC: ルート画面＋AuthModal自動表示）
  - [地図を見てみる] → `/`
  - [ログイン] → `/?auth=login&from=lp`（同パターン。TBD: login モード対応の要否）
  - フッターリンク → `/about` `/terms` `/privacy`
- **状態管理:**
  - ローディング: なし（静的）
  - 空状態: 実績数値取得失敗時は LpStats を非表示
  - エラー: ページ全体は静的のためエラーなし。Client境界は ErrorBoundary 既存方針
  - 成功: 通常表示

### SC-176-02: ルート画面の AuthModal 自動起動（既存画面の拡張）
- **URL:** `/?auth=signup&from=lp`
- **用途:** LP主CTAの着地。地図を背景に AuthModal（サインアップタブ）が開いた状態
- **変更点:** `HomeInteractive.tsx` に `useSearchParams` ベースの起動処理を追加（FR-176-08）。モーダルを閉じた場合は通常のルート画面として継続利用できる
- **画面遷移:** 登録成功 → 既存フロー（メール確認 or 即ログイン）／ モーダル閉 → `/`（クエリ除去）
