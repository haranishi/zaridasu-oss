## 3. 機能要件

### FR-176-01: `/lp` ルートの新設
- **説明:** `src/app/lp/page.tsx`（RSC）＋ `src/views/LandingPage.tsx`（表示コンポーネント）を新設。既存の `/about`（`force-static`, REQ-141 パターン）に倣う。
- **入力:** GETリクエスト（クエリ: UTMパラメータを受けるが描画には使用しない）
- **処理:** 静的生成。実績数値のみ ISR（`revalidate: 86400` = 24h、sitemap と同じ REQ-162 方針）で更新
- **出力:** LP全セクションのHTML
- **エラーハンドリング:** 実績数値の取得失敗時は数値セクションをフォールバック文言（数値非表示 or 前回キャッシュ）で描画し、ページ全体は必ず成功させる

### FR-176-02: ヒーローセクション
- **説明:** ファーストビュー。以下を含む:
  - キャッチコピー（一行価値提案。例: 「秋田の外来生物、見つけたらみんなの地図へ。」※文言はTBD・実装時に調整）
  - サブコピー（アメリカザリガニ・ウシガエルの目撃情報を住民みんなで集める市民科学プラットフォームである旨）
  - 主CTA「無料で参加する」（→ FR-176-08）＋ 副CTA「地図を見てみる」（→ FR-176-09）
  - ビジュアル: 実際の地図画面のスクリーンショット or イラスト（メディアは `public/lp/` 配下、`/optimize-media` 規定で軽量化）
- **バリデーション:** LCP対象画像は `next/image` + `priority` 指定

### FR-176-03: 課題共感セクション
- **説明:** 「なぜ今、外来生物の情報が必要か」を2〜3項目で提示（生態系への影響・防除には分布把握が必要・行政だけでは調査の手が足りない 等）。/about の外来生物法コンテンツと重複しすぎない要約レベルに留め、詳細は `/about` へリンク。

### FR-176-04: 特徴（Features）セクション
- **説明:** アプリの主要機能をカード4点で提示:
  1. **リアルタイム分布マップ** — 投稿が即座に地図に反映
  2. **AIが写真・鳴き声を判定** — 投稿するとAIが種を判定し撮影アドバイスも返す（REQ-170）
  3. **調査依頼に応える** — 研究者からの調査依頼に参加できる
  4. **バッジ・ランキング** — 貢献が見える化される（REQ-171）
- **出力:** 各カードは lucide-react アイコン＋見出し＋2行説明。スクリーンショット併用は任意

### FR-176-05: 使い方3ステップセクション
- **説明:** 「①見つける → ②撮って投稿 → ③地図に載る（AIと管理者が確認）」の3ステップ図解。登録〜初回投稿までの心理的ハードルを下げる（US-176-02/03 支援）

### FR-176-06: 実績・社会的証明セクション
- **説明:** 信頼形成のための実数提示:
  - 累計投稿数 / 参加ユーザー数 / カバー市町村数（25市町村）
  - 数値は API-176-01 でISR時取得
  - 卒業研究・大学プロジェクトとしての運営主体表記（信頼性向上。表記内容はTBD・要確認）
- **エラーハンドリング:** 取得失敗時は数値カードを非表示（FR-176-01）

### FR-176-07: FAQセクション
- **説明:** アコーディオン形式で5〜7問（無料か / 登録に何が必要か / 秋田県外でも使えるか / 投稿した情報はどうなるか / 個人情報・位置情報の扱い / 対象の生き物は何か 等）
- **処理:** 開閉はクライアント側で行う。開いた質問を `lp_faq_open` イベントで送出
- **出力:** FAQPage JSON-LD を併せて埋め込む（/about の FAQSchema パターン流用）

> **RSC/Client 構成の方針（REQ-206 FR-206-10 で確定 / 逸脱許容）**
> 当初本FR・SC-176-01 は「`'use client'` は FAQアコーディオンのみに限定し、他セクション（LpHeader/LpHero/LpProblem/LpFeatures/LpHowItWorks/LpStats/LpFinalCta）は RSC」と規定していた。
> しかし実装は既存 `src/views/*` の流儀（全ページ client + `useTranslation`、SSG 時に ja 辞書の同期初期化で HTML 出力を正常化）を踏襲し、`src/views/LandingPage.tsx` 全体を**単一のクライアントコンポーネント**として実装している（各セクションは同ファイル内の関数）。
> JSON-LD・本文 HTML・metadata は `src/app/lp/page.tsx`（RSC、`revalidate=86400`）側で生成されるため SSR/SEO は機能しており、実害は限定的。よって本REQでは **option (a)＝逸脱を正式に許容**し、RSC 分割は行わない（既存 views 群との一貫性・保守容易性を優先）。将来 LP を独立最適化する場合に RSC 化を再検討する。

### FR-176-08: 主CTA（会員登録導線）
- **説明:** LP内に複数配置（ヒーロー / 特徴後 / 最終セクション / モバイル時の追従フッターバー）
- **処理:** クリックで `/?auth=signup&from=lp` へ遷移。**HomeInteractive 側に新規対応を追加**: クエリ `auth=signup` を検知したら AuthModal をサインアップモードで自動オープンし、処理後にクエリを `router.replace` で除去する
- **計測:** クリック時に `lp_cta_signup`（dataLayer）。`from=lp` は AuthModal 側のサインアップ成功イベントに引き継ぐ（GA4上でLP経由CVを判別）
- **エラーハンドリング:** ログイン済みユーザーが踏んだ場合は AuthModal を開かず `/` を通常表示（または `/dashboard` へ。TBD）

### FR-176-09: 副CTA（地図閲覧導線）
- **説明:** 「登録せずに地図を見る」リンク。クリックで `/` へ遷移し `lp_cta_map` を送出。`next/link` の prefetch を有効にする

### FR-176-10: 計測イベント一式
- **説明:** GTM dataLayer へ以下を送出（既存 WebVitalsReporter / gtm.d.ts の型定義パターンに追加）:
  | イベント | タイミング | パラメータ |
  |---|---|---|
  | `lp_view` | LPマウント時 | `referrer`, `utm_*` |
  | `lp_scroll` | 25/50/75/100% 到達時（各1回） | `percent` |
  | `lp_cta_signup` | 主CTAクリック | `position`（hero/mid/footer/sticky） |
  | `lp_cta_map` | 副CTAクリック | `position` |
  | `lp_faq_open` | FAQ開閉（開のみ） | `question_id` |
- **備考:** 送出は production のみ（WebVitalsReporter と同方針）

### FR-176-11: ヘッダー・フッター
- **説明:** LPは没入を妨げないよう**アプリの共通ヘッダー/BottomNav は使わず**、LP専用の簡易ヘッダー（ロゴ＋「ログイン」リンク＋主CTA）と簡易フッター（/about /terms /privacy へのリンク、運営表記）を持つ
- **備考:** ロゴクリックはページ先頭へ（`/` に飛ばすとLPの目的を損なうため。要確認）

### FR-176-12: アプリ側からのLP導線（任意・小）
- **説明:** 未ログインユーザー向け SignupBanner（既存）に「ザリダスとは？」リンクを追加し `/lp` へ誘導できるようにする（検索流入で直接 `/` に来た新規ユーザーの救済）。**優先度: 低・任意**
