### 非機能要件（該当する場合のみ）

- [ ] NFR-230-01: **プライバシー最優先（PII 非公開）。** 公開データには PII を一切含めないこと。具体的に `user_id`・メールアドレス・`reporter_ip`（`reports.reporter_ip`＝REQ-179 で列保護、`posts_public` ビューでも非 admin には NULL＝`supabase/migrations/20240101000001_rls_and_audit_triggers.sql:87`）・`comment` の自由記述に含まれ得る個人情報の扱いを点検する（コメントは公開可否・サニタイズ方針を決める。判断を記録）。既存 CSV が除外している PII 方針（REQ-103）を公開配布物でも厳守し、`accuracy`（高精度の手がかり）も除外する（FR-230-03）。
- [ ] NFR-230-02: **位置粗化の一貫性と不可逆性。** 粗化は公開される全形式（CSV・GeoJSON・JSON-LD の `spatialCoverage`）で同一ルールを適用し、**生座標が復元できない**丸め（端数切り捨て/グリッドスナップ）であること。粗化前の生座標を公開物・公開キャッシュ・公開ログに残さないこと。
- [ ] NFR-230-03: **機械可読性・相互運用性。** CSV は UTF-8（BOM の要否を判断＝既存は BOM 付き＝`useCsvExport.ts:80`。機械処理向けには BOM 無し版も検討）・カンマ区切り・ヘッダ行付き。GeoJSON は RFC 7946 準拠（座標は `[lng, lat]` 順＝経度先）。日時は ISO 8601。種・情報種別はコード値（machine 用）とラベル（human 用）の両方、もしくはコード値＋データ説明での対応表を提供し、i18n ラベルに依存しない安定したキーで配布する。
- [ ] NFR-230-04: **再現性・運用手順。** 配布物生成と OSF/Zenodo へのスナップショット登録・DOI 反映の手順を runbook 化（`docs/runbooks/` に追加、`docs/runbooks/edge-function-deploy.md` の書式に倣う）。誰が見ても同じ手順で「最新スナップショットの公開と DOI 更新」ができること。バックアップ（REQ-217）とは目的が異なる（公開 vs 復旧）ため別手順とするが、生成ジョブ基盤は相乗り可。
- [ ] NFR-230-05: **性能・コスト非劣化。** 公開配布物の生成は ISR/静的生成または定期ジョブで行い、リクエスト毎に全件 SELECT して都度 CSV/GeoJSON を組む実装は避ける（egress・関数実行の増大防止）。`/dataset` ページ・配布ファイルはキャッシュ可能にし、`area/[municipality]`（`revalidate=86400`）と同等の鮮度方針（日次更新で十分＝分布は時間単位で変わらない）を踏襲する。
- [ ] NFR-230-06: **秘密値の非露出。** OSF/Zenodo の API トークン等を用いる場合は Secrets で扱い、リポジトリ・ログ・公開物に平文で残さないこと。手作業登録なら本書・runbook に実トークンを書かない。
