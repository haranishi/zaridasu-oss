## 要件概要

### 背景・目的
現状、調査依頼に対する会話は **`posts` 経由でしか成立しない**。具体的には:

- 結果投稿 (`posts`) は `survey_request_id` で依頼に紐付く（REQ-086 で確立）
- ユーザーは結果投稿に対するコメントを通じて間接的に依頼者と会話する
- しかし依頼そのもの（結果投稿が無い段階）に対する **直接コメント / 質問**は不可能

このため:
- 「依頼の意図を確認したい」軽量質問が場所を持てない
- 結果投稿が無いまま会話が始められない
- 同一依頼に複数結果投稿があるとコメントが分散する

REQ-084 のロードマップ最終 Phase 5 として、本要件は **調査依頼に直接コメントできるスレッド**を追加し、会話の分散を解消する。

### スコープ
**含む:**
- `survey_request_comments` テーブル新設（または既存 `comments` の polymorphic 化）
- 詳細ページ `/request/[id]` に直接コメントスレッド UI
- コメント投稿 / 削除（自分の投稿のみ）
- コメント通知（REQ-088 の通知基盤を流用）
- 既存 posts コメントとの両立（結果投稿のコメントは引き続き posts 側）
- 詳細ページで「依頼へのコメント」と「結果投稿へのコメント」を混在 view で統合表示

**含まない:**
- コメントの編集機能（投稿後は削除のみ）
- ネストスレッド（フラット 1 階層のみ）
- 画像 / 音声添付コメント（テキストのみ）
- リアクション / いいね（別要件）

### 前提条件・制約
- 既存 `comments` テーブルは `posts` 専用に紐付いている前提（実装確認が必要）
- 大規模リファクタを避けるため、**新規 `survey_request_comments` テーブル**を選択（polymorphic 化はリスク高）
- spam-check（REQ-007）が既存コメントに適用されているなら、新テーブルにも同等のロジックを適用
- 1 ユーザーのコメントレート制限: 24h で 30 件

### テーブル設計案の比較

| 案 | 概要 | 推奨度 |
|---|---|---|
| A: `comments` を polymorphic（target_type 列追加）化 | 全コメント統一管理 | × 既存 RLS / index 大幅改修 |
| B: `survey_request_comments` 新設 | 完全分離、シンプル | ◎ 推奨 |
| C: `posts` を介してすべてコメント | Phase 2 までの仕様 | × 結果投稿が無い依頼で会話できない |

→ **案 B を採用。view で両者を統合表示する。**
