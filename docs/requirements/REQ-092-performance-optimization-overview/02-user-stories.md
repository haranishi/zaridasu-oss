## 2. ユーザーストーリー

### US-001: 初訪問モバイルユーザーの即時表示
**As a** 秋田県の市民（4G モバイル、初回訪問）,
**I want to** ホーム（地図）を 2 秒台で操作可能にしたい,
**So that** ザリガニを見つけた瞬間に投稿できる。

**受け入れ条件:**
- [ ] AC-1: モバイル Lighthouse Performance ≥ 80
- [ ] AC-2: LCP ≤ 2.5s（モバイル / 3G Slow Throttle）
- [ ] AC-3: 地図のスケルトン → 実描画までのちらつき体感が現状以下
- [ ] AC-4: First Load JS（ホーム）≤ 220KB gzip

**優先度:** 高
**見積もり:** L

### US-002: 詳細ページの画像即時表示
**As a** 投稿詳細を開いたユーザー,
**I want to** 画像が CLS なく即時に出ること,
**So that** スクロール中にレイアウトが飛ばない。

**受け入れ条件:**
- [ ] AC-1: 投稿一覧は thumbnail（小サイズ）、詳細はフルサイズ AVIF/WebP で配信
- [ ] AC-2: 全投稿画像 / プレビュー画像が next/image を使用
- [ ] AC-3: CLS ≤ 0.1（モバイル）
- [ ] AC-4: `<img>` タグの直接利用がアイコン以外で 0 件

**優先度:** 高
**見積もり:** M（REQ-022 / REQ-041 を内包）

### US-003: ダッシュボードの統計が即出る
**As a** 自分の活動を確認したいログインユーザー,
**I want to** ダッシュボードを開いたら即時に統計が見えること,
**So that** ストレスなく自分の貢献を確認できる。

**受け入れ条件:**
- [ ] AC-1: ダッシュボード初回表示時の Supabase クエリ数が 1〜2 個
- [ ] AC-2: クライアント側で 2000 行を集計するロジックが消える
- [ ] AC-3: TTI ≤ 3.0s（モバイル）

**優先度:** 中
**見積もり:** M（REQ-032 を内包）

### US-004: 開発者がリグレッションを CI で検知
**As a** メンテナ,
**I want to** バンドルサイズと Lighthouse の悪化を PR で機械的に検知したい,
**So that** うっかり重い依存を入れても本番に届かない。

**受け入れ条件:**
- [ ] AC-1: CI で size-limit と lhci が走る（既に追加済 REQ-062）
- [ ] AC-2: size-limit の閾値を「実測値 +10%」まで締める
- [ ] AC-3: Lighthouse perf を `error` 0.8（現在 warn）に格上げ

**優先度:** 中
**見積もり:** S
