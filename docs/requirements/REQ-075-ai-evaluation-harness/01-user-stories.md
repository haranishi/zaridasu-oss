## ユーザーストーリー

### US-075-01: 開発者として施策の精度影響を計測したい
**As a** 開発者,
**I want to** 任意のモデル設定 / プロンプトに対して評価データセットを流して confusion matrix を得たい,
**So that** Phase 1 以降の施策が精度に与える影響を客観的に判定できる.

**受け入れ条件:**
- [ ] AC-1: `pnpm eval:ai audio --model=gemini-2.5-flash-lite` 形式で実行できる
- [ ] AC-2: 出力に **precision / recall / F1 / class-wise confusion matrix** が含まれる
- [ ] AC-3: 出力は標準出力 + JSON ファイル（`reports/eval/<timestamp>.json`）の両方
- [ ] AC-4: 同じデータセットで複数回実行した場合、結果は決定論的（temperature=0 等で固定）

**優先度:** 高
**見積もり:** M

### US-075-02: 開発者としてコスト施策の効果を金額で確認したい
**As a** 開発者,
**I want to** 直近 30 日 / 90 日の Gemini API 呼び出し回数と推定コストを月次で確認したい,
**So that** 施策のロールアウト前後で削減効果を金額として比較できる.

**受け入れ条件:**
- [ ] AC-1: `pnpm cost:ai --period=30d` で集計レポートが出力される
- [ ] AC-2: モデル別・Edge Function 別（image/audio）で呼び出し回数と推定コストが分かる
- [ ] AC-3: 管理画面 `/admin/ai-cost` で同じデータをグラフ表示（折れ線：日次推定コスト）

**優先度:** 中
**見積もり:** M

### US-075-03: 運用者として既存閾値の妥当性を確認したい
**As a** 運用者,
**I want to** 現状の自動承認/リジェクト閾値（0.75 / 0.85 / 0.70）が評価データセット上で過剰承認/過剰却下していないか分析したい,
**So that** Phase 1 のモデル切り替え時に閾値を再キャリブレーションできる.

**受け入れ条件:**
- [ ] AC-1: 評価レポートに **閾値ごとの自動承認率・自動リジェクト率・誤承認/誤却下件数** が含まれる
- [ ] AC-2: ROC 曲線または閾値スイープのグラフが出力される

**優先度:** 中
**見積もり:** S
