# REQ-330: 調査の日を「計画→案内→記録」の一続きにし、希少種は公開経路から切り離して記録する

作成日: 2026-10-01
優先度: P1 ／ 種別: UI + DB
状態: 実装済み（migration は本番未適用）
関連: REQ-329（位置の非公開・非公開スポット・経路リンク）、REQ-174（定点・structured）、REQ-283（フィールド探索モード・未実装の大構想）、REQ-331（構造の見直し 第1段）

## これは何か

本人要望（2026-10-01）は2つある。

1. 調査で希少種を見つけたとき「ここにいた」を記録したい。ただし公開すると採りに行かれるので、非公開で残したい。
2. 今日調べる場所にピンを立て、Google マップなどで順に案内できる「プロジェクト管理」の機能がほしい。

REQ-329 で投稿の位置は隠せるようになった。ただ、写真・種・市町村は公開のまま残る。しかも投稿の種は CHECK でアメリカザリガニとウシガエルの2種に限られており、希少種はそもそも種として記録できない。非公開スポットは名前とメモだけの地点メモで、「何がいたか」を持てない。どれも足りない。

本要件は、調査の日を「計画する → 案内される → 地点ごとに結果を残す」の一続きにする。地点ごとの結果は、外来種がいた（公開の投稿）、いなかった（不在の投稿）、希少種がいた（非公開の記録）の3種類で残す。希少種の記録は、公開の地図・一覧・公開データ・集計に**構造的に届かない**置き場へ入れる。

## 主要な決定（理由つき）

- **希少種の記録は posts に入れず、別表 `rare_sightings` と非公開の写真置き場 `rare-photos` に置く。** posts から漏れる道は多い。RLS を通らない公開 RPC（集計・ランキング・週報など約26本）、誰でも一覧できる写真置き場 `post-photos`、投稿の状態に関係なく全件公開の comments・likes がある。posts に入れると、これら全経路に除外条件を書き続けることになり、1か所の書き忘れで公開される。別表なら既存の公開経路はこの表を参照しない。REQ-329 も同じ理由で「投稿ごと隠す」案を採らなかった。
- **見られるのは本人と運営（管理者）だけ。** anon には GRANT 自体を付けない（`private_spots` と同じ形）。写真は期限付きの署名URLで表示する。
- **種は一覧から選び、無いものは名前を書く。** 一覧はコードの定数1か所に置き、DB は形式（英小文字の識別子）だけを検査する。種を足すたびに migration を書かずに済む。
- **調査計画は DB に置く**（`survey_plans`・`survey_plan_stops`・`survey_stop_posts`）。端末だけの保存では足りない。家のPCで計画して現地のスマホで使う、過去の計画を残す、研究で「どこを・いつ・調べたか」を集計する。この3つのどれにも、機器をまたぐ保存が要る。設計の見直し（REQ-331）では端末保存の第一版も提案されたが、機器間で共有できず運営も見られないので採らない。圏外の現場には、端末側の控えと送信待ちで備える。
- **計画・地点と投稿のつながりも、本人と運営だけの別表に置く。** posts に列を足すと anon から見える（列単位の GRANT が posts の全列に付いている）。
- **地点から作る投稿は `survey_method='structured'` にする。** その地点に希少種の記録があるときは、地点から作る投稿の位置を `hidden` にする。外来種の公開投稿の位置から希少種の池を推測されるのを防ぐためだ（市場調査 2026-09 の指摘）。
- **「いなかった」は地点シートから確認1回で記録する。** 不在の記録は研究価値が最も高いのに、投稿フォームの5択に埋もれていて累計0件だった（9/28 時点）。
- **案内は2つ。** 「次の地点へ」は既存の経路ボタン（Google・Yahoo!・Apple）を使う。「まとめて開く」は Google マップだけで、4地点ずつに区切る。経由地はスマホのブラウザで開くと3か所まで、URL は2,048字までという制限があるため。URL には座標だけを載せ、地点名は載せない（REQ-329 の約束）。
- **新しいコードは機能フォルダ `src/features/fieldwork/` にまとめる**（REQ-331 で規約化）。地図への差し込みは MapView に1行だけにする。

## 未決の論点（暫定の見立てつき）

- **投稿の上限（24時間5件）。** 管理者でない人は、6地点以上の計画で途中から投稿できなくなる（不在の投稿も1件に数える）。今回は変えない。posts の挿入トリガーは影響範囲が広く、いまの主な利用者（本人）は管理者で上限の対象外だからだ。春に高校などと協働する前に、「構造化調査は別枠」とする案を別の要件で決めたい。
- **希少種一覧の中身。** 暫定で、ニホンザリガニ・メダカ・ゼニタナゴ・シナイモツゴ・トウホクサンショウウオ・クロサンショウウオ・ゲンゴロウのなかま・タガメ・その他とする。協力団体と相談して差し替える前提で、差し替えはコードの定数1か所で済む。
- **卒業後に「運営だけが見られる記録」を誰が管理するか。** 決まっていない。管理者の引き継ぎは Supabase の app_metadata.role の付け替えでできるが、引き継ぎ先は本人が決める。
- **圏外での写真。** 今回は電波のある場所だけで写真を付けられる。圏外では写真なしで保存して送信待ちに入れる。
