# REQ-158: PostForm のエラー表示の不統一と aria-live 欠落

## 背景
投稿フォーム `PostForm.tsx`（`src/components/features/posts/PostForm.tsx`）には、ユーザーへ提示するエラーが複数種類存在するが、それぞれ表示場所・表示形式・支援技術への通知方法がバラバラになっている。エラーの種類ごとに表示位置が異なるため、ユーザー（特にスクリーンリーダー利用者）がエラーの発生に気づけない、あるいは原因のフィールドへたどり着けない問題がある。

WCAG 2.1 の以下に関連する:
- **3.3.1 エラーの特定（レベル A）**: エラーがテキストで提示されてはいるが、提示先が統一されておらず一貫した特定が困難。
- **4.1.3 ステータスメッセージ（レベル AA）**: 動的に表示されるエラーメッセージに `aria-live` 等のライブリージョン指定がなく、フォーカスを移動せずに発生を通知できない。

## 現状の問題
`PostForm.tsx` には、状態として 3 種類のエラーが定義されている（96〜98行）:
- `positionError`（96行）: 位置未選択エラー。
- `inlineError`（97行）: 個体数バリデーション / コメント文字数バリデーションエラー（送信時）。
- `countError`（98行）: 個体数入力中のリアルタイムバリデーションエラー。

加えて、`usePostForm` フックから来る `error`（送信処理・アップロード起因のエラー）も存在する。

これらの表示先が以下のように分散している:

1. **`error` と `inlineError`** → フォーム上部のスティッキーバナー（228〜243行）でまとめて表示。`{(error || inlineError) && (...)}` の条件で OR 表示。`role` / `aria-live` の指定なし。
2. **`positionError`** → `LocationSection` コンポーネントへ prop として渡され（267行）、位置選択セクション内に表示される（PostForm 本体には表示されない）。
3. **`countError`** → 個体数入力欄の直下に `<p className="text-red-500 text-xs mt-1">`（353行）でインライン表示。`aria-live` / `aria-describedby` 指定なし。
4. **コメント文字数カウンタ**（400〜404行）→ 残り文字数を色だけで警告（`text-red-500` / `text-yellow-500`）。文字超過時の `inlineError`（送信時・155行）とは別の場所・別の見え方。

結果として:
- 個体数のエラーが「入力中は欄の直下（countError）」「送信時は上部バナー（inlineError）」と二重・二箇所に分かれる。
- 位置エラーだけ別コンポーネント内に表示され、上部バナーには出ない。
- いずれのエラーにも `aria-live` がないため、送信ボタン押下でエラーが表示されてもスクリーンリーダーが読み上げず、視覚を使わないユーザーは「送信されない理由」が分からない。
- 送信時の検証（145〜156行 `handleSubmit`）でエラーになっても、フォーカスは送信ボタンに留まり、エラー箇所へ移動しない。

## 目的
PostForm の全エラーについて、表示位置・形式を統一し、`aria-live` によるライブリージョン通知を付与する。ユーザーがエラー発生を確実に認識し、原因フィールドへたどり着けるようにする。

## 要件
### 機能要件
- [ ] FR-158-01: 送信時バリデーションに起因するエラー（`error` / `inlineError` / `positionError`）を、フォーム上部のスティッキーバナー（228〜243行）に集約表示する。位置エラーも本バナーに表示されるようにする（`LocationSection` 内の個別表示と二重にならないよう整理する）。
- [ ] FR-158-02: 上部エラーバナー（229行の `<div>`）に `role="alert"` と `aria-live="assertive"` を付与し、エラー出現時に支援技術へ即時通知する。
- [ ] FR-158-03: 個体数の入力中バリデーション（`countError`、353行）は欄直下のインライン表示を維持しつつ、`aria-live="polite"` を付与し、入力欄から `aria-describedby` で関連付け、`aria-invalid` を連動させる。
- [ ] FR-158-04: 送信時（`handleSubmit`、145行〜）に検証エラーが発生した場合、エラーを表示するだけでなく最初のエラー該当フィールド（または上部バナー）へフォーカスを移動する。
- [ ] FR-158-05: コメント文字数の警告（400〜404行）は、色のみに依存せず、超過時はテキスト（または `aria-live`）でも超過状態が伝わるようにする。

### 非機能要件（該当する場合）
- [ ] NFR-158-01: エラー表示ロジックの統一により、エラー種別ごとの表示分岐の重複を減らす（DRY）。
- [ ] NFR-158-02: ライブリージョンの過剰通知を避けるため、即時性が必要なもの（送信失敗）は `assertive`、入力中のものは `polite` を使い分ける。

## 受入条件
- [ ] AC-01: 個体数の不正値・コメント超過・位置未選択のいずれのエラーも、送信時に同一のエラーバナー（上部）へ表示される。
- [ ] AC-02: 送信ボタン押下でエラーが発生した際、スクリーンリーダーがエラー文言を自動で読み上げる（`role="alert"` / `aria-live` により）。
- [ ] AC-03: 送信時バリデーションエラー発生後、フォーカスがエラー箇所（または上部バナー）に移動する。
- [ ] AC-04: 個体数欄の入力中エラーが `aria-invalid` と `aria-describedby` で入力欄に関連付けられ、欄フォーカス時に読み上げられる。
- [ ] AC-05: コメント超過状態が、色覚特性に依存せずテキスト/支援技術で判別できる。

## 影響範囲
- `src/components/features/posts/PostForm.tsx`（96〜98行の状態定義、145〜156行の handleSubmit、228〜243行のエラーバナー、336〜353行の個体数欄、400〜404行のコメントカウンタ）
- `src/components/features/posts/LocationSection.tsx`（positionError の表示箇所。集約表示への移行に伴う調整）
- 関連テスト: PostForm のバリデーション/アクセシビリティテスト

## 優先度
- **緊急度**: 中 / **重要度**: 中 / **理由**: WCAG 4.1.3（AA）および 3.3.1（A）に関わり、視覚を使わないユーザーにとって投稿失敗の原因が分からないという実害がある。一方で表示自体はテキストで存在するため致命的ではなく、UI ロジックの整理を伴うため中程度の優先度とする。
