## 非機能要件（全 Phase 共通）

### コスト削減目標
| 指標 | 現状（基準） | 目標 |
|---|---|---|
| 月額 Gemini API コスト | 1.00x（基準） | **0.10〜0.15x**（85% 減） |
| 1 投稿あたり API コスト | $0.0010（推定） | $0.00010〜0.00015 |
| 1 日あたり呼び出し数 | 投稿数 × 2 | 投稿数 × 0.7 程度（事前ゲートで削減） |

### 精度許容範囲
| 指標 | 許容低下幅 |
|---|---|
| ウシガエル recall（取りこぼし） | 施策前比 -3 ポイント以内 |
| ウシガエル precision（誤承認） | 施策前比 -2 ポイント以内 |
| 自動却下の false positive 率 | 施策前比 +1 ポイント以内（誤却下は最も避ける） |

### レイテンシ要件
- 投稿 → AI 判定完了までの **P50 レイテンシは現状維持**（10 秒以内）、**P95 は 15 秒以内**
- 各 Phase の施策がレイテンシを増加させないこと（Context Caching 等は逆に短縮されるはず）

### セキュリティ
- 評価フィクスチャの音声/画像は実投稿データから派生する場合、**個人情報（位置情報、投稿者特定情報）を含まない**形に処理してから `tests/fixtures/` 配下に置く
- 評価スクリプト実行時に Gemini API キーがログに残らない
- audio_hash / image_hash の追加は RLS ポリシー対象（既存 `posts` のポリシー範囲内）

### 可用性
- Phase 1〜4 のロールアウトは **段階的（フィーチャーフラグ or 環境変数）** で行い、不具合時に即時ロールバック可能
- Edge Function のキャッシュ機構（Phase 3）は **キャッシュ未ヒット時にも正常動作**すること（フェイルオープン）
