## リスク・トレードオフ

| リスク | 影響 | 緩和策 |
|---|---|---|
| Flash-Lite 化により精度低下 | 自動承認の品質低下 → 手動レビュー負荷増 | Phase 0 評価基盤で A/B 検証、許容範囲外なら閾値再キャリブレーション or ロールバック |
| クライアント圧縮で AI 判定が困難に | recall 低下、特に微妙な音声が判定不能に | 圧縮レベルを段階的に（48k→24k→16k）試し評価基盤で検証 |
| `gemini-3.1-flash-lite-preview` の preview 依存 | API 仕様変更や提供終了で突然動かなくなる | Phase 1 で **stable リリース版に戻す or fallback モデル指定**を検討 |
| Context Caching の保存料金 | 想定より小トラフィックだとキャッシュ料金が割高 | TTL を短め（5 分〜15 分）から開始、利用状況見て延長 |
| hash dedup での誤再利用 | 異なる投稿が同じハッシュ → 過去判定が再利用され不適切 | SHA-256 + ファイルサイズも併用、衝突時はフォールバックで再判定 |
| クライアント側ゲートが過剰に弾く | 投稿率低下、UX 悪化 | 警告に留め強制弾きはしない、テレメトリで弾き率を監視 |
