## 0. 要件サマリー

2026-07-28、リポジトリ管理外の旧 Database Webhook トリガー `analyze-image-on-insert` の定義に、**service_role の JWT がリテラルで埋め込まれていた**ことが判明した。`pg_get_triggerdef()` を読める者がキーを取得できる状態であり、値は**現行の service_role キーそのもの**で、有効期限は 2036 年相当である。

トリガーは同日削除済みで、DB 内からキーは消えている。**公開漏洩ではない**（リポジトリの作業ツリー・git 履歴のいずれにも存在せず、GitHub リポジトリは private、PostgREST は `pg_catalog` を公開しないため読めたのは DB 管理者権限を持つ者だけ）。したがって緊急ローテーションは不要である。

一方で衛生上は差し替えるべきであり、その手段として **Supabase の新方式キー（`sb_publishable_` / `sb_secret_`）への移行**を選ぶ。実測の結果、**新方式キーは 2026-03-04 に既に発行済み**であり、移行の前提は整っている。

> [!important] 本要件のスコープ判断
> レガシー `anon` キーの無効化はフロントエンドのバンドルに焼き込まれた値を差し替える必要があり、**全ユーザーのログアウトを伴わないが公開面の停止リスクがある**。本要件は **service_role 側（`sb_secret_`）の移行を主眼**とし、publishable 側の切り替えは段階を分けて扱う（FR-287-06）。
