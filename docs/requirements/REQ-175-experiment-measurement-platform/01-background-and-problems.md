## 背景
本アプリ「ザリダス」は卒業研究の仮説検証基盤であり、REQ-170〜174 で導入する各種介入（AIフィードバック、新ランキング等）が市民の投稿行動を実際に改善するかを定量的に実証する必要がある。これは卒研の核となる検証であり、最重要要件と位置づける。

Notion 先行研究レビュー RQ1「介入評価デザイン」の総括では、以下が指摘されている。
- **単純な前後比較（pre/post）は季節効果と交絡する**。ザリ（アメリカザリガニ等）の活動・目撃は季節依存性が強く、介入投入の前後で投稿数を比べても、増加が介入由来か季節要因かを分離できない。
- そのため、**DID（差分の差分法: Difference-in-Differences）または段階的ロールアウト（staggered rollout）による準実験デザイン**を推奨する。介入群と対照群（または介入投入時期の異なる群）を同一期間で比較し、季節効果を相殺する。
- 評価は単一指標ではなく、**4指標（投稿数・位置精度・写真添付率・リピート投稿率）を独立に追跡**し、ある指標の向上が別の指標を犠牲にしていないか（トレードオフ）を検出する。
- 仮説 **H2** は「介入により指標が有意に向上する」に留め、p 値の二値判定ではなく**効果量（effect size）とその信頼区間（CI）を報告**する設計が、サンプル規模が限られる卒研では堅実である。

本基盤は、この「介入評価デザイン」を技術的に成立させるための土台（フィーチャーフラグによる安定割付 + 4指標の独立計測 + 群×期間の集計 + 研究用匿名エクスポート）を提供する。

## 現状の問題
- `src/app/layout.tsx:65-74,138-141`: GTM スニペット（`NEXT_PUBLIC_GTM_ID`）は注入されるが、**機能フラグ単位の出し分けや群（variant）割付の仕組みは一切ない**。`grep -rli "feature.?flag|featureFlag|experiment|variant|ab.?test" src` のヒットは `src/hooks/usePostForm.ts`（EXIF まわり）と `src/lib/image/compressJpeg.ts` のみで、実験機構として該当する実装は存在しない。
- `src/components/common/WebVitalsReporter.tsx:12-27`: 計測は web-vitals を `window.dataLayer` に push するのみ。**4指標（投稿数・位置精度・写真添付率・リピート投稿率）を群・期間ごとに独立計測・比較・エクスポートする経路がない**。GA4/GTM はユーザー単位の安定した群分離も DID 集計も提供しない。
- `src/hooks/useAdminStats.ts:89-105`: 集計は `get_admin_post_stats` RPC 等に寄せられているが、**「実験群 × 期間」での層別集計に対応していない**。総数・種別・月次・市区町村の単純集計のみ。
- `src/components/features/dashboard/KPISection.tsx:43-120`: ダッシュボードは全体集計の表示専用で、**群間比較・効果量・信頼区間を表示する UI がない**。
- `src/types/database.types.ts:10-58`: `posts` テーブルには `created_at` / `user_id` / `photos`（写真添付の有無＝添付率算出に使用）/ `lat` `lng`（位置精度の基礎）/ `is_anonymous` があるが、**投稿に「どの実験群で行われたか」を紐づけるカラムがなく**、群別の事後集計ができない。位置精度を測る基礎として、EXIF GPS 由来か手動指定かの区別（`src/hooks/usePostForm.ts:81-91`）も保存されていない。
- `supabase/schema.sql:1042-1056`: `user_profiles` テーブルは存在する（`id` / `is_public` / バッジ系）が、**ユーザーの実験割付（variant）を安定保持する列がない**。ログインユーザーの安定割付の保存先が未整備。
- 結論として、H2 を準実験デザインで実証する基盤が欠落しており、現状では「介入の効果を季節効果と分離して測定する」ことができない。
