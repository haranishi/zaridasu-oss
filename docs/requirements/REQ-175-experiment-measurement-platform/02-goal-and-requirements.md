## 目的
フィーチャーフラグによる介入の段階ロールアウト/簡易A-B割付（ユーザーID ハッシュによる安定割付）と、4指標を群×期間で独立に集計・比較・匿名エクスポートする計測基盤を整備し、REQ-170〜174 の介入効果を準実験デザイン（DID/段階ロールアウト）で実証可能にする。倫理・プライバシー・再現性を満たした、卒研の仮説 H2 検証に耐える基盤を提供する。

## 要件

### 機能要件

#### フィーチャーフラグ / 群割付
- [ ] FR-175-01: 実験定義テーブル（例 `experiments`）を新設する。各実験は `key`（例 `ai_feedback` = REQ-170、`new_ranking` = REQ-171）、`enabled`、`rollout_percentage`（0〜100の段階ロールアウト率）、`variants`（例 `["control","treatment"]`）、`seed`（割付ハッシュ用ソルト）、`started_at` / `ended_at` を持つ。
- [ ] FR-175-02: ユーザーの群割付を**ユーザーID（未ログイン時は匿名安定IDのハッシュ）と実験 `seed` の決定的ハッシュ**で算出する安定割付関数を実装する。同一ユーザー・同一実験では常に同じ群になり、再読み込み・端末間で割付がブレないこと。
- [ ] FR-175-03: ログインユーザーの割付結果を `user_profiles`（または専用 `experiment_assignments` テーブル）に保存し、事後の群別集計で投稿と突合できるようにする。保存は「割付の確定（exposure）時」に行う。
- [ ] FR-175-04: 段階ロールアウト（`rollout_percentage`）に対応する。例: 20% のときハッシュ下位20%のユーザーのみ treatment、それ以外は control。率を引き上げると追加分のみ treatment に移行する単調性を担保する。
- [ ] FR-175-05: クライアントから現在のユーザーの全フラグ/群を取得する仕組み（例 React フック `useExperiment(key)` または `useFeatureFlag(key)`）を提供し、UI 側で介入の出し分け（AIフィードバックON/OFF、ランキング新旧）に使えるようにする。
- [ ] FR-175-06: フラグ評価結果はサーバー側で確定し、UI 出し分けのちらつき（フラッシュ）を避ける。SSR/RSC 経路でも同一の割付関数で評価できること。
- [ ] FR-175-07: 投稿作成時に、その投稿が**どの実験のどの群で行われたか**を `posts` に記録する（例 `posts.experiment_assignments` JSONB、または `posts.variant_*` 列）。事後の群別 4指標集計の突合キーとする。

#### 4指標の独立計測
- [ ] FR-175-08: 「位置精度」を測定可能にするため、投稿時に**位置の取得方法（EXIF GPS / 手動ピン / 端末 Geolocation）と、利用可能なら精度（accuracy 値）**を投稿に保存する（`src/hooks/usePostForm.ts:81-91` の EXIF 経路を活用）。
- [ ] FR-175-09: 4指標を群×期間で集計する RPC を新設する（例 `get_experiment_metrics(p_experiment_key, p_from, p_to)`）。返却は群ごとに以下を独立に含む:
  - 投稿数（件数）
  - 位置精度（例: GPS/手動の比率、または accuracy 中央値）
  - 写真添付率（`photos` が非NULL かつ非空の投稿の割合）
  - リピート投稿率（期間内に2回以上投稿したユーザーの割合、または1人あたり平均投稿数）
- [ ] FR-175-10: 同 RPC は、DID 算出に必要な**介入前後（pre/post）× 群（control/treatment）のセル別の値**を返せること（4セルの平均と件数）。これによりダッシュボード/エクスポート側で DID 推定量と効果量を計算できる。
- [ ] FR-175-11: 各指標について**効果量とその信頼区間（CI）の算出に必要な統計量**（群ごとの n、平均、分散または比率と分母）を返し、p 値の二値判定に依存しない報告（H2 の設計に整合）を可能にする。

#### 管理ダッシュボード（群間比較）
- [ ] FR-175-12: `src/app/admin` 配下に実験計測ビューを追加し、選択した実験について**群×期間の4指標を並べて比較表示**する（control vs treatment）。各指標はトレードオフ検出のため独立のカード/グラフで表示する。
- [ ] FR-175-13: 各指標について、群間差分・効果量・信頼区間（または DID 推定量）を表示する。CI が0をまたぐ場合は「有意でない可能性」を視覚的に示す。
- [ ] FR-175-14: 既存の `useAdminStats` / `KPISection` の集計パターン（`Promise.allSettled` による部分失敗許容、集計RPCへの集約）に倣い、一部指標の取得失敗が他指標表示を巻き込まないこと。
- [ ] FR-175-15: 実験のロールアウト率・有効/無効を管理画面から切り替えられる（フラグ管理 UI）。変更は監査ログ（`audit_logs`）に記録する。

#### 研究用エクスポート
- [ ] FR-175-16: 研究用に**匿名化された群×期間×指標の集計データ**を CSV または RPC で取得できるエクスポート機能を提供する。出力は集計値のみで、個人を特定可能な生データ（user_id 原文、緯度経度の生値、写真URL等）を含めないこと。
- [ ] FR-175-17: エクスポートは管理者権限でのみ実行可能とし、実行を `audit_logs` に記録する。

### 非機能要件
- [ ] NFR-175-01（倫理・同意）: 実験参加は市民科学プロジェクトの通常利用の範囲とし、UI 出し分けは利用体験を著しく損なわないものに限る。介入内容と「機能改善のための計測を行う旨」を利用上の説明（プライバシー/利用案内）に明記する。割付によって投稿の可否や安全性に差を生じさせない。
- [ ] NFR-175-02（プライバシー・匿名化）: 群割付・集計・エクスポートはすべて**個人特定不可（集計のみ）**を原則とする。位置精度指標は accuracy 値や GPS/手動の別など**精度メタデータのみ**を集計し、生の緯度経度を研究用出力に含めない。匿名ユーザーの安定IDは個人を再識別できない一方向ハッシュとする。
- [ ] NFR-175-03（再現性）: 割付は決定的（同一 user_id + seed → 同一群）で再現可能であること。実験定義（key/seed/rollout/期間）は DB に永続化し、集計の再実行で同じ結果が得られる。マイグレーションは `supabase/migrations/` に追加し、`supabase/schema.sql` と同期する（REQ-003 のスキーマ同期方針に従う）。
- [ ] NFR-175-04（RLS/権限）: 実験定義・割付・集計RPC・エクスポートは RLS で保護する。割付保存はユーザー本人または service role のみ、集計/フラグ管理/エクスポートは管理者のみ。集計RPC は `SECURITY DEFINER` の場合でも個人行を露出しないこと。
- [ ] NFR-175-05（性能）: 4指標集計はクライアントでの全行転送を行わず、`get_admin_post_stats` 同様に DB 側 GROUP BY 集計 RPC で完結させる。ダッシュボードの群比較1回の往復で取得できること。
- [ ] NFR-175-06（型安全）: 新規テーブル・RPC は `src/types/database.types.ts` に型を追加し、`Database` 型・RPC Args/Returns 型と整合させる。
- [ ] NFR-175-07（フォールバック）: フラグ機構が利用不能（実験未定義・取得失敗）の場合は安全側（control / 介入OFF）にフォールバックし、通常投稿機能を阻害しない。
