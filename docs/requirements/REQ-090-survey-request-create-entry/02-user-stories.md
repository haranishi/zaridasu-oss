## ユーザーストーリー

### US-090-01: 一般ユーザーとして調査を依頼したい
**As a** ザリダスのログインユーザー（一般市民、研究者、自治体職員）,
**I want to** 「調査依頼を立てる」ボタンを画面のどこかから 1〜2 タップで見つけて押せる,
**So that** 自分の地域の外来種について他のユーザーに調査を頼める.

**受け入れ条件:**
- [ ] AC-1: 任意の画面でハンバーガーメニュー（左上）→ 「🔍 調査依頼を立てる」を 2 タップで到達できる
- [ ] AC-2: `/requests` ページの右下に常時 FAB が見え、1 タップで `SurveyRequestForm` が開く
- [ ] AC-3: 開いたフォームから依頼を送信できると、一覧が即座に再取得され先頭に新しい依頼が現れる
- [ ] AC-4: 送信成功後、フォームは自動で閉じる

**優先度:** 高 ／ **見積もり:** S

### US-090-02: 未ログインユーザーとして自然にログインへ誘導されたい
**As a** 未ログインの訪問者,
**I want to** 「依頼を立てる」を押した時に、フォームが空打ちで開くのではなくログインを促される,
**So that** 何が必要かを把握してからログインできる.

**受け入れ条件:**
- [ ] AC-1: 未ログインで FAB / メニュー項目を押すと、`AuthModal`（login タブ）が開くか `/auth` に遷移する
- [ ] AC-2: 「ログインが必要」を一瞬でも視覚的に知らせる（モーダル即時オープンで足る）
- [ ] AC-3: フォームが空打ちで開いた直後に `null` を返して画面が壊れる挙動が起きない

**優先度:** 高 ／ **見積もり:** XS

### US-090-03: スマホで FAB が他 UI と重ならないでほしい
**As a** スマホでアプリを使うユーザー,
**I want to** FAB が BottomNav や iOS の home indicator にめり込まないこと,
**So that** ボタンが押せる / 視認できる.

**受け入れ条件:**
- [ ] AC-1: iPhone Safari（safe-area あり）で FAB が BottomNav の上に visible で配置される
- [ ] AC-2: BottomNav が表示されない画面（該当なし。`/requests` は `VISIBLE_PATHS` に未登録の場合 BottomNav は出ない＝より下部に置ける）でも自然に見える
- [ ] AC-3: FAB のヒットエリアが 44×44pt 以上を満たす（iOS HIG / Material 推奨）

**優先度:** 中 ／ **見積もり:** XS

### US-090-04: アクセシビリティ準拠でキーボード/SR ユーザーが到達できる
**As a** スクリーンリーダー / キーボード利用者,
**I want to** 「調査依頼を立てる」ボタンに到達でき、ラベルで何のボタンか分かる,
**So that** マウス無しでも依頼を立てる導線にアクセスできる.

**受け入れ条件:**
- [ ] AC-1: FAB / メニュー項目の `aria-label` が「調査依頼を立てる」または同等
- [ ] AC-2: Tab キーで FAB / メニュー項目にフォーカス可能、Enter / Space で発火
- [ ] AC-3: モーダル開閉時に `useFocusTrap` 相当でフォーカスが閉じ込められる（`SurveyRequestForm` 既存実装に依存）

**優先度:** 中 ／ **見積もり:** XS
