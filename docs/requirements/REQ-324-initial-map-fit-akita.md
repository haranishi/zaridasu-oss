# REQ-324: 初期の地図表示を秋田県全域に合わせる

作成日: 2026-09-06
優先度: P2 ／ 種別: UI
状態: 実装済み（2026-09-06）
関連: REQ-323（UI 採点 第5周）、`.agent-harness/runs/2026-08-16-uiux-loop/NEEDS-HUMAN.md` 論点 3-b、REQ-243（位置情報プライバシー・座標の露出範囲は変えない）

## これは何か

トップの地図は `AKITA_CENTER` と `AKITA_ZOOM`（9）の固定値で開いていた。横長の画面（1440px）では左 35% が海になり、青森・岩手が主役に見える。UI 採点で第 0 周と第 5 周の 2 回指摘されたが、「最初に何を見せるか」はプロダクト判断なのでハーネスでは触らず保留していた。2026-09-06 に本人が「秋田県に合わせる」と決めた。

## 要件

- **FR-324-01**: トップの地図は表示直後に `AKITA_FIT_BOUNDS`（県のおおよその実範囲。南北 38.87〜40.51・東西 139.69〜140.99）へ `fitBounds` する。検証用の `AKITA_BOUNDS` は東端が岩手側まで広いので使わない。ズームは整数のまま（小数ズームはタイルの継ぎ目に 1px の線が出るのを実測）。余白込みで入る整数ズームより 1 段寄っても、余白なしで県全域が画面に収まるならそちらを選ぶ（実測: 1440×900 は 8 だと東北全体が映るので 9、390×844 は 9 だと幅が足りないので 8）。
- **FR-324-02**: 余白は上 56px・左右 12px・下は幅 640px 以上で 96px、未満で 160px。上は地図コントロール、下は種別カード（`bottom-20`）と初回訪問の紹介カードに県の端が隠れないぶん。
- **FR-324-03**: 合わせるのは最初の 1 回だけ。利用者が動かしたあとに戻さない。現在地ボタンや投稿の地図（`LocationSection` / `SurveyRequestForm`）は対象外で、従来の中心・ズームのまま。
- **FR-324-04**: `BoundsWatcher` より後に置き、`animate: false` で流す。`moveend` の購読が付いたあとにフィットするので、表示範囲のフィルタ（`onBoundsChange`）は最初からフィット後の範囲で動く。

## 受け入れ条件

- **AC-01**: 1440×900 と 390×844 のどちらでも、初期表示に秋田県の北端（八峰町）と南端（にかほ市・湯沢市）が入る。
- **AC-02**: 初期表示で、種別カードと地図コントロールが県の端のマーカーを隠さない。
- **AC-03**: 既存の E2E（`tests/e2e/*.spec.ts`・38 件）が通る。

## やらないこと

- LCP 用の先行タイル（`public/map-tile-placeholder.png`）は取り直さない。ぼかした下敷きなので、ズームが 9 から 8 に変わっても絵柄の一致は要らない（`HomePage.tsx` の注記）。
- 現在地が取れたときに現在地中心へ寄せる案（NEEDS-HUMAN 3-b の第 3 案）は採らない。位置情報の許可を求める挙動を初期表示に足さない。
