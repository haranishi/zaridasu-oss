## 目的

- ザリダスに、シェイプ言語で設計した**マスコット（SVG）**と**組み合わせ型ロゴ**を与え、favicon（16〜20px）からホーム画面アイコン・OG カードまで**一貫した固有の図像**で「ザリダスだ」と一目で分かる状態にする（ブランド VI ノート §6・良いロゴ 5 条件 Scalable）。
- ブランド資産を **1 枚ブランドメモ**（公式 HEX・2 書体・Voice & Tone の形容詞 3〜5 個＋アーキタイプ＋ Do/Don't・ロゴのクリアスペース/最小サイズ/誤用例）として文書化し、UI・OG・通知・SNS・LP のすべてが同じ判断基準で一貫できるようにする。
- 絵文字依存・壊れた `favicon.ico` 参照・旧ドメイン参照を解消し、配信元と図像を一本化する。
- OG・シェアカードの**被写体・構図のガイドライン**（主役 1 つ・リーディングライン・セーフエリア・マスコットの置き方）を定め、REQ-027/REQ-042 の動的生成ロジックがブランド一貫した画像を出せる土台を渡す。
- マスコットを**空状態の挿絵**（REQ-222 と連動）など UI のやさしい体験へ転用できる形（複数ポーズ）で用意する。
- 上記すべてを、`docs/lp-copy.md` の確定方針（大学名・「卒業研究」NG、やさしい言葉、ベネフィット主導、誇張なし）に厳密に従って行う。

### 非機能要件（該当する場合のみ）

- [ ] NFR-225-01: **Scalable（縮小耐性）。** マスコット/ロゴ/favicon は SVG（パス）で、20px〜512px で破綻しないこと（良いロゴ 5 条件・シルエットテスト）。ラスタ（`og-image.png` 等）は必要箇所のみとし、SVG を正本とする。
- [ ] NFR-225-02: **配信の軽量性。** 追加する SVG はインライン化または `public/` 配信で、LCP/初期表示に悪影響を与えないサイズに収める（マスコット SVG は装飾用途。Web フォント追加〔FR-225-07〕を行う場合は `display: swap`・サブセット等で体感速度を損なわないこと）。
- [ ] NFR-225-03: **一貫性（Single Source of Truth）。** ブランド色・書体・ロゴ配置・トーンは 1 枚ブランドメモ（FR-225-08）を唯一の正本とし、`tailwind.config.js` / `layout.tsx` / `manifest.ts` / `og-image.svg` / `opensearch.xml` の値がそこと矛盾しないこと（ブランド VI ノート §6・§7）。CSS 変数化の実体は REQ-224 と整合させる。
- [ ] NFR-225-04: **多言語トーンの一貫性。** Voice ガイド（FR-225-08）は ja/en/ko/zh 共通の判断基準として機能し、各言語の見出し/CTA（`src/locales/*/translation.json` の `lp.*` 等）が同じ人格・トーンで書かれていること（言語ごとに人格が変わらない）。
- [ ] NFR-225-05: **方針順守（ブランド禁止語）。** すべての成果物（マスコットの説明・Voice メモ・OG コピー・OpenSearch 文言）で、**大学名・研究室名・「卒業研究」「研究プロジェクト」を使わない**（`docs/lp-copy.md` 確定事項・project memory）。学生が作ったことは `docs/lp-copy.md` §⑤の表現（「秋田の自然が大好きなひとりの大学生がつくった」）の範囲に留める。
- [ ] NFR-225-06: **アクセシビリティ。** 装飾目的のマスコット/ロゴ SVG は支援技術から無視（`aria-hidden` / `role="presentation"` 等）し、意味を持つロゴには適切な代替テキスト（例: 「ザリダス」）を与えること。配色のコントラスト基準そのものは REQ-224 が主管。
