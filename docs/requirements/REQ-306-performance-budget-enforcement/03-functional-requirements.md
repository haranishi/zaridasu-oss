## 機能要件

- **FR-306-01**: **ルート単位の First Load JS 合計**を CI でゲートする仕組みを追加する。`.next/app-build-manifest.json` の各ルートのファイル一覧を gzip 圧縮して合算し、ルートごとの上限と比較して超過時に非 0 終了するスクリプト（`scripts/check-first-load-js.mjs` 相当）を新設し、`npm run size:routes` として `package.json` に登録する。**本監査で用いた手法をそのまま実装に落とす**。対象ルートは最低限 `/`・`/lp`・`/post/[id]`・`/collection`・`/trends`・`/ranking`・`/dashboard` の 7 本。
- **FR-306-02**: FR-306-01 の初期閾値は **「2026-07-30 実測値 ＋ 約 5% のヘッドルーム（10 kB 単位に丸め）」**とする。ヘッドルームは日常的な依存更新のゆらぎを吸収するためで、それ以上の増加は必ずレビュー対象にする意図。

  | ルート | 実測（2026-07-30） | 提案初期閾値 |
  |---|---|---|
  | /dashboard | 347.1 kB | 360 kB |
  | /collection | 335.1 kB | 350 kB |
  | / (home) | 332.2 kB | 350 kB |
  | /post/[id] | 330.6 kB | 350 kB |
  | /trends | 305.4 kB | 320 kB |
  | /ranking | 305.3 kB | 320 kB |
  | /lp | 214.6 kB | 225 kB |

- **FR-306-03**: `.size-limit.json` に**共有チャンクのエントリを追加**する（少なくとも Sentry+app-router 9898、Supabase 6962、zod 5653、ja 翻訳 4600、i18next 5662 に相当するもの）。**ただし FR-306-01 を主ゲートとし、こちらは内訳の可視化を目的とした補助とする。** チャンク番号の変動で「対象 0 件」になっても静かに通過する性質があるため、`path` glob が 1 件以上マッチすることを確認する仕組み（`npx size-limit --json` の出力でサイズ 0 / 対象なしを検出する等）を併せて用意する。
- **FR-306-04**: `.size-limit.json` に **/dashboard と /ranking のルート固有チャンクの予算エントリを追加**する（現在は予算なし）。閾値は他ルートと同じ流儀（実測＋ヘッドルーム）で置く。
- **FR-306-05**: `.lighthouserc.json` に **モバイル preset の第 2 実行を追加**する（`ci.collect` を desktop / mobile の 2 構成にする、または LHCI を 2 回起動して別 config を当てる）。**モバイル側の `total-blocking-time` は最低限 error 化**する（REQ-180 の趣旨に従い `categories:performance` 全体は warn のままでよい。TBT は JS 実行量の直接的な指標で、共有 runner のノイズを受けつつも「+49 kB 規模の常駐 SDK 追加」のような変化は検知できる）。閾値はモバイル実測を取ってから決め、初回は実測＋ヘッドルームで置く。
- **FR-306-06**: `.lighthouserc.json` の計測 URL（`:7`）に **`/lp`（広告着地）と `/dashboard`（最重量ルート）を追加**する。`numberOfRuns: 3` を維持したまま実行時間が許容範囲かを確認し、超える場合はモバイル実行の URL を `/` と `/lp` に絞る。
- **FR-306-07**: FR-306-01 / FR-306-03 / FR-306-04 / FR-306-05 を CI ワークフローに接続し、**PR で必ず走って失敗が PR をブロックする**状態にする（既存の size-limit ジョブに追加するか、新ジョブを立てる）。
- **FR-306-08**: **REQ-305 の実施後に全ルートを再計測し、FR-306-02 / FR-306-04 の閾値を締め直す**（削減した分がそのまま次の余裕にならないようにする）。閾値変更は必ず実測値をコメントで残す（`.size-limit.json` の既存エントリが REQ 番号と実測値をコメントに書いている流儀に合わせる）。
