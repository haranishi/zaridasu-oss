## 受入基準

- **AC-01**: `npm run size:routes`（FR-306-01）が全 7 ルートで実行され、各ルートの First Load JS 合計と閾値が出力される。**/ (home) の監視カバー率が 2.8%（9.3 / 332.2 kB）から 95% 以上へ改善**していること（＝共有チャンクを含む合算が見えている）。
- **AC-02**: **退行検知の実証**。REQ-305 で削った Sentry 相当（49.0 kB gzip）を一時的に戻した状態、または任意の共有チャンクへ 30 kB 規模の依存を追加した状態で、**CI が error で落ちる**ことを実際に確認する（現状は全項目パスして通過してしまう）。確認手順と結果を PR に残す。
- **AC-03**: `npx size-limit` の出力に **/dashboard と /ranking のエントリが列挙される**（現状は存在しない）。全エントリの `path` が 1 件以上のファイルにマッチしていること（対象 0 件のエントリが無いこと）を検証できる。
- **AC-04**: LHCI が **desktop / mobile の 2 preset** で実行され、レポートが両方アップロードされる。**モバイル側の `total-blocking-time` が error アサーション**になっており、意図的に閾値超過させると CI が落ちる。
- **AC-05**: LHCI の計測 URL に `/lp` と `/dashboard` が含まれ、`numberOfRuns: 3` のまま CI の実行時間が許容範囲（既存ジョブの所要時間から大幅に悪化しない）。
- **AC-06**: 追加した予算・閾値のすべてに、**根拠となる実測値と日付（2026-07-30 / develop 89495e9）がコメントで残っている**。
- **AC-07**: `npm run size` がパスする（現行実測 home 9.32/10、/post/[id] 14.04/18、framework 54.39/60、crayfish3d 233.9/250 kB を維持しつつ、追加した共有チャンク／ルート合算の予算もパスする）。
- **AC-08**: `lint` / `type-check` / 既存 **652 テスト**がパスする。新設スクリプトが CI 以外（ローカル `npm run build` 後）でも同じ結果を返す。

## 対象外

- 実際のバンドル削減（**REQ-305**）。本REQは枠を作るところまで。
- `categories:performance` の error 化（REQ-180 の判断を覆さない。共有 runner のノイズが解決していないため）。
- `unused-javascript` / `unused-css-rules` / `uses-long-cache-ttl` の再有効化（REQ-180 / REQ-267 で off にした判断を維持する。本REQで代替となる決定論的なゲート＝バイト数の直接計測を入れるため、これらを戻す必要はない）。
- 本番 RUM（Web Vitals → GA4）側のダッシュボード整備。計測自体は生きている（`providers.tsx:111` / `trackEvent('web_vital')`）ため、CI ゲートとは別課題として扱う。
