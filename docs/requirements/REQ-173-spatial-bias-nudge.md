# REQ-173: 空間バイアス補正のための優先調査エリア・ナッジ

## 背景
市民科学（オポチュニスティック観測）データには、観測者がアクセスしやすい場所へ報告が集中する「空間サンプリングバイアス」が普遍的に存在する。eBird・iNaturalist の大規模解析では、道路沿い・都市部・人口集中地への観測偏在が一貫して報告されており、農村圏・低アクセス地域が構造的に過少代表（under-sampling）になる。秋田県の外来生物分布把握を目的とする本アプリでも、農村圏の過少観測は分布推定の精度を直接損なう深刻な課題である。

この課題に対する有効な介入として、Callaghan, Bowler et al. (2023) の FrogID（オーストラリアの市民科学カエル音声記録プロジェクト）における1年間のランダム化比較試験（RCT）が挙げられる。同研究では、観測密度の低い「高優先度セル」をユーザーへ提示する行動ナッジを与えた介入群で、対象セルへの訪問率が 58〜73%（対照群は 15〜32%）に達し、ナッジが空間バイアスの改善に大きな効果を持つことが示された。さらに同研究は、競争的フレーミングよりも「ここの情報が不足しており、あなたの観察が分布把握に役立つ」という内発的動機に整合したフレーミングが望ましいことを設計上の注意点として挙げている（Notion 先行研究レビュー RQ1 サブテーマ2「空間バイアスと行動ナッジ」および「設計上の注意点」より）。

本アプリは現在、機会記録（opportunistic）の投稿を受け付けるのみで、過少観測エリアへユーザーを誘導する仕組みを持たない。本要件は、観測密度の低いエリアを算出・可視化し、内発的動機整合フレーミングでの優先調査エリア提示（ナッジ）を導入することで、空間バイアスを軽減する。

## 現状の問題
- `src/components/features/map/MapView.tsx:286-338`: 地図は投稿のヒートマップ（`HeatmapLayer`）と種別マーカークラスタ（`MarkerClusterGroup`）、および調査依頼マーカー（`surveyRequests`）を表示するのみ。「観測が少ない＝情報が不足しているエリア」を可視化するレイヤーが存在しない（密度の高い場所だけが強調され、過少観測エリアはむしろ目立たない）。
- `src/app/(home)/HomeInteractive.tsx:168-232`: ホーム画面に「今週優先したいエリア」を提示する UI が無く、ユーザーは自分の観察がどこで分布把握に役立つかを知る手段がない。
- `src/hooks/useStats.ts:172-177`: 市区町村ランキング（`municipalityRank`）は「件数が多い順」のみを算出しており、過少観測エリア（低密度セル/市区町村）を特定する集計が存在しない。
- `src/components/features/admin/MunicipalityRanking.tsx:26-47`: 件数の多い上位市区町村のみを表示し、報告がゼロ・少数の市区町村は一覧にすら現れない（過少代表が不可視化されている）。
- `src/types/database.types.ts:139-192` / `supabase/schema.sql`: 投稿の位置情報（`posts.lat` / `posts.lng` / `posts.municipality`）は存在するが、グリッドセル単位の観測密度や「優先度」を算出する RPC（`get_municipality_post_counts` のような集計関数）が無い。
- `src/lib/constants.ts:113-138`: 全25市区町村の中心座標（`MUNICIPALITY_DATA`）は定義済みで優先エリア提示に流用できるが、現状どこからも密度補正の用途では参照されていない。

## 目的
観測密度の低いグリッドセル／市区町村を Supabase 側の集計で算出し、地図上に「情報が不足しているエリア」として可視化し、ホーム・地図上に「今週優先したいエリア」を内発的動機整合フレーミングで提示する。これにより機会記録の空間的偏在を緩和し、過少観測エリアへの観察を促す。プライバシー（私有地・個人住所の特定）に配慮した粒度で提示する。

## 要件

### 機能要件
- [ ] FR-173-01: 観測密度を算出する Supabase RPC（例: `get_spatial_priority_cells`）を追加する。秋田県の範囲を一定サイズのグリッドセル（例: 約 0.05°≒5km 格子）に分割し、`status = 'approved'` の投稿件数をセル単位で集計して密度と優先度スコアを返す。既存 `get_municipality_post_counts`（`supabase/migrations/20260513000010_*.sql`）と同様に `SECURITY INVOKER` / `STABLE` で実装し、RLS を尊重する。
- [ ] FR-173-02: 優先度スコアは「密度が低いほど高い」ロジックとする（例: セル件数が県内中央値・閾値を下回るセルを高優先度とし、件数ゼロのセルも候補に含める）。算出ロジックはアプリ側ではなく RPC／集計クエリ側に置く。
- [ ] FR-173-03: 市区町村単位の過少観測ランキング（例: `get_undersampled_municipalities`）を返せるようにする。`MUNICIPALITY_DATA`（全25市区町村）を母集合とし、件数の少ない順（ゼロ件を含む）に市区町村と件数を返す。
- [ ] FR-173-04: `MapView.tsx` に「低密度セルの淡色オーバーレイ」レイヤーを追加する。高優先度セルを地図上に淡い色（例: 半透明の塗り）で重畳し、「ここの情報が不足している」ことを視覚的に示す。既存のヒートマップ／クラスタ表示と排他または併存で切り替え可能とする（`MapSettingsContext` 経由のトグルを想定）。
- [ ] FR-173-05: ホーム（`HomeInteractive.tsx`）に「今週優先したいエリア」セクション／カードを追加し、FR-173-03 の過少観測市区町村を上位数件提示する。各エリアは `/area/[municipality]` または地図の該当エリアへ誘導する。
- [ ] FR-173-06: ナッジの文言は内発的動機整合フレーミングとする。競争・ランキング・順位煽りの表現を用いず、「このエリアの情報が不足しています。あなたの観察が分布把握に役立ちます」系の協力要請フレーミングで提示する（i18n キーとして追加）。
- [ ] FR-173-07: プライバシー配慮として、提示・可視化の最小粒度をグリッドセル／市区町村レベルに留め、特定の私有地・住所・個人宅をピンポイントに指し示す表現や座標を提示しない。
- [ ] FR-173-08: 優先エリアレイヤー／カードを表示する際、対象データが無い（全セルが十分にサンプリング済み、または投稿ゼロ）場合のフォールバック表示を用意する。

### 非機能要件
- [ ] NFR-173-01: 優先度算出は Supabase RPC／集計クエリで行い、全投稿の生データをクライアントへ転送してアプリ側で密度計算しない（`useStats` の RPC 集約方針と整合）。
- [ ] NFR-173-02: 優先エリアの集計結果はクライアントでキャッシュ（`useStats` と同様の sessionStorage TTL、例: 5分）し、地図操作のたびに RPC を再実行しない。
- [ ] NFR-173-03: グリッド集計クエリは対象範囲を絞る部分インデックス等（`idx_posts_approved_municipality` と同方針）で最適化し、投稿増加に対してスケールする。
- [ ] NFR-173-04: 淡色オーバーレイレイヤーは既存マーカー描画のパフォーマンス（ビューポート内描画・LRU アイコンキャッシュ）を阻害せず、レイヤー OFF 時はレンダリングコストを発生させない。
- [ ] NFR-173-05: 追加 UI・レイヤートグル・ナッジ文言は既存のダークモード・i18n・アクセシビリティ方針（`aria-*` 付与）に準拠する。

## 受入条件
- [ ] AC-01: 新規 RPC を呼ぶと、秋田県のグリッドセルごとの投稿件数と優先度スコアが返り、件数の少ないセルほど優先度スコアが高い。
- [ ] AC-02: 投稿が1件も無い（または閾値未満の）市区町村が、過少観測ランキング RPC の結果に含まれる（件数ゼロでも欠落しない）。
- [ ] AC-03: 地図で優先エリアレイヤーを ON にすると、高優先度（低密度）セルが淡色オーバーレイで表示され、OFF にすると消える。
- [ ] AC-04: ホームに「今週優先したいエリア」が表示され、各エリアをタップすると該当エリアの画面／地図位置へ遷移する。
- [ ] AC-05: 提示文言に競争・順位煽りの表現が無く、「情報が不足／あなたの観察が役立つ」系の協力要請フレーミングになっている（i18n キーで検証可能）。
- [ ] AC-06: 提示・可視化が市区町村／グリッドセル粒度に留まり、私有地・住所・個人宅をピンポイントに示す座標やラベルが出力されない。
- [ ] AC-07: 優先エリアの集計結果が sessionStorage にキャッシュされ、TTL 内の再表示で RPC が再実行されない。
- [ ] AC-08: 対象データが無い場合に、エラーではなくフォールバック表示（例: 「現在優先エリアはありません」）が出る。

## 優先度
- **緊急度**: Medium
- **重要度**: High
- **理由**: 空間バイアスの軽減は本アプリの目的（秋田県の外来生物分布の正確な把握）の中核に関わる。Callaghan et al. 2023 の RCT で効果が実証された介入であり、研究上の新規性・貢献も大きい。一方で既存の投稿・地図機能が損なわれているわけではないため緊急度は Medium とする。
