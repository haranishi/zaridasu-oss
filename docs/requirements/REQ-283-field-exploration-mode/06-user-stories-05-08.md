### US-283-05: 審査待ちでも達成感を得る

**As a** 初回参加者,  
**I want to** 送信直後に発見演出と次の見通しを得たい,  
**So that** 審査結果が出る前に離脱せず、再訪理由を理解できる.

**受け入れ条件:**

- [ ] AC-1: 送信直後に「仮発見」カードを表示する。
- [ ] AC-2: 仮報酬は「審査中」と明記し、正式XP・ランキングへ加算しない。
- [ ] AC-3: 審査結果の通知設定を提示する。
- [ ] AC-4: 却下・追加写真依頼時は理由と修正方法を表示する。

**優先度:** 高  
**見積もり:** M

### US-283-06: 自分の調査で地域が変わる

**As a** 継続参加者,  
**I want to** 承認された記録が地域地図や図鑑へ反映される様子を見たい,  
**So that** 自分の貢献の意味と次の目標を感じられる.

**受け入れ条件:**

- [ ] AC-1: 承認後、対象セルの状態と最終確認日が更新される。
- [ ] AC-2: XP、図鑑、クエスト、地域探索率が同じ承認イベントから冪等に更新される。
- [ ] AC-3: 「未調査セルを初めて埋めた」等の貢献理由を表示する。
- [ ] AC-4: 生座標ではなくセル名・市町村・安全な公開表現だけを履歴へ残す。

**優先度:** 高  
**見積もり:** L

### US-283-07: 管理者が安全性と研究価値を制御する

**As an** 管理者・研究運用者,  
**I want to** 公開セル、ミッション、安全状態、再調査期限、報酬を管理したい,  
**So that** 危険誘導を防ぎ、必要な地点に調査を配分できる.

**受け入れ条件:**

- [ ] AC-1: 管理者だけが公開ミッションを作成・公開・停止できる。
- [ ] AC-2: すべての変更を `audit_logs` に記録する。
- [ ] AC-3: 投稿の正確座標を公開セルへ変換する処理はDB側の権威処理とする。
- [ ] AC-4: 重複、却下、不正、危険報告の比率をセル単位で確認できる。

**優先度:** 高  
**見積もり:** L

### US-283-08: 通信圏外でも観察を失わず提出する

**As a** 山間部・水辺で調査する参加者,  
**I want to** 回線がない状態でも写真と観察情報の送信操作を完了したい,  
**So that** 帰宅後に入力し直さず、通信が戻ったとき同じ記録を安全に提出できる.

**受け入れ条件:**

- [ ] AC-1: ミッション開始時に安全情報、必要写真枠、セル情報、入力選択肢をオフラインフィールドパックとして保存する。
- [ ] AC-2: 圏外で「送信」を押すと、観察情報・処理済み写真・位置精度・観察時刻・ミッション参照が1件のOutbox項目として原子的に保存される。
- [ ] AC-3: 保存完了後は「端末保存済み・未送信」と表示し、「サーバー送信済み」「審査中」と誤認させない。
- [ ] AC-4: 通信復帰、アプリ起動、前景復帰、手動操作のいずれかで再送し、対応ブラウザではBackground Syncも補助的に使う。
- [ ] AC-5: 再送、アプリ強制終了、タイムアウト、途中までの写真アップロードが起きても、同じ `client_submission_id` から投稿を二重作成しない。
- [ ] AC-6: 401は `needs_auth`、入力不整合は `needs_edit`、一時障害は `retry_wait` として保持し、ユーザー操作なしに記録を削除しない。
- [ ] AC-7: サーバーが同一IDの受付完了と `postId` を返した後にだけ端末内の写真・正確位置を削除する。
- [ ] AC-8: ブラウザデータ消去等による消失可能性、送信待ち件数、最終試行時刻、モバイル通信利用方針を確認できる。

**優先度:** 高  
**見積もり:** L
