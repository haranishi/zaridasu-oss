### 1.3 スコープ

#### MVP（本要件の必須範囲）

- 既存ホーム地図への「見る / 探索」モード追加
- 探索セルと侵入シグナルの公開表示
- 管理者が安全確認したフィールドミッション
- ミッション詳細・安全確認・開始
- 現地到着判定と探索セッション
- 全身・特徴・水辺をガイドする3枠スキャン
- 通常投稿データへの接続
- 仮発見と審査待ち状態
- 承認後のセル更新、XP、図鑑、クエスト、地域進捗連動
- 不在確認の努力量記録
- ミッション開始時のオフラインフィールドパック保存
- 写真・位置・調査情報を保持するOffline Outbox
- 通信復帰・アプリ再開・手動操作による再送と、対応端末でのBackground Sync
- 送信待ち／送信中／要ログイン／要修正／送信済みの状態表示
- 管理者向けセル／ミッション管理
- GA4イベントと既存実験基盤への接続

#### Phase 2候補

- 事前審査済み水辺パトロールルート
- 時間限定の一斉調査（BioBlitz）
- 学校・自治体単位の協力チーム
- 専門家／上級者向け同定協力ミニタスク
- カメラ上の簡易3D遭遇演出
- 天候・季節・再調査周期を考慮した推薦

#### 対象外

- 生物の捕獲、殺処分、運搬数を競うゲーム
- 正確な生座標を一般公開するリアルタイム通知
- 私有地・学校・保育施設・危険な護岸への誘導
- ユーザーが無審査で公開ミッション／ルートを作成する機能
- バックグラウンドでの常時位置追跡
- 衛星通信、SMS、Bluetoothメッシュ等を使った圏外からの直接送信
- ブラウザやOSを終了した状態でも、すべての端末で即時自動送信されるという保証
- 第三者地図タイルの無制限な一括ダウンロード
- ガチャ、課金アイテム、取引、PvP、捕獲数ランキング
- MVPでの高度なAR・空間認識
- 一般ユーザーによる実物個体の飼育を促す相棒機能

### 1.4 前提条件・制約

- 現行技術スタック（Next.js 15 App Router、React 19、TypeScript、Tailwind CSS 4、Leaflet、Supabase、Gemini、PWA）を維持する。
- 新機能は `field_exploration_v1` 実験フラグで段階公開し、取得失敗時は従来画面へ安全にフォールバックする。
- 通常投稿、調査依頼、定点観察、公開データセットの既存仕様を壊さない。
- 中核の投稿機能はレベルでロックしない。探索モード未利用でも従来どおり投稿できる。
- XP・図鑑登録・セル正式開放は、DB上で投稿が `approved` へ遷移した後にのみ確定する。
- 位置情報はREQ-243の `precise / coarsened / hidden` を継承する。
- 公開マップは観察地点ではなく、粗化した探索セルまたは管理者が定めた安全な集合地点を表示する。
- 通常利用者に捕獲・運搬を促さない。初回ミッション前に安全・法律ガイドを表示する。
- IndexedDB、Cache Storage、Service Workerを既存PWAの範囲で利用し、オフライン機能だけを理由にUnity／ネイティブアプリへ移行しない。
- Background Synchronization APIは非対応ブラウザがあるため補助経路とし、アプリ起動時・前景復帰時・通信復帰時・手動再送を必須経路とする。
- `navigator.onLine` は表示上のヒントにのみ使い、実際のAPI到達結果とサーバー確認応答を同期成功の根拠とする。
- ブラウザのサイトデータ消去、アプリ削除、端末故障まで含む永続保証はできない。端末保存の限界をユーザーへ明示し、可能な場合は永続ストレージを要求する。
