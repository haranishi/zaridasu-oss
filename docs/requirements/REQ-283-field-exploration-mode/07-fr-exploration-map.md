## 4. 機能要件

### 4.1 探索マップ

#### FR-283-01: 見る／探索モード

- **入力:** ホーム上部のセグメント切替、実験variant、URLクエリ `?mode=explore`
- **処理:** 現行の投稿閲覧レイヤーと探索レイヤーを同一Leaflet画面上で切り替える。
- **出力:** 探索モードではセル、ミッション、地域進捗、近隣カードを表示する。
- **バリデーション:** 不正なmodeは `view` へフォールバックする。
- **エラー:** 探索API失敗時も現行マップと通常投稿は利用可能にする。

#### FR-283-02: 探索セル状態

公開セルは最低限、次の状態を持つ。

| 状態 | 意味 | 公開表現 |
|---|---|---|
| `unexplored` | 有効な調査が不足 | 霧＋「未調査」 |
| `recent_verified` | 所定期間内の承認記録あり | 赤い波紋＋最終確認日 |
| `historical_verified` | 過去の承認記録あり | オレンジ枠＋「過去確認」 |
| `absence_surveyed` | プロトコル付き不在確認あり | 青い斜線＋調査条件 |
| `revisit_due` | 再調査期限を超過 | 紫の時計＋「再調査」 |
| `restricted` | 危険／私有地／機微 | 非表示または鍵表示 |

- 状態は色だけでなく、形、アイコン、テキストを併用する。
- `recent` の日数、再調査周期、確度閾値は管理設定可能にする。
- `absence_surveyed` は存在しないことの証明として扱わない。

#### FR-283-03: 公開位置の二層構造

- 一般公開: 粗化セル中心、セル境界、管理者設定の安全な集合地点
- 所有者・管理者: 投稿の正確座標（REQ-243準拠）
- 研究利用: 正式合意と権限の範囲内
- `hidden` の記録はセル集計にも個体特定可能な形で表示しない。
- セル集計で件数が少ない場合、必要に応じて最小集計数ルールを適用する。

#### FR-283-04: 近隣ミッション推薦

推薦スコアは次を優先する。

1. 未調査または再調査期限超過
2. 安全確認済み・公開アクセス可能
3. 現在地から近い
4. 対象期間・日中・天候条件を満たす
5. 同一ユーザーの直近重複でない
6. データが集中している既知ホットスポットより、被覆不足セル

生物がいる確率のみで推薦を最適化しない。
