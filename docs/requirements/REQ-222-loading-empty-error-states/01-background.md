## 背景

ザリダス（秋田県の外来生物の市民科学情報マップ／卒業研究 PF）の主要画面は、ほぼすべてが Supabase からのデータ取得を伴う「データ取得画面」である（ホーム地図・写真ギャラリー・みんなの記録〔ランキング/多様性〕・トレンド・プロフィール・調査依頼一覧/詳細・地域ページ・マイページ）。Obsidian デザイン基礎ノートでは、こうしたデータ取得画面には **Loading(スケルトン) / Empty / Error の 3 状態を必ず作る**ことを基本としている：

- `02_notes/デザイン基礎/UI_コンポーネントとパターン.md`: データ取得画面は Loading（できれば**スケルトン**）・Empty・Error の 3 状態を必ず設計する。スピナーよりスケルトンの方が「これから何が出るか」を予告でき体感待ち時間が短い。
- `02_notes/デザイン基礎/マイクロインタラクションとモーション.md`: 空状態は「**説明 2 : 楽しさ 1**」のバランスで、**肯定形コピー＋単一の CTA** によりオンボーディングの好機に変える。スケルトンは**実コンテンツと同じ骨格**にして体感待ち時間短縮と **CLS（レイアウトシフト）防止**を両立する。
- `02_notes/デザイン基礎/アクセシビリティとUXライティング.md`: エラーは「**何が起きたか＋どう直すか＋リトライ**」をセットで提示し、`role="alert"` / `aria-live` で支援技術へ通知する。読み込み中の領域は `role="status"` / `aria-busy` で読み上げる。

ザリダスは卒研の市民科学 PF であり、先行研究レビュー（research-rq1：市民科学のエンゲージメント／継続）に基づき「投稿のしやすさ・初回貢献への誘導」を重視している。特に**まだ投稿が無いユーザー・データが無い画面**は、現状「まだ〇〇がありません」という行き止まりの否定表現になっており、**初回投稿（オンボーディング）への最大の機会を逃している**。本 REQ は、3 状態を**統一コンポーネント／パターンとして体系化**し、とりわけ **Empty state を「肯定形コピー＋単一の投稿 CTA」のオンボーディングに変える**ことに集中する。

### 既存 REQ との関係（重複回避は「影響範囲」で詳述）

- **REQ-192**（フェッチ失敗と空状態の分離, `docs/requirements/REQ-192-fetch-error-empty-state-separation.md`）: 「取得失敗（Error）」を「データ無し（Empty）」から**切り離し**、フック戻り値に `error` を足して再試行導線を付ける、という **state の分離と再フェッチ配線**を担う。本 REQ-222 はそれを前提に、分離後の 3 状態を**見た目・コピー・コンポーネントとして統一**し、Empty を**オンボーディング化**する側を担う（state の正しさ＝REQ-192、表現の統一＋空状態の質的転換＝REQ-222）。
- **REQ-201**（地図区画専用のエラーバウンダリ, `docs/requirements/REQ-201-map-error-boundary.md`）: 地図チャンクの**描画例外/チャンク失敗を地図枠に閉じ込める**エラーバウンダリと、`ErrorBoundary` フォールバックの i18n を担う。本 REQ-222 は**フェッチ層の 3 状態**（取得中/空/取得失敗のインライン表現）であり、**例外バウンダリ層とは別レイヤー**。地図フェッチの Empty/Loading 表現は本 REQ、地図の throw 捕捉は REQ-201 が担う。
- **REQ-193 / REQ-195**（操作失敗のトースト通知 / ErrorAlert のライブリージョン）: 「ユーザー操作（いいね・保存等）の結果通知」と「メッセージ要素の `role`/`aria-live`」を担う。本 REQ は**取得（ページ/一覧の表示）の 3 状態**が対象で、操作系トーストは扱わない（Error 表示で `ErrorAlert` を再利用する点のみ接続）。
- **REQ-198**（ソフト 404 を真の 404 に）: 「**存在しない ID**」は 404（notFound）へ寄せる別 REQ。本 REQ の Empty は「**取得は成功したが 0 件**」のみを指し、404 相当（その投稿/依頼が存在しない）は Empty として扱わない。
