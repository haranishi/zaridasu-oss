# REQ-063: モバイルヘッダー簡素化

## 背景
Biome アプリのモバイルヘッダーは「ハンバーガー + ページタイトル」という最小構成に統一されており、地図コンテンツにファーストビューを最大限割り当てている。一方、本アプリの `src/components/layout/Header.tsx` は PC とモバイルで同じ高さ（`h-12`）のバーに多数の要素をレイアウトしており、モバイル幅では左右のアクションに目が行って肝心のコンテンツに集中できない。

現状の PC 側（`src/components/layout/Header.tsx:150-351`）では、以下 9 種の要素がヘッダーに同居している。
- ロゴ（`:150-156`）
- ページタイトル相当のサブタイトル（`:153-155`）
- 4 タブのグローバルナビ（`:159-168`）
- 言語切替メニュー（`:174-210`）
- テーマ切替（`:213-223`）
- ログイン／新規登録ボタン（`:226-244`）
- 調査依頼ボタン（`:248-257`）
- 投稿ボタン（`:260-266`）
- ユーザーメニュー（`:269-349`）

モバイル側（`:119-147`）では一応「ハンバーガー + ページタイトル + テーマ切替」の 3 要素に抑えてはいるものの、右側のテーマ切替がコンテンツ領域を圧迫しており、Biome 風の「☰ + タイトル」2 要素構成に揃えたい。

## ユーザーストーリー
As a スマホで地図を見に来たユーザー,
I want to 画面上部のクロムを最小限にして、地図・一覧・投稿サマリーに集中したい,
So that 小さい画面でも情報密度を最大化でき、ワンハンド操作で迷わず目的の機能にたどり着ける。

## 現状の問題
- `src/components/layout/Header.tsx:132-134` — モバイル中央のページタイトル。ここは残すが、左右に並ぶボタンが増減すると中央揃えがブレる。
- `src/components/layout/Header.tsx:137-147` — モバイルでテーマ切替ボタンがヘッダー右に常駐しており、タップターゲット（40px 程度）が左右対称ではなく視覚的ノイズになっている。
- `src/components/layout/Header.tsx:19-27` — `PAGE_TITLES` が `/ranking` `/trends` 等 7 ルート分しか定義されておらず、動的ルート（投稿詳細など）では常に「ザリダス」に fallback する。
- `src/components/layout/Header.tsx:117` — `h-12`（48px）は Biome のモバイルヘッダー（およそ 56px）より低く、ステータスバーとの境界が視覚的にキツい。

## 要件

### 機能要件
- [ ] FR-063-01: モバイル幅（`md:hidden`、Tailwind 768px 未満）ではヘッダー要素を「左: ハンバーガーボタン」「中央: ページタイトル」の 2 要素のみとする。
- [ ] FR-063-02: モバイルヘッダーからテーマ切替ボタン・ロゴ・言語切替・ユーザーメニュー等は撤去し、`DrawerMenu` 側に集約する（REQ-066 と連動）。
- [ ] FR-063-03: ページタイトルは `usePathname()` で解決し、`PAGE_TITLES` の静的マップに加え、`/post/[id]` や `/species/[slug]` 等の動的ルートでも `document.title` または個別 prop からタイトルを取得できるフォールバック経路を追加する。
- [ ] FR-063-04: ハンバーガーボタンは既存の `drawerOpen` ステートを維持し、`aria-expanded` と `aria-label` の現行実装（`Header.tsx:125-126`）は壊さない。
- [ ] FR-063-05: 投稿ボタン・ログイン／新規登録ボタン・調査依頼ボタンのアクセスは、`BottomNav` とドロワーの二重導線に移譲する。モバイル Header からは完全に削除する。
- [ ] FR-063-06: PC（`md:flex`）表示は現行維持し、今回の変更で影響を与えない。

### 非機能要件
- [ ] NFR-063-01: ハンバーガーと（あれば）タイトル横のサブアクションのタップターゲットは最小 44×44 px（`p-2` + アイコン 20px 以上で担保）。
- [ ] NFR-063-02: ドロワー開閉・フォーカスリング・背景ブラーのアニメーションは 250ms 以内。`prefers-reduced-motion: reduce` 下では `transition-none` にフォールバックさせる。
- [ ] NFR-063-03: dark variant 対応（`dark ? 'bg-slate-950/95' : 'bg-white/95'` 等、既存の `useTheme()` 経路を踏襲）。
- [ ] NFR-063-04: iOS `env(safe-area-inset-top)` を現状どおり `paddingTop` に適用（`Header.tsx:115`）。
- [ ] NFR-063-05: Lighthouse モバイル CLS（Cumulative Layout Shift）に影響を与えない。タイトル文字数が変わっても高さは固定 56px を維持。

## デザイン仕様

### レイアウト
| 項目 | サイズ |
| --- | --- |
| ヘッダー高さ | 56px（`h-14`）※現行 48px から引き上げ |
| 左右パディング | 16px（`px-4`） |
| ハンバーガー hit area | 44×44 px（アイコン 22px + padding 11px） |
| タイトルフォント | 16px / `font-bold` / `tracking-tight` |
| タイトル最大幅 | `calc(100% - 88px)`（左右のボタン領域を差し引き） |
| 左右ボタン間の gap | 12px（`gap-3`） |

### 配色（既存パレット準拠）
- 背景: ライト `bg-white/95 backdrop-blur-md`、ダーク `bg-slate-950/95 backdrop-blur-md`
- 下ボーダー: ライト `border-gray-200`、ダーク `border-slate-800/80`
- アイコン（通常）: ライト `text-gray-500`、ダーク `text-slate-400`
- アイコン（ホバー背景）: ライト `hover:bg-gray-100`、ダーク `hover:bg-slate-800`
- タイトル文字: ライト `text-gray-800`、ダーク `text-slate-100`

### 状態
- default: 通常表示。ボタンはアウトライン無し。
- active（ドロワー開）: ハンバーガーアイコンを `X` に差し替え（既存 `drawerOpen ? 'menuClose' : 'menuOpen'` ラベル切替を踏襲）。
- focus-visible: `ring-2 ring-red-400 ring-offset-2`（アクセシビリティのため追加推奨）。
- disabled: モバイルヘッダーに disabled ボタンは設けない。

## 受入条件
- [ ] AC-063-01: 375×812（iPhone 12 相当）で閲覧時、ヘッダー内の可視要素がハンバーガーとタイトルの 2 つのみであること（DevTools で検証）。
- [ ] AC-063-02: 言語・テーマ・投稿・ログイン・ユーザーメニューへのアクセスが、ハンバーガー → ドロワー経由、または `BottomNav` 経由で 100% 可能であること。
- [ ] AC-063-03: `/` `/trends` `/ranking` `/dashboard` `/about` `/terms` `/privacy` の各ルートでタイトルが正しく切り替わる。
- [ ] AC-063-04: 動的ルート（例: `/species/crayfish-red`）でもフォールバックで意味のあるタイトルが表示される（最低でもルートセグメントを人間可読化、もしくは各ページから props 経由で上書き）。
- [ ] AC-063-05: `md:` ブレイクポイント以上では既存のヘッダーレイアウトが変わっていない（スクリーンショット回帰テスト）。
- [ ] AC-063-06: Axe で WCAG 2.1 AA 違反 0 件（特にランドマーク `<header>`、`aria-label`、コントラスト）。

## 影響範囲
- 変更: `src/components/layout/Header.tsx`（モバイルブロック `:119-147` の整理、`PAGE_TITLES` の拡張）
- 変更: `src/components/layout/DrawerMenu.tsx`（テーマ切替・言語切替は既存あり、ユーザーエリアは REQ-066 で再設計）
- 追加（任意）: `src/lib/pageTitle.ts`（ルート → タイトル解決ユーティリティ）
- 影響なし: `src/components/layout/BottomNav.tsx`、PC ビューのレイアウト

## 優先度
- **緊急度**: High
- **重要度**: High
- **理由**: モバイル UX の第一印象を決めるヘッダー領域で情報密度が高すぎ、地図・投稿体験を直接阻害している。ドロワーへの機能集約は後続 REQ-066 の前提条件でもあり、先行実装する必要がある。
