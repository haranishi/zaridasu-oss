# REQ-330 §1 戦略・ユーザーストーリー・UX5階層

## 戦略：調査する人の手間を減らし、研究に使える「調べた記録」を増やす

調査する人の目的は、決めた場所を迷わず回り、地点ごとの結果を漏れなく残すことだ。水辺では片手しか空かず、電波も弱い。長い入力はできない。

運営（研究）の目的は、「どこを・いつ・調べて・いた/いなかった」がそろった記録を増やすことにある。いまは足りない。9/28 時点で、研究に使える投稿（DUO）も不在の記録も0件だった。計画から生まれる記録なら、場所と時刻と調べ方が最初からそろう。

希少種の場所を守ることは、保全団体や高校と組むための前提でもあり、たとえば秋田市の新屋高校は、大森山動物園の塩曳潟でゼニタナゴなどの在来魚を守りながら、週1回わなを回収してアメリカザリガニとウシガエルを駆除している（調査 2026-10-01）。

他との違いは、計画→案内→記録が1つの画面でつながることと、希少種の記録が最初から公開経路の外に置かれることの2つだ。

成功の目安（3か月）：計画の作成数、地点の完了率、計画から生まれた投稿と不在の記録の件数、希少種の記録の件数、30日以内に2つ目の計画を作った人の割合。

## UX5階層

| 階層 | 決めたこと |
|---|---|
| 戦略 | 上の節のとおり。量より「そろった記録」を増やす |
| 要件 | 計画の作成・地点の追加/並べ替え/削除・案内（次へ・まとめて）・地点ごとの結果3種とスキップ・希少種の非公開記録（計画の外からも）・運営の一覧と CSV・圏外での閲覧と送信待ち |
| 構造 | 入口は地図の「調査」ボタン1つ。押すと調査パネル（今日の計画・進み具合・地点の一覧・案内）。地点を押すと地点シート（案内・結果3種・スキップ）。希少種は専用シート。ピンと非公開スポットの吹き出しに「計画に入れる」「希少種を記録」 |
| 骨格 | スマホは画面の下半分のシート、PCは右のパネル。地図は残し、地点の位置関係を見ながら操作できる。並べ替えはドラッグでなく↑↓ボタン。結果の3ボタンは大きく、色だけでなく文字と記号で区別する |
| 表層 | 計画の地点は番号つきの丸（済みはチェック、飛ばしは灰）。希少種と「非公開」は REQ-329 の非公開スポットと同じ紫と錠前の記号で統一し、「あなたと運営だけ」と毎回書く |

## 5階層を通して変わった設計（6件）

1. 戦略の「不在の記録を増やす」から、「いなかった」を投稿フォームの選択肢でなく地点シートの1ボタンにした。
2. 戦略の「希少種の場所を守る」から、希少種の記録がある地点で作る投稿は位置を hidden にする規則を足した。
3. 要件の「家で計画して現地で使う」から、計画を端末保存でなく DB に置くことにした。
4. 要件の「まとめて案内」から、Google マップの経由地の上限に合わせて4地点ずつに区切る形にした。
5. 構造の検討で、地図右下のボタンを増やさず「調査」1つに集約した（今もボタンの位置を高さの決め打ちで並べており、増やすほど崩れやすい）。
6. 骨格の「片手・水辺」から、並べ替えをドラッグでなく↑↓ボタンにし、結果のボタンを大きくした。
