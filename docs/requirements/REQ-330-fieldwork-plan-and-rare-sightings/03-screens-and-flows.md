# REQ-330 §3 画面と流れ：入口は地図の「調査」ボタン1つ、記録は地点シートで完結させる

## 入口と、地図右下のボタン

地図の右下に「調査」ボタンを1つ足す。REQ-329 のボタン（ピンを立てる・非公開で保存）と同じ列に並べる。

いまは各ボタンの位置を、ほかのボタンの高さを足した決め打ちで計算している（`MapView.tsx` の `calc(5rem + …)` と `PersonalMapLayer.tsx` の `calc(5rem + 3.75rem + …)`）。ボタンが増えるたびに崩れるので、MapView に右下ボタンの共通の入れ物を1つ置き、各レイヤーはそこへ自分のボタンを差し込む形に変える。

ログインしていない人が押したら、既存のログイン画面を開く。調査の機能はすべてログインが前提になる。

## 調査パネル（計画の管理）

押すと調査パネルが開く。スマホでは画面の下半分のシート、PCでは右側のパネルにして、地図は残す。中身は上から次の順に並べる。

1. 計画の切り替え：今日の計画（無ければ「今日の計画を作る」）と「これまでの計画」
2. 題名・予定日・進み具合（例「3 / 5 地点」）
3. 地点の一覧：番号・名前・状態（済み・飛ばし・未）・↑↓・メニュー（名前を変える・メモ・外す）
4. 地点を足す：「地図で選ぶ」（パネルを開いている間は、地図を押すと地点が増える）・「保存したスポットから選ぶ」（REQ-329 の非公開スポット）・「現在地を足す」
5. 案内：「次の地点へ」（Google・Yahoo!・Apple の既存の経路ボタン）と「Google マップでまとめて開く」
6. 計画の操作：「この計画を終える」「この計画をもう一度使う」（同じ地点で新しい計画を作る。定期的な再調査のため）

もう1つのタブに「希少種の記録」を置き、自分の記録の一覧と「計画なしで記録する」を出す。計画を作らずに希少種を見つけた人も、ここから記録できる。

計画の編集（地点の追加・並べ替え・削除）は電波のある場所でだけ行う。計画は家で作る想定で、圏外の編集まで面倒を見ると送信待ちの衝突処理が大きくなるためだ。

## まとめて開くときの区切り方

Google マップの経路 URL は、スマホのブラウザで開くと経由地が3か所まで、それ以外では9か所までで、URL は2,048字まで（公式の Maps URLs の説明）。どの端末でも同じ順に開けるよう、未完了の地点を4つずつ区切る。1区間目は出発地を書かずに現在地から始め、2区間目からは前の区間の最後の地点を出発地にする。移動手段は既存の経路ボタンと同じ車にする。URL には座標だけを載せ、地点名は載せない。Yahoo! マップの公開 URL には経由地の指定が無いので、「次の地点へ」だけで使う。

## 地点シート（現地での記録）

地点を押すと地点シートが開く。上に名前・メモ・案内、下に大きなボタンを4つ置く。

| ボタン | 動き |
|---|---|
| いた（投稿する） | 既存の投稿フォームを開く。調査方法は structured、位置は下の規則で決める。投稿できたら投稿と地点をつなぎ、地点を「済み」にする |
| いなかった | 種を選ぶ（アメリカザリガニ・ウシガエル。既定はアメリカザリガニだけ）。調査にかけた分数は任意。確定すると不在の投稿を種ごとに作り、地点とつないで「済み」にする。承認は既存のDB規則に従い、一般利用者の投稿は審査待ち、管理者の投稿は承認済みになる |
| 希少種を記録 | 希少種シートを開く。保存すると地点に「希少種あり」の印が付き、地点を「済み」にする |
| 飛ばす | 地点を「飛ばし」にする。理由は任意でメモに残す |

1つの地点に結果をいくつ付けてもよい。状態は「元に戻す」で未に戻せる（作った投稿や記録は消さない）。

**位置の規則**：記録するときに現在地を最大8秒取りにいく。誤差100m以内で、地点から300m以内なら現在地を使う（取り方は gps、誤差も保存）。そうでなければ地点の座標を使う（取り方は map）。どちらを使ったかを確定前に表示する。研究に使える投稿は誤差30m以内の現在地が要るので、現場にいるなら現在地を優先する。

**希少種のある地点の規則**：その地点に希少種の記録があると、地点から作る投稿（いた・いなかった）は位置を非公開（hidden）にする。投稿フォームでは非公開の選択を固定し、理由を1行で表示する。

## 安全の一言

人を水辺へ案内する機能なので、地点シートと「まとめて開く」の前に、短い注意を1行出す。「水に入らない・子どもだけで行かない・立入禁止の場所や私有地に入らない」。2025年の水の事故では、用水路で69人、湖・沼・池で46人が亡くなるか行方不明になった（警察庁「令和7年における水難の概況等」）。毎回出す1行は短く保ち、読み飛ばされても邪魔にならない大きさにする。

## 希少種シート

種は一覧のボタンから選び、「その他」を選んだときだけ名前の入力欄を出す。数・メモ・写真（3枚まで）・観察日時（既定は今）は任意で、位置は上の規則で決める。保存ボタンの上に「この記録は、あなたと運営だけが見られます。地図・一覧・公開データには出ません」と毎回書く。圏外では写真を選べないようにし、理由を表示する（写真なしで保存できる）。

## 地図に出すもの

- 計画の地点は、調査パネルを開いている間と、パネルを畳んで今日の計画を続けている間だけ、番号つきの丸で出す
- 希少種の記録は、パネルの「希少種を表示」を入れたときだけ出す（既定は出さない）。地図の画面写真を人に見せたり SNS に載せたりしたときに場所が漏れないようにするためだ
- どちらも本人の画面にだけ出し、地点の吹き出しから地点シートを開ける

## 運営の画面

管理画面に「希少種の記録」を足す（`AdminSpotsPage` と同じ形）。種・数・観察日時・座標・利用者の短縮 ID を一覧にし、写真は署名 URL で小さく出す。CSV は `lib/csv.ts` の `csvCell` を通す（式の差し込み対策）。画面の上に「取り扱い注意：外部に出さない」と表示する。

## 圏外のとき

- 計画は端末に控えを持つ（利用者ごとに別の保存先）。圏外では控えを表示し、「最後に同期した内容」と示す
- いなかった・飛ばす・元に戻す・写真なしの希少種の記録は、端末の送信待ちに入れて電波が戻ったら送る。希少種の記録は `client_id` で二重登録を DB が弾く
- 送信待ちは利用者 ID ごとに分け、別の人がログインしても送らない。アカウントが替わったら画面の状態を作り直す（REQ-316 の非公開スポットの修正と同じ考え方）
