# REQ-330 §4 受け入れ条件・置き場所・やらないこと

## 受け入れ条件

- **AC-01**: anon は新しい4表を読めない（`has_table_privilege` が偽、SELECT は 42501）。`rare-photos` の写真も読めない
- **AC-02**: 他人の計画・地点・つながり・希少種の記録は0行に見え、書き換えも削除もできない。管理者は全員分を読める
- **AC-03**: 希少種の記録が公開の経路（地図・一覧・詳細・公開データの CSV と GeoJSON・sitemap・地域ページ・集計 RPC）のどこにも出ない。anon が実行できる関数の本文に新しい表の名前が無いことを CI で検査する
- **AC-04**: 未完了が6地点の計画で「まとめて開く」を押すと、Google マップの URL が2本（4地点と2地点）できる。どちらも2,048字以内で、経由地は3か所以内、座標以外の文字を含まない
- **AC-05**: 地点で「いなかった」を確定すると、選んだ種ごとに不在の投稿（structured）ができ、地点とつながり、地点が「済み」になる。その地点に希少種の記録があれば、投稿の `location_disclosure` は hidden になる
- **AC-06**: 地点の「いた」から投稿すると、structured の投稿ができて地点とつながる
- **AC-07**: 圏外では計画の控えが見え、いなかった・飛ばす・写真なしの希少種の記録が送信待ちに入り、電波が戻ると1回だけ送られる。同じ `client_id` の再送で希少種の記録は増えない
- **AC-08**: アカウントを替えると、前の人の計画・希少種の記録・送信待ちが画面に出ない
- **AC-09**: 写真は EXIF を消してから `rare-photos` に入り、署名 URL で表示される。公開 URL は作らない
- **AC-10**: 希少種の記録は、パネルで「希少種を表示」を入れたときだけ地図に出る
- **AC-11**: `type-check`・`lint`・`test`・`i18n:check`（4言語）・`schema:check`・pg-tap・`size`・`size:routes`・e2e が通る。ホーム `/` のページ JS（上限10 kB）を増やさない。パネルとシートは押したときに読み込む
- **AC-12**: UI 採点ループ（Web 制作ハーネス）を、パネル・地点シート・希少種シートの 390 px と 1440 px で回す。🔴が無くなるまで、最大3周
- **AC-13**: 地点シートと「まとめて開く」の前に、安全の一言（水に入らない・子どもだけで行かない・立入禁止の場所や私有地に入らない）が出る

## 置き場所

新しいコードは `src/features/fieldwork/` にまとめる（REQ-331 の規約）。散らさない。中は data（DB と写真置き場の関数）・lib（区切り方・位置の規則・送信待ち・控え）・hooks・components・admin に分ける。`src/app/` に置くのは管理画面のルート（`admin/(protected)/rare-sightings/page.tsx`）の再 export だけで、翻訳キーは `fieldwork.*` にまとめる。

機能フォルダの README には、この機能の表・関数・pg-tap・地図への差し込み口を書く。後から辿るための案内板だ。docs/current には `fieldwork.md` を足し、`privacy.md` にも希少種の記録の守り方を足す。

## 本番への出し方

1. `supabase db push --linked --yes` で REQ-316 と本要件の migration を本番に当てる（develop → main のマージより先に）
2. develop → main をマージして本番に出す
3. 本番で確かめる：anon の鍵で `rare_sightings` を読むと拒否される。別アカウントから他人の写真を読めない。自分の記録は見える

## やらないこと（今回）

| 内容 | 理由 |
|---|---|
| 投稿の上限（24時間5件）の変更 | posts の挿入トリガーは影響範囲が広い。春の協働の前に別の要件で決める |
| 調査依頼の場所を計画に入れる | 調査依頼の吹き出しが MapView 本体（806行）にあり、差し込み口の整理（REQ-331 の段2）の後にする |
| 計画をチームで共有する | 招待と権限の設計が要る。自分用で使われ方を見てから決める |
| 希少種の記録を公開に切り替える機能 | 公開の判断は運営が個別に行う |
| 圏外での写真の保存・計画の編集 | 写真は容量が大きく、編集は衝突処理が大きい |
| 希少種の周りの既存の公開投稿を自動で非公開にする | posts のトリガー（9回書き直された最も込み入った関数群）に触る。独立したトリガーとして別に検討する |
| REQ-283 のゲーム要素（探索セル・ミッション・XP） | 小さい版の使われ方を見てから決める |
| 希少種の AI 判定 | 判定の正しさを検証する材料が無い |
