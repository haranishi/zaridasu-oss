# REQ-018: 管理者認証の強化（レート制限・MFA・パスワード要件）

## 背景
管理画面は投稿の承認・削除、ユーザー管理、ロール付与など高権限の操作を扱う。現状、管理者ログインにブルートフォース対策やMFAがなく、パスワード要件も最低6文字と弱い。攻撃者が無制限にログイン試行できる状態にある。

## 現状の問題
- `src/views/admin/AdminLoginPage.tsx:20`: `signInWithPassword` を直接呼び出し、試行回数の制限なし
- `src/components/modals/AuthModal.tsx:14`: パスワード最低長が6文字、複雑性要件なし
- `src/lib/supabase/middleware.ts:34-45`: 管理者判定は `app_metadata?.role === 'admin'` のJWTクレームのみ
- MFA/2FA が未実装
- セッションタイムアウトが未設定
- メールアドレス列挙攻撃が可能（`AUTH_ERROR_MAP` で `already registered` を区別して表示）

## 目的
管理者アカウントをブルートフォース攻撃・不正アクセスから保護し、一般ユーザーのパスワード強度も向上させる。

## 要件

### 機能要件
- [ ] FR-018-01: ログイン試行レート制限を実装する（IP単位で15分あたり5回まで。超過時は一定時間ロックアウト）
- [ ] FR-018-02: Supabase Auth の TOTP ファクターを利用し、管理者アカウントにMFAを必須化する
- [ ] FR-018-03: パスワード最低長を8文字以上に引き上げ、大小英字＋数字の組み合わせを要件とする
- [ ] FR-018-04: 新規登録時のエラーメッセージを統一し、メールアドレスの存在有無が判別できないようにする（例: 「入力内容を確認してください」）
- [ ] FR-018-05: 管理者セッションに非活動タイムアウト（30分）を実装する
- [ ] FR-018-06: 管理者ログイン成功・失敗を監査ログに記録する

### 非機能要件
- [ ] NFR-018-01: レート制限はサーバーサイド（middleware または Supabase Edge Function）で実装し、クライアント側のみの制限にしない
- [ ] NFR-018-02: MFA設定画面は管理者ダッシュボードに統合し、既存UIと一貫したデザインにする

## 受入条件
- [ ] AC-01: 同一IPから6回連続でログインに失敗すると、15分間ログインがブロックされる
- [ ] AC-02: MFA未設定の管理者がログインすると、MFA設定画面にリダイレクトされる
- [ ] AC-03: 5文字以下のパスワードで新規登録しようとするとバリデーションエラーが表示される
- [ ] AC-04: 登録済みメールアドレスで新規登録しても「このメールは既に登録済み」とは表示されない
- [ ] AC-05: 管理者が30分操作しないと自動ログアウトされる
- [ ] AC-06: 管理者ログイン試行がaudit_logsテーブルに記録される

## 影響範囲
- `src/views/admin/AdminLoginPage.tsx`
- `src/components/modals/AuthModal.tsx`
- `src/lib/supabase/middleware.ts`
- `supabase/schema.sql`（レート制限テーブル追加）
- Supabase ダッシュボード（Auth設定）

## 優先度
- **緊急度**: Critical
- **重要度**: Critical
- **理由**: 管理者アカウントの侵害はシステム全体の制御権喪失に直結する
