## 要件概要

### 背景・目的
現状、調査依頼に関する通知は **一切存在しない**。新規依頼が立っても近隣ユーザーには気づかれず、応答 / 結果投稿があっても依頼者にはアプリを開きに来ないと分からない。

REQ-084 Phase 4 として、本要件は **メール通知**（Resend 経由）を導入し、依頼ループに「外からの呼び込み」を加える。スマホ push 通知は本要件のスコープ外（将来要件）。

### 通知トリガー一覧

| イベント | 通知先 | 内容 |
|---|---|---|
| 新規依頼の INSERT | 同一市区町村の opt-in ユーザー | 「○○市で新しい調査依頼があります」 |
| 結果投稿（status: open → responded） | 依頼者 | 「あなたの依頼に結果投稿がありました」 |
| 応答（survey_request_responses INSERT） | 依頼者 | 「あなたの依頼に協力者が増えました」（1 日 1 通ダイジェスト推奨） |
| 依頼クローズ（owner 操作） | 応答者 / 結果投稿者 | 「協力していた依頼がクローズされました」 |
| コメント（REQ-089 後）| 依頼者 + コメントスレッド参加者 | 「コメントが追加されました」 |

### スコープ
**含む:**
- Edge Function `notify-survey-request`（Deno）の新規追加
- DB Webhook（pg_net）から Edge Function を起動するトリガー
- `user_profiles` に通知 opt-out カラム追加（`notify_survey_request boolean default true` など）
- ダイジェスト集約（応答通知のみ、24h バッチ）
- 通知メールのテンプレート（既存 Resend / Supabase Auth メールと同トーン）
- 通知配信失敗時のエラーログ記録（`audit_logs` 流用）

**含まない:**
- スマホ push 通知（PWA / web push API） — 別要件
- アプリ内インボックス UI（通知センター） — 別要件
- SNS / Slack 連携 — 別要件
- 多言語通知（日本語のみ初期実装）

### 前提条件・制約
- メール送信基盤は **Resend**（既存環境変数 `RESEND_API_KEY` を流用、要確認）
- 既存 `analyze-image` などと同じ pg_net + Edge Function 起動パターンを踏襲（REQ-073 と同等）
- 通知の **送信元アドレス**は Supabase Auth と同一ドメイン（DNS 設定済み前提）
- 依頼のレコードに位置情報（lat/lng）は含むが、通知メールには **市区町村以下の粒度に丸めて含めない**
