## 背景（裏取り済み）

### 問題A: 検索流入ページに出口が無い 🔴

| ページ | ヘッダー | ボトムナビ | フッター |
|---|---|---|---|
| `/species/[species]` | **無し** | **無し** | **無し**（パンくずのみ） |
| `/area/[municipality]` | 無し | **無し** | あり |
| `/about` `/dataset` | 赤ベタ＋戻る矢印 | **無し** | あり |
| `/` `/trends` `/ranking` | 白＋ハンバーガー | あり | — |

`BottomNav.tsx:25` の `VISIBLE_PATHS = ['/', '/trends', '/ranking', '/dashboard', '/profile', '/collection']`
に `/species` `/area` `/about` `/dataset` が入っていない。
**`/species` と `/area` は検索エンジンからの着地ページ**（`sitemap.ts` に含まれ ISR 生成される）なので、
そこへ来た人がアプリ本体（地図・投稿）へ進む導線を持たないのは機会損失が大きい。

### 問題B: 赤が3系統に割れている 🔴

主要ボタンの赤に `#DC2626`（brand-600）・`#EF4444`（red-500）・グラデーション（`#EC3D45`→`#E11D47`）が混在。
`bg-red-500` + 白文字は **3.76:1** でAA不合格、これがコード全体で **24箇所**（REQ-319のP1）。
※ `CrayfishIllustration.tsx` の `#EF4444`/`#DC2626` は**イラストの陰影**なので対象外（統一しない）。

### 問題C: 1440/768 で左端の縦ラインが揃っていない 🟡

1440px で左端が **x=12（検索窓）/ 98（ハンバーガー）/ 17（パンくず）/ 352（本文）** の4本に割れている。
LPは FAQ だけコンテナ幅 768（他セクションは1150）。
`dataset` の箇条書きは折返し行が行頭記号の位置まで左へ飛び出す。

### 問題D: ホーム390のファーストビューで地図が潰れている 🔴

`home_390_fv` は上下のチップ・モーダルに挟まれ、地図の素の可視部が実質 **25px**。
**マーカーは正しく描画されている**（第1周で確認済み・下表）が、**サインアップ促進モーダルが
ちょうどマーカーの座標帯を覆っている**。

| 幅 | クラスタ「6」 | クラスタ「2」 | モーダル占有 |
|---|---|---|---|
| 390×844 | (164, 604) | (194, 742) | 概ね y=450〜745 |
| 1440×900 | (689, 632) | (719, 770) | y=530〜820・x=465〜975 |

→ **打ち手は地図側ではなくモーダル側**（位置・サイズ・出すタイミング）。
初期の中心座標・ズームを動かす案は筋が悪い（マーカーは既に画面内にある）。

### 問題E: 少ないデータが「欠損」に見える 🟡

`ranking` は順位番号の無い「名無し調査員」1行、`trends` の月別グラフは12本中11本が0でラベルの「0」だけが並ぶ、
「上位10件」の見出しに1件。**本番データが8件なのは仕様**なので、
直すのはデータではなく**少ない状態の見せ方**。

## 機能要件

- **FR-320-01**: `/species/[species]` `/area/[municipality]` `/about` `/dataset` に
  **共通ヘッダーとボトムナビ**を出す。`VISIBLE_PATHS` に4パスを追加し、
  本文コンテナに `ナビ高さ+16px` の下部余白を確保する（REQ-268 の方針を踏襲）。
  ※ `/about` `/dataset` `/species` は Server Component なので、
  BottomNav（`onPostClick`/`onLoginClick` を要求する Client Component）を出すには
  **クライアント側のラッパーが要る**。既存の `CollectionPage.tsx` の使い方を前例にする。
- **FR-320-02**: ヘッダーの意匠を1系統に統一する。`/about` `/dataset` の**赤ベタヘッダーを廃止**し、
  白背景・下1px境界・左に戻る矢印・中央にロゴ＋ページ名に寄せる。
- **FR-320-03**: `/species` にフッターを追加する（`/area` と同じ `Footer` コンポーネント）。
- **FR-320-04**: 主要ボタン・タブ・バッジの赤を **`#DC2626`（brand-600）に一本化**する。
  `bg-red-500` + 白文字（3.76:1）を全廃（REQ-319 P1 の24箇所を本周で消化）。
  グラデーションのCTAも上端を brand-600 相当に寄せる。**イラストの陰影は対象外**。
- **FR-320-05**: コンテナ幅と左パディングを共通トークン化し、1440/768 で左端の縦ラインを1本に通す。
  LP の FAQ セクションも他セクションと同じコンテナ幅にする。
- **FR-320-06**: `dataset` の箇条書きの折返しがぶら下がりインデントになるよう直す。
- **FR-320-07**: ホームのサインアップ促進モーダルが**マーカーを覆わない**ようにする。
  390では画面下部のシート型にして地図の可視領域を確保し、1440では地図中央を避ける。
  「今は不要」で閉じた後に地図が主役として見えることを保証する。
- **FR-320-08**: 空状態の見せ方を整える。
  - `ranking`: 1件しか無くても順位番号を出す。「上位10件」のような**実データと矛盾する見出しを出さない**
  - `trends`: 0が並ぶ月別グラフは、0のラベルを描かないか期間を実データのある範囲に寄せる
  - 共通: 「まだ少ない」ことを前向きに伝える文言＋投稿への導線を置く（データの捏造はしない）
- **FR-320-09**: FR-320-04 で直した組を `src/lib/__tests__/contrast.test.ts` の表に追記する。
