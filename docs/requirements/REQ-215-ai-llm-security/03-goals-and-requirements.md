## 目的
- Gemini レスポンスを **「外部 API 出力 ＋ ユーザー入力」**として扱い、受信後に独立したスキーマ/値域検証層を通してから DB・自動判定・UI へ反映する（responseSchema を唯一の防御にしない）。
- 自由文 AI 出力（`notes` / `concerns`）の enum 化・上限統一・サニタイズを行い、第三者表示面に Gemini 生成テキストが無害化されずに出ないようにする。
- AI 判定（自動承認/却下）の権威化に対し、**閾値の安全側下限・濫用検知（異常 auto-approve の監視）・新規投稿経路のコスト/濫用ガード**を整備する。
- プロンプト構築で**ユーザー由来データを明示的に分離・無害化**し、`record.species` 等のプロンプト混入による判定誘導を抑止する。再分析経路で client が渡す `record` の信頼境界を明確化する。
- Gemini への送信前に**サイズ上限・件数・データ最小化**を Edge 側で担保し、機微データの過剰送信を抑える。
- 鍵のサーバー専用方針と redaction 依存を維持・固定する。

- [ ] FR-215-02: `is_appropriate` のフェイルオープンを是正する。**`is_appropriate` が明示的に `true` のときのみ自動承認可**とし、欠落/`null`/非 boolean のときは自動承認しない（手動レビューへ）。`analyze-image/index.ts:910-915` の `shouldAutoApprove` と `analyze-audio/index.ts` の `combineDecision`（:384 ほか）を、FR-215-01 の正規化済み値を前提に修正する。`is_appropriate === false` の自動却下は維持する。
