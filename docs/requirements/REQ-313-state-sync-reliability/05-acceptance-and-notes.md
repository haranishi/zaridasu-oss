## 受入基準

- **AC-01**: プッシュ通知を ON にして失敗した場合、トグルが戻るだけでなく理由が表示される。**OFF 操作がサーバーに反映されるまで購読 OFF 表示にしない**（DB 削除失敗時はトグルが ON のまま、エラーが表示される）。
- **AC-02**: `get_user_quality` を失敗させた状態でランキングの品質タブを開くと、`LoadErrorState` ＋再試行が表示され、「品質スコアがありません」の空状態が表示されない。再試行で復帰する。
- **AC-03**: オフライン状態で品質タブを開いても無言の空表示にならない。
- **AC-04**: いいね操作が失敗し、かつ再同期クエリも失敗する状況で、表示中のいいね数が 0 に変わらない（押下前の値が保持される）。エラートーストは従来どおり表示される。
- **AC-05**: **該当0件の条件で CSV エクスポートを実行するとダウンロードは行われず**、0件であることが明示される。ヘッダ行だけのファイルが落ちてこない。
- **AC-06**: CSV のクエリ失敗が `logError` 経由で Sentry に記録される。
- **AC-07**: 追加した i18n キーが ja/en/ko/zh 4言語すべてに存在し `npm run i18n:check` がパスする。
- **AC-08**: `lint` / `type-check` / 既存652テストがパスする。

## 備考（要確認）

- FR-313-02 で「OFF 失敗時はトグルを ON のまま維持」とした場合、ブラウザ側の `sub.unsubscribe()`（`usePushSubscription.ts:201`）は成功しているが DB 削除だけ失敗した、という中間状態が起こり得る。この場合の表示（「解除処理が完了していません。再試行してください」等）と、次回 `subscribe()` 時の復旧挙動は**要確認**。
- 問題D-3（iOS Safari のダウンロード不安定）は監査時点でコードの書き方から指摘されたもので、**実機での再現は未確認**。FR-313-06 の `<a>` append と revoke 遅延は一般的な安全策として実施するが、実機検証を別途行うことが望ましい。
- FR-313-06 の「0件時に出す通知」は `toast.info` 相当が既存の Toast API に存在するかを**要確認**（無ければ既存の種別で代替する）。
