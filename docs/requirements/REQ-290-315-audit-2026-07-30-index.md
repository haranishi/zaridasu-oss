# REQ-290〜315: 全体監査 2026-07-30 — 課題インデックス

## これは何か

2026-07-30 に6観点で実施した並列監査の結果を、REQ-290〜315 の26要件に割り当てた索引。総課題数 106件（Critical 1 / High 22 / Medium 51 / Low 32）。本文は下記の部品ファイルに逐語のまま分割してある。

## 目的・背景の要約

前回監査（REQ-269〜281、2026-07-17）以降に実装済みの項目を除外し、**現在のコードに実在し裏取りできた課題のみ**を採録している。事前の健全性確認では type-check・lint・Vitest 652件がすべて通っていたが、`npm audit --omit=dev` は High 4パッケージを検出した。これが滞留していた理由も特定済みで、CI の audit ステップが exit code を打ち消す warning 専用の書き方になっており、**ゲートが最初から発火しない設定**だった。

## 主要な決定事項の要点

- **Critical は1件**。位置選択が地図クリック専用で、キーボード・支援技術の利用者が投稿を完了できない（REQ-294、WCAG 2.1.1 失敗）。
- **High に共通する2つの型**。①「**コードは入っているのに値の供給・失効が未完で実効性ゼロ**」（REQ-290 の資格情報残存、REQ-291 の webhook 常時パススルー）。②「**CI が緑なのに検査していない**」（REQ-297 の Edge Function 型検査漏れ、REQ-306 の監視カバー率 2.8%、REQ-298 のドリフト検知の穴）。
- **実施順序はフェーズ0〜4**。まず値を入れるだけの運用タスク（REQ-290 / REQ-291）、次に P0、**そのあと検査基盤（REQ-297 → REQ-306 → REQ-298）を先に直す**。後続の修正が退行しても気づけなくなるためこの順序を崩さない。
- **重複の一本化**: `DrawerMenu` の閉状態DOM残存は **REQ-307 FR-307-07 に一本化**、`/dashboard` の h1 追加は **REQ-315 が正本**、`public/offline.html` は SW配線＝REQ-293／i18n＝REQ-304 で分担。
- **REQ-290 の CI 検知には構造的な限界がある**。CI はクリーン checkout で動くため未追跡のローカルファイルは存在せず、`gitleaks dir` を足しても捕まらない。実際に効く層はローカルの pre-commit。
- **意思決定待ちは REQ-312 の hreflang / 多言語URL**（`/[locale]` 導入は工数が大きくプロダクト判断）。
- 2026-07-31 時点で REQ-292 / 293 / 294 / 295 / 296 / 297 / 302 / 306 / 310 / 312 に実装済み・一部実装済みの記録が入っている（詳細は対応表を参照）。
