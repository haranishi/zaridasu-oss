# REQ-032: データ取得の効率化（集約クエリ・サイトマップ）

## 背景
統計データの取得で6-7個の並列クエリが発行されており、DB側集約関数で最適化できる。また、サイトマップ生成で最大3000レコードを一括取得しており、大規模化時にタイムアウトのリスクがある。

## 現状の問題
- `src/hooks/useStats.ts:120-133`: 6-7個の `Promise.all` による並列クエリ
  - 総投稿数カウント
  - 今月の投稿数カウント
  - 先月の投稿数カウント
  - 全投稿の species, info_type 取得（limit 2000）
  - 月別データ
  - 市町村別データ
  - クライアントサイドで集計処理を実行
- `src/app/sitemap.ts:32-72`: 最大3000レコードを一括取得
  - 投稿: 1000件
  - 調査依頼: 500件
  - ユーザープロフィール: 500件
  - 全カラム取得（必要なのは id, updated_at のみ）

## 目的
DB側の集約関数・最適化クエリにより、データ転送量とクライアント側計算量を削減する。

## 要件

### 機能要件
- [ ] FR-032-01: useStats の集計ロジックをDB側RPC関数 `get_dashboard_stats()` に移行する（種類別カウント、情報種別カウント、月別集計、市町村別ランキングを1回のRPC呼び出しで返す）
- [ ] FR-032-02: サイトマップ生成クエリで必要なカラムのみ選択する（`select('id, updated_at')`）
- [ ] FR-032-03: サイトマップのページネーション対応を追加する（1000件超の場合に複数サイトマップインデックスを生成）
- [ ] FR-032-04: useStats で取得した2000件の全投稿データをクライアント側で集計している処理を、DB側 `COUNT(*) GROUP BY` に置換する

### 非機能要件
- [ ] NFR-032-01: ダッシュボードの統計データ取得が現状比50%以上高速化されること
- [ ] NFR-032-02: サイトマップ生成が10秒以内に完了すること（10,000投稿規模でも）
- [ ] NFR-032-03: RPC関数は `SECURITY INVOKER` で実行し、RLSポリシーを尊重する

## 受入条件
- [ ] AC-01: `get_dashboard_stats()` RPC関数がSupabaseに存在し、1回の呼び出しで統計データが返る
- [ ] AC-02: useStats のクエリ数が1-2個に削減されている
- [ ] AC-03: サイトマップの SQL で `select('id, updated_at')` が使用されている
- [ ] AC-04: ダッシュボードページの初回表示が体感的に改善されている
- [ ] AC-05: `npm run build` で sitemap 生成がタイムアウトしない

## 影響範囲
- `supabase/schema.sql`（RPC関数追加）
- `src/hooks/useStats.ts`
- `src/app/sitemap.ts`
- `src/app/dashboard/DashboardPageClient.tsx`
