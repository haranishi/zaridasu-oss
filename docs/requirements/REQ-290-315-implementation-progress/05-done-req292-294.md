### REQ-292 anon GRANT された RPC の認可欠陥修復（P0/High）
- 新規 migration `supabase/migrations/20260730000001_req292_authz_defects_anon_granted_rpc.sql` ＋ pgTAP `supabase/tests/req292_anon_granted_rpc_authz.sql`（28アサーション）
- anon GRANT 剥奪＋関数本体に fail-closed ゲート `_req292_is_server_caller()`。**`role` GUC が SECURITY DEFINER 内でも書き換わらないことを Postgres 16 で実測**し、`role GUC` 判定を第1ガード・claims 判定を第2ガードにした独立2段構成。第2が破れても閉じたままであることを pgTAP §5-b で検証
- `check_email_exists` の事前チェックを `AuthModal` から削除し、重複判定を `signUp` 後の `identities` 空判定へ一本化
- Auth Hook 用 `public.admin_login_password_attempt(jsonb)` を新設（`/auth/v1/token` 直叩きも記録できる）
- **pgTAP はローカル Docker で CI harness を完全再現して実行し 212/212 PASS**。migration の冪等性も2回連続適用で確認
- **CI の一括 GRANT が REVOKE を打ち消す問題**に対し `supabase/ci/reapply-after-grants.txt` へ追記。捨てコンテナで「一括GRANT後は anon=true → 再適用後は anon=false」を実測確認済み

**残タスク（運用・コードでは不可）**
1. `supabase db push`（これだけで問題A・C・Dが閉じる）
2. Auth Hook の有効化（`supabase/config.toml` に `enabled = false` で記述済み）。**有効化したら正しいパスワードでログインできることを必ず実測**すること。本番で Hooks（Beta）が使えるかも要確認
3. 本番での GRANT 実測クエリ・`audit_logs` 汚染調査クエリの実行（migration 末尾に記載）

> **Auth Hook が `decision: reject` を返さない設計は意図的**。このフックのペイロードに IP が含まれずカウンタが「メール単位・全IP共通」になるため、reject を有効にすると第三者が管理者メールで5回失敗させるだけで**正規管理者をロックアウトできる**（管理者DoS）。総当たり対策は Supabase Auth のレート制限に委ねている。

**⚠️ 実装レビューで検出・修正した欠陥（同種の再発に注意）**
`<MapContainer aria-label={...}>` が **DOM に一切出力されていなかった**。react-leaflet 5.0.0 の `MapContainer` は div へ `className`/`id`/`style` のみを spread し、残りは Leaflet コンストラクタに渡って黙って捨てられる。JSX ではハイフン入り属性名が props 型と照合されないため `tsc` も検出しない。実測すると `aria-label` が `null` なのに Leaflet が `tabindex="0"` を付けており、**名前のない要素にフォーカスが入る**状態だった。
→ `map.getContainer()` 経由で設定する形に修正し、**モックしない実 react-leaflet を jsdom で render する回帰テスト**（`LocationPicker.integration.test.tsx`）で DOM 属性を直接 assert。
**教訓: ラッパーコンポーネントに aria 属性を渡す実装は、必ず実DOMでの出力をテストすること。**
