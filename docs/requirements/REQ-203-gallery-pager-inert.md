# REQ-203: 地図⇄写真ギャラリー切替パネルの inert 化・タッチターゲット・i18n

## 背景
ザリダスのホーム画面 `src/app/(home)/HomeInteractive.tsx` は、地図パネルと写真ギャラリーパネルを横スライドで切り替える 2 面構成になっている（308〜366行）。実装は幅 200% の内側 `<div>` を `transform: translateX(-${panelIndex * 50}%)`（316行）でずらす方式で、非アクティブ側のパネルは画面外（オフスクリーン）に配置されるが、DOM 上は常に存在しフォーカス可能なままである。

このため:
- 地図表示時（`panelIndex===0`）は、画面外にある「地図に戻る」ボタン（345行）へ `Tab` が移動できてしまう。
- ギャラリー表示時（`panelIndex===1`）は、画面外の地図コントロール・マーカー群へ `Tab` が移動できてしまう。

いずれもフォーカスが画面外（不可視）へ移り、フォーカスインジケータが見えない「フォーカスの迷子」を生む。これは WCAG 2.1 **2.4.3 フォーカス順序（レベル A）**（および 2.4.7 フォーカスの可視性・レベル AA）に反する。React 19 は `inert` 属性をネイティブサポートしており、非アクティブパネルを `inert` 化することで配下要素を一括してフォーカス・操作対象から外せる。

あわせて、同領域に以下の付随課題がある:
- エッジハンドル（328〜337行、地図→ギャラリー誘導ボタン）が `h-16 w-6`（幅 24px）で、タッチターゲットが小さい。WCAG **2.5.8 ターゲットのサイズ（最小）（レベル AA, 24×24px）** はぎりぎりだが、iOS（44pt）/ Android（48dp）の推奨を大幅に下回る。エッジスワイプ（`handleTouchEnd` の 40px 超判定、`Math.abs(dx) < 60` 等 300〜305行）という代替操作はあるが、「スワイプで切替」の案内（352行）は**写真パネル側にのみ**表示され、地図パネル側からは見えない。
- ラベル `aria-label="写真ギャラリーを開く"`（330行）・「地図に戻る」（345行 aria-label / 349行表示テキスト）・「スワイプで切替」（352行）が**日本語ハードコード**で、`t()` を使っていない（多言語で日本語のまま表示・読み上げ）。

## 現状の問題
- `src/app/(home)/HomeInteractive.tsx:309-366` — 地図⇄ギャラリー切替コンテナ。`translateX(-${panelIndex * 50}%)`（316行）でオフスクリーン化するが、非アクティブパネル（地図側 318〜338行 / ギャラリー側 339〜358行）に `aria-hidden` / `inert` がない。
  - 地図表示時: 画面外の「地図に戻る」ボタン（345行）へ `Tab` 到達可能。
  - ギャラリー表示時: 画面外の地図コントロール・マーカー群（`MapView` 319行配下）へ `Tab` 到達可能。
- `src/app/(home)/HomeInteractive.tsx:328-337` — エッジハンドルが `h-16 w-6`（24px 幅）でタッチターゲット不足。スワイプ代替の案内（352行）は地図側から不可視。
- `src/app/(home)/HomeInteractive.tsx:330` `aria-label="写真ギャラリーを開く"` / `:345` `aria-label="地図に戻る"`・`:349` 「地図」 / `:352` 「スワイプで切替」 — いずれも日本語直書き（`t()` 不使用）。

## 目的
非アクティブパネル配下をフォーカス・操作対象から除外し（`inert`）、フォーカスが可視パネル内に閉じるようにする（WCAG 2.4.3）。エッジハンドルのタッチターゲットを見た目を変えずに 44px 以上へ拡大し、関連ラベル 3 点を 4 ロケールで i18n 化する。

## 要件
### 機能要件
- [ ] FR-203-01: 非アクティブなパネルに `inert` 属性を付与する（React 19 ネイティブ対応）。具体的には:
  - 地図パネル（318行の `<div className="w-1/2 h-full relative">`）は `panelIndex !== 0` のとき `inert`。
  - ギャラリーパネル（339行の `<div className="w-1/2 h-full flex flex-col">`）は `panelIndex !== 1` のとき `inert`。
  - `inert` により配下のボタン・リンク・マーカーが一括でフォーカス/クリック対象外になることを利用する（個別 `tabindex` 操作は不要）。
- [ ] FR-203-02: エッジハンドル（328〜337行）のタッチ当たり判定を 44px 以上に拡大する。**見た目（`h-16 w-6` の視覚サイズ）は維持**し、透明な `padding`（または擬似要素/不可視の拡張ヒット領域）でヒットエリアのみ拡大する。
- [ ] FR-203-03: 以下のラベルを i18n キー化し、`t()` 経由にする（4 ロケール ja/en/ko/zh に追加）:
  - 330行 `aria-label="写真ギャラリーを開く"`
  - 345行 `aria-label="地図に戻る"` および 349行の表示テキスト「地図」
  - 352行 「スワイプで切替」
  - キー命名は既存規約（例: `home.openGallery` / `home.backToMap` / `home.swipeHint` 等）に合わせる。
- [ ] FR-203-04（任意・UX 改善）: 「スワイプで切替」案内（352行）が写真パネル側にのみ表示され地図側から見えない非対称を是正する（地図パネル側にも控えめなヒントを出す、もしくはエッジハンドル自体が誘導として十分かを判断して記録する）。必須ではないが、対応有無を実装時に明記する。

### 非機能要件（該当する場合のみ）
- [ ] NFR-203-01: `inert` 適用後も、アクティブパネル内の操作（地図のパン/ズーム/マーカー、ギャラリーのスクロール/項目操作）は従来どおり動作すること。
- [ ] NFR-203-02: タッチターゲット拡大はレイアウト（隣接要素の位置・地図表示領域）を崩さないこと（透明領域がオーバーレイして他操作を奪わない）。
- [ ] NFR-203-03: 新規 i18n 文言は 4 ロケールすべてに存在し、欠損ロケールがないこと。

## 受入条件
- [ ] AC-01: 地図表示時（`panelIndex===0`）に `Tab` を巡回させても、フォーカスが画面外のギャラリー側要素（「地図に戻る」ボタン等）へ移動しない（フォーカスが可視の地図パネル内に閉じる）。E2E で確認する。
- [ ] AC-02: ギャラリー表示時（`panelIndex===1`）に `Tab` を巡回させても、フォーカスが画面外の地図コントロール・マーカー群へ移動しない。E2E で確認する。
- [ ] AC-03: エッジハンドルのタッチターゲット（ヒットエリア）が 44px 以上ある一方、視覚的な見た目サイズは従来（`h-16 w-6`）と変わらない。
- [ ] AC-04: 「写真ギャラリーを開く」「地図に戻る」「地図」「スワイプで切替」が、言語切替時に各言語で表示・読み上げされる（日本語ハードコードが残らない）。新規キーが 4 ロケールに存在する（キー網羅テスト）。
- [ ] AC-05: 地図⇄ギャラリー切替を含むページに対する axe 検査で、オフスクリーン要素起因のフォーカス/可視性違反が 0 件。
- [ ] AC-06: 既存のホーム画面（地図/ギャラリー切替）関連テストが全て成功する。

## 優先度
- **緊急度**: 中 / **重要度**: 中 / **理由**: オフスクリーン要素へのフォーカス漏れは WCAG 2.4.3 レベル A 違反で、キーボード/スクリーンリーダー利用者が「見えない要素」にフォーカスを奪われる実害がある。一方で主要 CV を直接妨げるものではなく、`inert`（React 19 対応済み）の付与・ヒットエリア拡大・ラベル i18n と対応は局所的・低リスク。ユーザー向けモーダル系（REQ-187〜189）に続けて対応する。
