## ユーザーストーリー

### US-086-01: 結果投稿者として依頼との紐付けを確実にしたい
**As a** 調査依頼に応答する投稿者,
**I want to** 「調査結果を投稿する」ボタンから始めた投稿が、確実に元依頼に紐付く,
**So that** 後で詳細ページから「これに対する結果」として一覧表示される.

**受け入れ条件:**
- [ ] AC-1: ボタン押下後の投稿フォームに「○○ さんの調査依頼への返信」バナーが表示される
- [ ] AC-2: 投稿完了後、生成された posts レコードの `survey_request_id` が一致する
- [ ] AC-3: 元依頼の詳細ページの「関連投稿」に新しい投稿が出現する
- [ ] AC-4: ユーザーがフォーム途中でキャンセル / 別画面に行ってもバナーは離脱で消える（持ち越さない）

**優先度:** 高 ／ **見積もり:** S

### US-086-02: 依頼者として結果が来たら status が前進してほしい
**As a** 依頼を立てた投稿者,
**I want to** 結果投稿が紐付いた瞬間に依頼の status が `open → responded` に自動遷移する,
**So that** 一覧で進捗が一目で分かる.

**受け入れ条件:**
- [ ] AC-1: `posts.insert` で `survey_request_id` が non-null かつ親が `open` なら status が `responded` に変わる
- [ ] AC-2: 親が既に `closed` の場合は変更しない
- [ ] AC-3: 結果投稿が `rejected` になった場合の扱いは初期実装では responded のまま（次フェーズで再検討）

**優先度:** 高 ／ **見積もり:** S

### US-086-03: 依頼者として誤紐付けを防ぎたい
**As a** 依頼者および結果投稿者,
**I want to** `survey_request_id` を投稿者が自由に書き換えられないようにしたい,
**So that** 誰かが他人の依頼に勝手に紐付けて状態を変えるのを防げる.

**受け入れ条件:**
- [ ] AC-1: `posts.update` で `survey_request_id` を書き換えることは制限される（既存 `restrict_user_columns` トリガーで保護）
- [ ] AC-2: insert 時の `survey_request_id` は実在する依頼のみ受け入れる（FK 制約で保証済み）

**優先度:** 中 ／ **見積もり:** XS
