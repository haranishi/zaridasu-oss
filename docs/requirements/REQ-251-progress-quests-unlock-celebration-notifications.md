# REQ-251: 進捗の可視化・クエスト・解放演出・通知（ゲーミフィケーションの結合層）

## 背景
REQ-248（レベル/XP エンジン）・REQ-249（機能解放）・REQ-250（コレクション/水槽/3D）は「進行の実体」を作る。しかし進行は**見えて・手応えがあって・戻ってきたくなる**ようにして初めて機能する。本 REQ は、それらを結ぶ**フィードバック層**——次の解放までの進捗表示、品質を促す穏やかなクエスト、解放/レベルアップの演出、節目の通知——を定義する。既存の演出/検知/通知基盤を最大限流用し、新規の重い依存（アニメーションライブラリ等）は入れない。

**流用できる既存基盤**:
- 解放検知: `src/lib/achievement.ts`（`detectNewThresholds(scopeKey,total,thresholds)` / `detectNewBadgeIds` / `prefersReducedMotion()`、`:32-100`）——localStorage 差分で「新たに跨いだしきい値」を検出し一度だけ演出する仕組み。`BadgeSection.tsx:24-27`・`ProfilePage.tsx:73-79` で配線済み。**レベルアップ/解放の瞬間検知にそのまま使える**。
- 演出: `src/app/globals.css` の CSS キーフレーム（`badge-unlock` `:617-624` / `like-pop` / `fade-up`。transform/opacity のみ＝リフローなし）。`prefers-reduced-motion` で全アニメ無効化（`:212-220`）＝**a11y 無償準拠**。framer-motion 等は不使用。
- 通知: REQ-234（Resend ライフサイクルメール）・REQ-237（Web Push）・`notify-*` Edge Function 群。
- 品質/多様性の促し: REQ-173（空間バイアス nudge）・REQ-174（定点観察）・REQ-235（品質バッジ）。

## 現状の問題（機会）
（ファイルパス:行番号つき）

1. **進行が可視化されていない**: レベル/XP/解放（REQ-248/249/250）を入れても、「次に何をすればどれだけで何が解放されるか」を見せる UI が無ければ動機に変換されない。既存の達成演出（REQ-226）はバッジ単発で、進行全体のナビゲーションが無い。
2. **行動の方向づけ（クエスト）が無い**: 「次に何をすると良いか」の導線が無く、量産（Goodhart）に流れやすい。品質・多様性へ誘導する軽いミッションが無い。
3. **解放/レベルアップの瞬間の手応えが弱い**: `achievement.ts` の一度きり演出は使えるのに、レベルアップ/機能解放/新図鑑カードには未接続。
4. **戻ってくる理由（通知）が進行に未接続**: REQ-234/237 の通知基盤はあるが、「あと 1 件で解放」「レベルアップした」等の進行イベントに紐づいていない。

## 目的
進行を可視化し、品質・多様性へ促す穏やかなクエストと、既存基盤を流用した解放演出・通知でフィードバックループを閉じる。ダークパターン（喪失を罰するストリーク強制・過剰通知）を避け、ブランドの穏やかな声を保つ。

## 要件

### 機能要件
- [ ] FR-251-01: **進捗の可視化**。ダッシュボード/プロフィールに「現在レベル・次のレベルまでの XP・次に解放される機能/カード」を表示する（`get_user_progress`＝REQ-248、`FEATURE_UNLOCKS`＝REQ-249 を参照）。ロック項目に「あと承認 n 件／XP で解放」を添える（REQ-249 のティーザーと共通化）。図鑑の収集率（%）も表示。
- [ ] FR-251-02: **クエスト/ミッション（品質・多様性志向）**。「今週の調査ミッション」等として、**量ではなく質/多様性**を促す軽い課題を提示する（例: 定点観察を 1 回／新しい市町村で観察／GPS 精度の高い記録を残す／不在確認を記録）。REQ-173/174/235 と整合。達成は REQ-248 の XP/図鑑と接続。**任意参加・未達成を罰しない**（喪失ベースのストリーク圧力を作らない）。
- [ ] FR-251-03: **解放演出**。レベルアップ・機能解放・新図鑑カード獲得の瞬間を、`achievement.ts` の `detectNewThresholds` パターン＋既存 CSS キーフレーム（`badge-unlock` 系）で一度だけ祝う。新規アニメライブラリは追加しない。`prefers-reduced-motion` 準拠。
- [ ] FR-251-04: **通知連携**。レベルアップ／機能解放／節目（「あと少しで解放」「久しぶりの再訪で解放が近い」）を、REQ-234（メール）・REQ-237（Web Push）に穏やかな頻度で接続する。既存の配信基盤・購読/解除（`/u/unsubscribe`）・PII 最小（REQ-211）を尊重。過剰通知を避けるレート/まとめ配信。
- [ ] FR-251-05: **i18n**。進捗/クエスト/演出/通知の文言を 4 言語に追加し `i18n:check` を通す。ブランド声（です・ます・「！」不使用）・禁止語（大学/卒業研究 等）不使用。マスコットのセリフ（例「ここにザリガニがいますよ」）を使う場合も同様。

### 非機能要件
- [ ] NFR-251-01: 演出は transform/opacity のみのリフローフリー（REQ-226 の NFR に準拠）。`prefers-reduced-motion` で無効化。追加の重い依存を入れず size-limit（`.size-limit.json`）・Lighthouse（CLS≤0.1・a11y≥0.9）を維持。
- [ ] NFR-251-02: **ダークパターン回避**。喪失回避を煽るストリーク強制・偽の緊急性・過剰バッジ/通知を用いない。クエストは任意で、未達成にペナルティを与えない（内発的動機を損なわない＝research-rq1 の動機整合）。
- [ ] NFR-251-03: 進捗/クエストの集計はクライアント負荷・DB 負荷を抑え、`/dashboard`・`/ranking` の性能バジェット（REQ-191/124）を悪化させない。`achievement.ts` の localStorage 検知はプライバシー安全（サーバーに逐次送らない）。
- [ ] NFR-251-04: 通知はオプトイン/解除を尊重し、頻度上限を設ける（REQ-234/237 の方針に整合）。

## 受入条件
- [ ] AC-01: ダッシュボード/プロフィールに「現在レベル・次までの XP・次の解放・図鑑収集率」が表示され、ロック項目に到達条件が添えられる。
- [ ] AC-02: 品質/多様性志向のクエストが提示され、達成が XP/図鑑に反映される。未達成でペナルティが無い。
- [ ] AC-03: レベルアップ/機能解放/新図鑑カードで一度きりの解放演出が再生され、`reduced-motion` で無効化される。新規アニメ依存が増えていない。
- [ ] AC-04: 進行イベントがメール/Web Push に穏やかな頻度で連携し、解除設定が機能する。
- [ ] AC-05: 追加文言が 4 言語に存在し `i18n:check` が通る。禁止語・ダークパターン文言を含まない。

## 優先度
- **緊急度**: Low / **重要度**: Medium
- **理由**: 進行（REQ-248〜250）を「動機」に変える結合層。既存の検知（achievement.ts）・演出（CSS keyframes）・通知（REQ-234/237）基盤を流用でき追加コストが小さい。ダークパターンを避けつつ、継続動機とデータ品質（卒研の成果）を同時に押し上げる。REQ-248〜250 の後に着手する仕上げ層。
