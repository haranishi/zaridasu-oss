# いまの仕様

**「いま何が正しいか」を書く場所。** 何かを実装する前に、関係する領域のページを読む。

## なぜ分けてあるか

`docs/requirements/` の REQ 文書は 300 本を超える。1 本ずつが「そのとき何を決めたか」を書いた変更の履歴なので、**現在の姿を知るには読み漁るしかない**。「投稿」という語だけで 180 本以上に登場する。

そこで領域ごとに 1 枚だけ、現在の状態を書いたページを置くことにした。REQ 文書は履歴として残す。消さない。

## 書き方のルール

- **「いま」だけを書く。** 「以前は〜だった」は履歴の仕事
- **コードを読めば分かることは書かない。** 列の一覧や関数の引数を並べても、コードを見れば済む。書くのは**コードを全部消したら失われること**——なぜそうしたのか、何に頼っているのか、変えると何が壊れるのか
- **各節に正本のファイルを書く。** 食い違ったらコードが正しく、この文書が古い
- **1 ページ 100 行以内**

## 直すとき

仕様を変えたら、REQ 文書とは別にここも直す。直し忘れが続けば、この仕組みごと信用されなくなる。そうなったら元の木阿弥なので、面倒でも一緒に直す。
