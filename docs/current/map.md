# 地図の現在地（追従）

地図右下の「現在地を表示」ボタンの、いまの挙動。決めた経緯は [map-location-follow](../../.kiro/specs/map-location-follow/brief.md)。

## 何をするか

押すと端末の位置を継続して取り、青い点と精度の円を動かして、地図の中心を現在地に保つ（追従）。
地図を動かすと追従だけが一時停止し、点は動き続ける。ボタンを押すと現在地へ戻って再開する。追従中に押すと止まり、点と円が消える。
位置が届く前（取得中）に地図を動かしたら、位置が届いても追従にせず、一時停止にして地図を引き戻さない。位置が3秒たっても来ないとき、追従を始めた最初の1回、一時停止になった最初の1回は、ボタンの左に説明の札が出る（止め方・戻り方）。
地図を開いただけでは位置を取らず、許可も求めない（REQ-324）。

正本: [LocateControl](../../src/components/features/map/LocateControl.tsx)。状態の遷移は [locationFollow.ts](../../src/lib/maps/locationFollow.ts)、地図を動かす規則は [useFollowCamera.ts](../../src/hooks/useFollowCamera.ts)。

## 約束

- **追従のために取った座標を、当サイトは自動で送信・保存しない。** Reactの状態（メモリ）にだけ置く。試験が、通信・`sendBeacon`・`localStorage`/`sessionStorage`・IndexedDB・Cookie・ログ・`dataLayer` に何も出ないことを固定している。
  利用者が押した機能（投稿・「非公開で保存」・「近くの水域を探す」）は別で、その機能に必要な座標（現在地や、現在地に合わせた地図の中心）を使う。
  ただし、地図の背景画像は表示している地域の分を提供元（OpenStreetMap・国土地理院）から取るので、追従中は現在地の周辺の地域がIPアドレスとともに提供元に伝わる。手で動かしても同じ仕組みで、避けられない。プライバシーのページに書いてある。
- **取得中・追従中は「現在の地図範囲内のみ」をオフにする。** この絞り込みは、地図の範囲を検索条件としてサーバーへ送る。追従中は範囲が現在地を中心に動くので、オンのままだと移動の軌跡が、利用者のIDと一緒にサーバーのログに残る。一時停止中は、利用者が見る場所を選んでいるので使える。
- ボタンの状態は、色や動きだけで伝えない。取得中は輪郭の矢印（脈動）、追従は塗りつぶしの矢印、一時停止は十字と太い黒枠。静止画や「視覚効果を減らす」でも見分けるため（視覚評価で、脈動だけでは追従と同じに見えると指摘された）。
- ボタンの名前は常に「現在地を表示」。E2E（`map-settings.spec.ts`）がこの名前で数えている。押された状態は `aria-pressed`、押すと起きることは `title` で伝える。
- 秋田県の外でも点を出して追従する。
- 追従の自動移動も、既存の `map_interact` 計測を出す。初期表示の移動でも出る既存の作りで、変えていない。

## 変えると壊れること

- **一時停止の検出**は `movestart` で行う。自分の `panTo` には `noMoveStart: true` を付けて、自分の移動に `movestart` を出させない。「印を立てて `moveend` で降ろす」作りだと、滑らかな動きの最中に次の位置が届いたとき、前の動きを止める `moveend` で印が先に消え、自分の移動を利用者の操作と取り違えて一時停止になる（車での連続した移動で毎回起きる）。
- ズームでは止めないが、中心が48px以上ずれたら止める。ほかの部品の `setView`・`flyTo` を、追従が引き戻さないため。
- 利用者のズームのアニメーション中は、地図を動かさず、`zoomend` のあとで寄せる。Leafletはそのあいだの `setView` を黙って捨てるため。
- 位置は高精度・5秒の鮮度で取る。網による測位は数百m〜数kmずれ、車の追従にならない。
- 取得している間は画面を点けたままにする。自動で消えると、ブラウザが位置の更新を止め、点がまた動かなくなる。
- 点が画面の中心から8px以上離れたときだけ地図を寄せる。毎秒動かすと、`HomePage` の境界の再計算が無駄に増える。
- 取得中の札は、共通のトーストでなく専用の札にする。トーストは閉じられず、位置が届いたあとも「取得しています」が残る。同じ失敗の通知は5秒重ねない（拒否のまま押し直すと、同じ通知が積み重なって画面の上半分を覆った）。
- ボタンの状態を `outline` で表さない。Leafletは、地図の中で `mousedown` が起きるたびに（タップのあとの `mousedown` でも）、押した要素に `outline-style: none` を直接書く（`DomUtil.preventOutline`）。取得中の点線を `outline` で描いたら、押した直後に消え、評価で「出ていない」と指摘されるまで気づけなかった。`border` か `box-shadow`（`ring`）で描く。
- 精度の円は押せない。押せると、地図のクリック・長押し・ピン立てを円が受けてしまう。
- 青い点は専用の層（z-index 620）に描く。標準の層だと、投稿のマーカーやまとまり（600）の下に隠れ、投稿の多い場所で現在地が見えなくなる。円は下の層のまま（マーカーを薄く覆わないため）。

## できないこと

- 画面を閉じている間・ほかのアプリに切り替えている間の追従（Webの制約）。戻ると取り直す。
- 進行方向の矢印、軌跡の記録。
