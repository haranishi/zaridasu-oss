# プライバシーと個人情報 — いまの仕様

> 「いま何が正しいか」だけを書く。「そのとき何を変えたか」は `docs/requirements/REQ-*.md`（履歴）。
> 食い違ったら**コードが正**。

このプロジェクトは市民から生きものの目撃情報を集める。**位置情報と投稿者が結びつくと、その人の生活圏が分かってしまう**。だから防御は「アプリが気をつける」ではなく **DB の権限と生成列**で作ってある。

## 何を守っているか

| 守る対象 | どう守るか |
| --- | --- |
| 正確な座標 | 生 `lat` / `lng` を列 GRANT で剥奪。公開は粗化した生成列だけ（[posts.md](./posts.md#座標の扱いここが一番壊れやすい)） |
| 非公開にした投稿の地名 | `locality` / `water_body` を管理者専用の `post_hidden_geo` へ退避し、公開列は NULL（REQ-329） |
| 非公開スポット（クイック保存） | 別テーブル `private_spots`。RLS で本人と管理者だけ・anon には GRANT 自体が無い（REQ-329） |
| 通報者・投稿者の IP | `reporter_ip` を列レベルで保護。管理画面でも既定はマスク表示 |
| 写真の撮影位置 | アップロード前にブラウザで EXIF を除去 |
| メールアドレス | 公開データセットにも公開プロフィールにも出さない |

## 列レベル保護の落とし穴（過去に本番で漏れた）

**「テーブル全体に GRANT SELECT してから、特定の列だけ REVOKE SELECT」では列を保護できない。** PostgreSQL のテーブルレベル付与は全列をカバーし、後続の列単位 REVOKE はそれを分解しない。列だけ剥がしたつもりでもテーブル付与が残り続ける。

**旧実装はこれで no-op になっており、本番で `reporter_ip` が anon から読めていた**（migration `20260615000001` では保護できておらず `20260616000005` で是正）。

正しいやり方は、**テーブル付与を剥がしたうえで「守りたい列を除く全列」を列挙して列単位で GRANT し直す**こと。

**列を足したらこの列挙もやり直しになる。** だから `schema.sql` では、posts の全 `ALTER` が終わったファイル末尾でこのブロックを実行している。途中に置くと後から足した列に SELECT が付かない。

正本: `supabase/schema.sql` の末尾「REQ-179: reporter_ip 列レベル保護」

## IP のマスク

管理画面の通報一覧では IP を既定でマスクし、「表示」トグルで原文を見る。**保存値は変えない（表示だけ）。**

IPv4 は末尾オクテット、**IPv6 は先頭 3 ハイテット（≒ /48）だけ残して以降を伏せる**。以前は IPv4 しか考えておらず IPv6 がフルで出ていた。正本: `src/lib/maskIp.ts`

## 公開プロフィール

`user_profiles` は `is_public = true` のとき、**配信停止トークン（`unsubscribe_token`）以外の全列が anon から読める**。トークンは列単位の権限で隠してある。読めると、`apply_unsubscribe` で他人の通知を止められるためだ（2026-10-21 に是正）。列を足したときは、読ませたい列に `GRANT SELECT (列)` を打たない限り読めない（安全側）。

非公開（`is_public = false`）の利用者の図鑑と進捗（`get_user_collection` / `get_user_progress`）は、本人以外には、未ログインを含めて 0 行を返す。

**だから公開したくない情報を user_profiles に列として足さないこと。** REQ-325 のオンボーディング回答（居住地域）を別テーブル `user_onboarding` に切り出したのはこれが理由。プロフィールに足すと地域が誰にでも見えてしまう。

同じ判断が必要になったら、own-row RLS の別テーブルを作る。

## 関数の実行権限は、既定で閉じる

ブラウザが直接呼べる関数（RPC）は、そのまま攻撃の入口になる。匿名（anon）に見せてよい SECURITY DEFINER 関数は 9 本だけ（ランキング・公開プロフィール・配信停止・実験の割付）で、許可リストは `supabase/tests/req316_function_execute_default_closed.sql`。内部専用（通知・保守・集計の再計算）は service_role だけ、管理者・本人用はログイン済みだけが実行できる。

これから作る関数は、明示の `GRANT` が無ければ匿名・ログイン済みから実行できない（`ALTER DEFAULT PRIVILEGES`）。`REVOKE ... FROM anon` だけでは PUBLIC 経由で実行できてしまうので、閉じるときは `FROM PUBLIC` を先に打つ。許可リストに無い関数が匿名で実行できると、CI の DB テストが落ちる。経緯は REQ-316。

## 回数制限は、受付時刻で数える

投稿・コメント・いいね・通報などの回数制限は、保存済みの行を `created_at` で数える。一般ユーザーの INSERT は `created_at` を受付時刻に固定し、UPDATE では変えさせない（トリガー `aaa_pin_created_at`）。固定しないと、過去の日時を付けて上限を回避できる。観察した日は `observed_at` が持つ。管理者・service_role・SQL の直接実行は固定しない。投稿を消して作り直すと枠が戻る点は、今は塞いでいない。

## 退会

退会（`delete_own_account`）は、会員のアカウントを消す。投稿は持ち主の結び付きだけ外して残り、監査ログは行を残して記録者の欄だけ空にする。投稿の保護トリガーは持ち主の付け替えを防ぐが、旧い持ち主がもう `auth.users` にいないときの NULL 化だけは通す（これが無いと、投稿のある会員が退会できなかった）。コメントを残すか消すかは、`schema.sql`（匿名で残す）と migration `20260323000001`（消す）が食い違ったままで、本人の判断待ち。公開の写真・音声の実体は消えず、URL には旧 UID が残る。

## 写真

アップロード前に**ブラウザ側で** EXIF を除去し、長辺 1280 px にリサイズして JPEG 化する。サーバーに届く時点で位置情報は入っていない。正本: `src/lib/imageProcessor.ts`

変換に失敗すると `processImage` は原本（位置情報つき）をそのまま返す。**原本のまま・JPEG でない・空のときは、公開の保管先へ送らない。** 新規投稿・希少種・水域に加えて、投稿の編集で足す写真も同じ（`uploadPhoto`）。編集で 1 枚でも上げられなければ、古い写真を消さず、投稿を更新せず、エラーを出して止める。

## 投稿を消しても実体は残る

`posts` を削除すると comments / likes / reports は CASCADE で消えるが、**Storage の写真・音声の実体は参照が切れるだけで残る**。投稿を削除する処理（本人・管理者の単体と一括・通報画面）は、写真・AI 判定用の縮小版（`<id>.ai.jpg`。本体と別のオブジェクト）・音声を保管先から消してから行を消す（`src/lib/postMedia.ts` の `removePostMedia`。消せなければ行も消さない。管理者側は記録して続ける）。削除処理を書くときは、これを使うこと。

ゲーミフィケーションの集計も自動では戻らない。投稿が 0 件になった利用者の `user_progress` / `user_collection` の行は残るので、手で消す必要がある。バッジに剥奪ロジックは無い。

## 非公開スポットと外部の地図アプリ

非公開スポットは希少種の生息地を含み得る。**経路ボタンで外部の地図アプリへ渡すのは座標だけ**で、スポットの名前は URL に載せない（`src/lib/maps/routeLinks.ts`）。圏外で保存した分は送信まで端末の localStorage に残る（利用者 ID 付き。別の人がログインしても送らない）。座標が入るので、ログアウトの前の確認（送ってから出る／破棄して出る／やめる）と退会が、この送信待ちも扱う（同じ端末のほかの人の分は残す）。

アカウントが替わると地図のスポット表示と送信待ちを作り直し、前のアカウントの応答（送信中に返ってきたものを含む）は今のアカウントの画面に入れない。同じ画面で同じ送信待ちを二重に送らない（`src/hooks/usePrivateSpots.ts`）。ただし別のタブとの重複や、応答が途切れたあとの再送までは防げない（DB に重複を弾く鍵が無い）。

## 希少種の記録と調査計画

希少種の記録は投稿（posts）に入れず、別表 `rare_sightings` と非公開の写真置き場 `rare-photos` に置く。posts から出ていく道（RLS を通らない公開 RPC・誰でも一覧できる `post-photos`・全件公開の comments と likes）に除外条件を足し続けると、1 か所の書き忘れで生息地が公開されるからだ。調査計画と地点、地点と投稿のつながりも別表にしてある。どれも本人と管理者しか読めず、anon には GRANT 自体が無い。

**公開の関数がこれらの表を読み始めたら CI が止める**（`npm run private-tables:check`）。表に触れてよい関数は許可リストで決めてあり、足す前に anon が実行できないことを確かめる。

写真は 1 時間の署名 URL でだけ見せ、公開 URL は作らない。EXIF を消せなかった写真は送らない。記録を消しても写真の実体は残るので、写真も一緒に消す。

画面でも場所を漏らさない。本人の地図にも希少種の記録は既定で出さず（画面写真を人に見せたときに生息地が漏れないように）、「希少種を地図に表示」を入れたときだけ出す。希少種の記録がある地点から作る投稿は、位置を hidden にする（外来種の公開投稿の位置から池を推測されないように）。外部の地図アプリへ渡す URL は座標だけ。端末に残す計画の控えと送信待ちは利用者 ID ごとに別の保存先に置き、別の人がログインしても出さず送らない。詳細は [fieldwork.md](./fieldwork.md)。
