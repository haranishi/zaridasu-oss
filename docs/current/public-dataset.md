# 公開データセット — いまの仕様

> 「いま何が正しいか」だけを書く。「そのとき何を変えたか」は `docs/requirements/REQ-*.md`（履歴）。
> 食い違ったら**コードが正**。正本: `src/app/dataset/zaridasu.csv/route.ts`

`/dataset` から CSV と GeoJSON を配布している。**これは外部に配った成果物なので、他の画面と違って「後方互換」を守る対象**。

## 何を配るか

**承認済み（`status = 'approved'`）の投稿だけ。** 未承認・却下は入らない。

座標は**小数第 3 位（約 111 m グリッド）に粗化**する。位置非公開（`hidden`）の投稿は座標が NULL になるため、**行ごと除外**される。座標が壊れている行（NaN 等）も除外する。0,0 のような値で埋めない。

**PII は一切含めない**: `user_id`・メール・`reporter_ip`・自由記述の `comment`・写真・`accuracy`（高精度の手がかりになるため）。

ライセンスは **CC BY 4.0**（`DATASET_LICENSE_NAME`）。コードの MIT とは別物で、互いに及ばない。

## 列は 1 つの表から導出する

`DATASET_COLUMNS` に「ヘッダ名・DB の列・値の取り出し方・GeoJSON に入れるか・説明文」を 1 行ずつ書き、**CSV ヘッダ・CSV 行・GeoJSON の properties・`/dataset` ページの説明表・SELECT 文をすべてここから導出する**。

こうしてあるのは、**ヘッダの配列と行の組み立てが別々のリストだと、列を足したときに値がずれるから**。同じ要素から出るので、順序の不一致が起こりようがない。列を足すときはこの表に 1 行足すだけでよい。

一部の列は DB に無い導出値（`select: null`）。種名は **i18n に依存しない安定キー（`species_code`）と、人間向けの日本語ラベル（`species_label_ja`）を両方出す**。ラベルだけだと翻訳を変えたときに配布済みデータと食い違う。

## 変えてはいけないもの

- **ヘッダ名**。配布済みデータを読んでいる人のスクリプトが壊れる
- **列の並び**
- **粗化の桁数**。細かくすると過去に配ったものより精度が上がり、位置情報の約束が変わる

列を**足す**のは互換性を壊さないので構わない。

## アプリ内の CSV 出力とは別物

`useCsvExport`（アプリの画面から出す CSV）とは**列が違う**。

| | 公開データセット | アプリ内 CSV |
| --- | --- | --- |
| locality・water_body | あり | なし |
| 天候・気温・湿度 | なし | あり |
| 座標の列名 | `display_lat` そのまま | `lat` へエイリアス |

**どちらかに寄せないこと。** 公開側は配布済みデータの契約で、アプリ内は利用者向けの利便。目的が違う。

## 流量の制限はアプリの外で

大量取得への対策は **Vercel Firewall か Cloudflare のレート制限ルール**で敷く。アプリ内のトークンバケットはインスタンスごとに揮発する粗いふるいで、分散アクセスには効かない。重いレートリミッタや新しい依存を入れない。

アプリ側にあるのは CDN キャッシュ・入力の許可リスト・座標粗化・`DATASET_MAX_ROWS` の上限まで。手順は `docs/runbooks/dataset-og-rate-limiting.md`。

## 取得の作り

1000 行で切れないよう、短いページが返るまで offset を進めて全件取る（`DATASET_MAX_ROWS` が絶対上限）。**Supabase のクエリビルダは await 後に再利用できない**ので、ページごとに組み直している。

環境変数が未設定のときは空配列を返す（fail-open）。配布物が壊れるより空の方がまし、という判断。
