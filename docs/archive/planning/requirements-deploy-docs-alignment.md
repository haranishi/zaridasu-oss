# デプロイ設定とドキュメント整合化 要件定義

## 1. 概要
- 対象課題: 実運用設定と README の記載不一致
- 優先度: 中
- 作成日: 2026-03-14

## 2. 背景
README の説明、`vercel.json`、`public/_redirects` の役割分担が曖昧だと、環境構築と障害時対応に時間がかかる。新規参加者が短時間で再現できるドキュメント整備が必要。

## 3. 目的
- 開発者が 30 分以内にローカル起動できる状態にする
- デプロイ先・手順・ロールバック手順を明文化する

## 4. スコープ
### 対象
- README のデプロイ/ローカル手順
- `vercel.json` と `_redirects` の責務説明
- リリース/ロールバック手順

### 非対象
- デプロイ基盤そのものの乗り換え
- CI/CD パイプライン全面改修

## 5. ユーザーストーリー
As a 開発メンバー,
I want to 実運用に一致した手順で環境構築とデプロイを行いたい,
So that 作業ミスと初期セットアップ時間を削減できる。

## 6. 受け入れ条件
- [ ] README の記載が現行運用に一致する
- [ ] `vercel.json` と `_redirects` の使い分けが明記される
- [ ] リリース手順とロールバック手順が文書化される
- [ ] 新規メンバーが README のみで 30 分以内に起動できる

## 7. 機能要件
| ID | 要件 | 優先度 |
|---|---|---|
| F1 | README のデプロイ先表記を実態に合わせて修正する | 高 |
| F2 | ルーティング設定ファイルの責務を図または表で説明する | 中 |
| F3 | リリースチェックリストを追加する | 中 |
| F4 | 障害時のロールバック手順を追加する | 高 |

## 8. 非機能要件
- 手順は 1 人で再現できる
- 記載コマンドはそのまま実行可能
- 更新時期と責任者が分かる

## 9. 実装方針
- まず現行運用を確認して事実ベースで更新
- 手順は最短導線を優先し、分岐は最小限にする
- 変更時にチェックリストも同時更新する

## 10. テスト観点
- README 手順のみで起動できるか
- ビルドと本番ルーティングの再現
- ロールバック手順の実行可能性

## 11. 完了定義
- ドキュメントレビュー完了
- 新規メンバー検証で 30 分以内起動達成
- リリース時の参照先が一本化
