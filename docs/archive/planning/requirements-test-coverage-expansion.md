# テストカバレッジ拡大 要件定義

## 1. 概要
- 対象課題: 主要機能の回帰検知力不足
- 優先度: 高
- 作成日: 2026-03-14

## 2. 背景
現状カバレッジは statements 65.08%、branches 53.58%、functions 49.34% で、品質ゲート目標（80/70）を下回っている。特に HomePage、EditDialog、storage ユーティリティ周辺の未検証領域が大きく、回帰リスクが高い。

## 3. 目的
- リリース前に主要フローの破壊的変更を自動検知できる状態にする
- テスト結果を CI の合否に直結させる

## 4. スコープ
### 対象
- 投稿作成フロー
- 認証フロー（ログイン、登録、ガード）
- 地図と一覧の同期挙動
- 管理操作の代表フロー（投稿削除または通報解決）

### 非対象
- E2E テスト導入
- デザイン改修のみの変更

## 5. ユーザーストーリー
As a 開発者,
I want to 主要画面と主要 hooks の回帰テストを網羅したい,
So that 本番障害をリリース前に検出できる。

## 6. 受け入れ条件
- [ ] 重要フローに対して新規テストを最低 8 件追加する
- [ ] 失敗系テストを最低 3 件追加する
- [ ] `npm test` が CI 上で常時実行される
- [ ] カバレッジ閾値を statements >= 80, branches >= 70 に設定する
- [ ] 低カバレッジ領域（HomePage, EditDialog, storage）にテストが追加される

## 7. 機能要件
| ID | 要件 | 優先度 |
|---|---|---|
| F1 | `src/pages/HomePage.jsx` のフィルタ、件数整合、エラー表示を統合テストする | 高 |
| F2 | `src/components/modals/EditDialog.jsx` の更新成功/失敗/バリデーションをテストする | 高 |
| F3 | `src/utils/storage.js` の成功/失敗パターンを unit test で検証する | 高 |
| F4 | 投稿作成と認証の主要フローを失敗系含めてテストする | 高 |
| F5 | Supabase モックを共通化し、各テストで再利用可能にする | 中 |
| F6 | カバレッジ閾値を Vitest 設定で強制する | 高 |

## 8. 非機能要件
- テスト実行時間はローカルで 30 秒以内を維持する
- flaky test 発生率を 0% にする

## 9. 実装方針
- React Testing Library + Vitest を継続利用
- ネットワーク依存はモック化し、外部 API に依存しない
- ページ系は user-event 中心、hooks は単体で網羅

## 10. テスト観点
- 正常系: 投稿できる、編集できる、画面遷移できる
- 異常系: API 失敗、権限不足、入力不備
- 境界値: 空入力、最大件数、未ログイン

## 11. 完了定義
- CI 上で閾値を満たした状態でテストが green
- 追加テストが PR でレビュー済み
- 既存機能の回帰がない
