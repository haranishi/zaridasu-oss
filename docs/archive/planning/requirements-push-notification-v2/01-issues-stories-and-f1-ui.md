
## 現状の課題

1. PWA 対応済みだが、**Push 通知機能が未実装**（Service Worker に push ハンドラーなし）
2. 新しい目撃情報が投稿されてもユーザーに能動的に伝える手段がない（メール通知もなし）
3. API-005 の要件定義は存在するが、**UX フロー・エラーハンドリング・アクセシビリティの詳細が不足**
4. iOS の制約（16.4+、ホーム画面追加必須）への対応設計が不十分

## ユーザーストーリー

| # | 対象ユーザー | やりたいこと | 理由 | 受け入れ条件 |
|---|------------|------------|------|------------|
| US1 | 地域住民 | 自分の市区町村に出没情報が投稿されたらスマホに通知が来てほしい | 即座に対処行動を取れる | 指定市区町村の投稿のみ通知される |
| US2 | 農業従事者 | 「農業被害」種別の投稿のみ通知してほしい | 農地被害の早期発見に直結する情報だけ受け取りたい | info_type フィルタが機能する |
| US3 | 研究者 | ウシガエル+捕獲の投稿のみを通知してほしい | データ収集の機会を逃さず現地調査を計画できる | species + info_type の組み合わせフィルタが機能する |
| US4 | ライトユーザー | 通知が多すぎたら簡単にオフにしたい | うるさい通知は即アンインストールに繋がる | ワンタップで通知 OFF + 設定ページから再 ON |
| US5 | iOS ユーザー | iPhone でも通知を受けたい | Android と同等の体験がほしい | iOS 16.4+ でホーム画面追加済みなら動作する |

## 機能要件

### F1: 通知購読 UI（DashboardPage 内 `PushNotificationCard`）

**状態遷移図**:

```
[未購読]
   │
   ├── ブラウザが Push 非対応 → 「お使いのブラウザは通知に対応していません」（グレーアウト）
   ├── iOS 16.4 未満 → 「iOS 16.4 以降 + ホーム画面追加が必要です」（グレーアウト + 手順リンク）
   ├── iOS 16.4+ だが standalone でない → 「ホーム画面に追加してから通知を有効にしてください」（手順表示）
   │
   └── 対応環境 → 「通知を受け取る」トグル表示
                      │
                      └── ON クリック
                            │
                            ├── Notification.requestPermission()
                            │     ├── 'granted' → PushManager.subscribe() → DB 保存 → [購読中] 状態へ
                            │     ├── 'denied' → 「ブラウザの設定から通知を許可してください」+ 設定手順
                            │     └── 'default'(閉じた) → トグル OFF に戻す
                            │
                            └── [購読中]
                                  ├── フィルタ条件設定 UI 表示
                                  └── OFF クリック → unsubscribe + DB 削除 → [未購読] に戻る
```

**フィルタ条件設定 UI**:

| 設定項目 | UI | デフォルト |
|---------|-----|---------|
| 市区町村 | MUNICIPALITIES から複数選択チェックボックス | 全て（空配列 = 全域） |
| 種別 | american / bullfrog チェックボックス | 両方 ON |
| 情報種別 | sighting / capture / trace / damage / absence チェックボックス | 全て ON |

- フィルタ変更は即座に DB に保存（デバウンス 500ms）
- 「全てリセット」ボタンでデフォルトに戻す
