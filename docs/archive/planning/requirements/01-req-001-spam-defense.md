### REQ-001: スパム対策強化

**背景**
匿名投稿の制限が `localStorage` のクライアント側のみに依存している。localStorage は容易に偽造・削除が可能であり、大量スパムを許容してしまう。DBトリガーによるサーバー側制限は存在するが（匿名: 1分3件）、IPアドレスベースの制御が不十分。

#### ユーザーストーリー

```
As a サービス管理者,
I want to スパム投稿を自動的にブロックしたい,
So that データ品質を維持し、正常な利用者の体験を守ることができる。

受け入れ条件:
- [ ] クライアント側の localStorage チェックに加え、サーバー側でも制限を実施する
- [ ] 匿名ユーザーは IP ベースで 1分以内3件・24時間以内10件を超えた場合にブロックされる
- [ ] 認証ユーザーは 24時間以内5件を超えた場合にブロックされる（現行維持）
- [ ] ブロック時に「次に投稿できる時刻」をユーザーに通知する
- [ ] 管理者はレート制限の対象外
- [ ] honeypot フィールドによるボット検知を維持する
- [ ] 通報（reports）が多い投稿者の投稿は自動フラグを立てる
```

#### 機能要件

| # | 要件 | 優先度 |
|---|------|--------|
| F1 | Supabase DBトリガー `check_post_rate_limit` の匿名制限を IP ベースに変更する | 高 |
| F2 | `reporter_ip` を posts テーブルに追加し、IP を記録する（表示はしない） | 高 |
| F3 | Supabase Edge Function でリクエストの IP を取得して投稿時に渡す | 高 |
| F4 | スパム判定時のエラーメッセージに次回投稿可能時刻を含める | 中 |
| F5 | 通報数が閾値（3件）を超えた投稿に `is_flagged` フラグを立てる DB トリガーを追加 | 中 |

#### 非機能要件

- IP の保存は個人情報として扱い、90日後に自動削除する
- Edge Function の処理時間は 200ms 以内

#### 現状の制限との差分

```
現状:
  匿名: DB側 → 1分以内3件（同一ユーザーID=NULL の投稿数で判定）
  認証: DB側 → 24h以内5件（user_id で判定）
  クライアント: localStorage で24h5件チェック（偽造可能）

改善後:
  匿名: DB側 → IP ベースで 1分以内3件 + 24h以内10件
  認証: DB側 → 現行維持（user_id で24h5件）
  クライアント: 維持（UX のための事前チェック）
  honeypot: 維持
```
