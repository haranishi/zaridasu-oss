### REQ-003: エラーハンドリングの統一化

**背景**
`console.error()` のみでユーザーに何も伝えない箇所が複数存在する。また、エラーの種類（ネットワーク/バリデーション/権限/サーバー）によって対応が異なるが、統一されたパターンがない。

#### ユーザーストーリー

```
As a 一般ユーザー,
I want to 操作が失敗したときに何が起きたか・どうすれば良いかを知りたい,
So that 混乱せずに適切に対処できる。

受け入れ条件:
- [ ] 全ての API 呼び出しにエラーハンドリングが存在する
- [ ] エラー発生時にユーザー向けのメッセージが toast または インライン表示される
- [ ] エラーメッセージは日本語で、原因と対処法が明確である
- [ ] 開発環境では詳細なスタックトレースがコンソールに出力される
- [ ] 本番環境では機密情報（スタックトレース）はユーザーに表示しない
- [ ] ネットワークエラーと権限エラーは異なるメッセージで区別される
- [ ] エラー後に再試行できる操作では「再試行」ボタンを表示する
```

#### 機能要件

| # | 要件 | 優先度 |
|---|------|--------|
| F1 | エラーハンドリングユーティリティ `src/utils/errorHandler.js` を作成する | 高 |
| F2 | Supabase エラーコードに対応した日本語メッセージマッピングを定義する | 高 |
| F3 | `CommentSection.jsx` の `notify-comment` silent catch を適切なログに変更する | 中 |
| F4 | `useDeletePost.js` のストレージ削除失敗を個別にユーザーへ通知する | 中 |
| F5 | ErrorBoundary をページレベルに追加（現状: アプリ最上位のみ） | 中 |
| F6 | オフライン状態でのエラーメッセージを専用化する（「インターネット接続を確認してください」） | 低 |

#### エラーメッセージ設計

```
エラー種別 → メッセージ例:
  ネットワーク: 「通信エラーが発生しました。インターネット接続を確認してください。」
  認証切れ:    「セッションが切れました。再度ログインしてください。」
  権限なし:    「この操作を行う権限がありません。」
  レート制限:  「投稿頻度が高すぎます。しばらく時間をおいてください。」
  サーバー:    「サーバーエラーが発生しました。しばらく後に再試行してください。」
  バリデーション: （フィールド別に個別表示）
```

#### エラーハンドラー設計

```javascript
// src/utils/errorHandler.js
export function handleSupabaseError(error, context = '') {
  if (import.meta.env.DEV) {
    console.error(`[${context}]`, error)
  }
  // エラーコード → ユーザー向けメッセージへのマッピング
  // toast.error() でユーザーへ通知
}
```
