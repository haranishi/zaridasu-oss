# React Router v7 移行リスク対応 要件定義

## 1. 概要
- 対象課題: React Router future flag 警告の放置
- 優先度: 中
- 作成日: 2026-03-14

## 2. 背景
テスト実行時に `v7_startTransition` と `v7_relativeSplatPath` の警告が出ている。現時点で動作していても、将来アップグレード時に挙動差分や不具合が顕在化する可能性がある。

## 3. 目的
- v7 移行時の挙動差分を先行検証する
- ルーティング挙動をテストで固定化する

## 4. スコープ
### 対象
- ルーター生成箇所
- `/`, `/detail/:id`, `/dashboard`, `/admin`, `*` の主要ルート
- リダイレクトとガード挙動

### 非対象
- URL 設計そのものの変更
- 新規ページ追加

## 5. ユーザーストーリー
As a 開発者,
I want to Router v7 で変わる挙動を先に吸収したい,
So that ライブラリアップデート時の障害を防げる。

## 6. 受け入れ条件
- [ ] 警告対象の future flag 方針（有効化または延期理由）が明文化される
- [ ] 主要ルートの回帰テストが追加される
- [ ] 未認証時と認証時のガード挙動が仕様通りである
- [ ] 404 ルートが期待通りに表示される

## 7. 機能要件
| ID | 要件 | 優先度 |
|---|---|---|
| F1 | Router 設定で future flag の適用可否を決定し実装する | 高 |
| F2 | トップ、詳細、管理、404 の遷移テストを追加する | 高 |
| F3 | ルートガード（未認証/認証済み）をテストで担保する | 高 |
| F4 | 移行方針を docs に追記する | 中 |

## 8. 非機能要件
- 既存 URL 互換を維持する
- 既存 SEO 導線に影響を与えない

## 9. 実装方針
- まず現行挙動をテストで固定
- 次に future flag を段階的に検証
- 差分が出る箇所は仕様として明文化

## 10. テスト観点
- ルートごとの表示検証
- リダイレクトの行き先検証
- 存在しない URL の 404 検証

## 11. 完了定義
- future flag 警告が解消済み、または意図的延期が記録済み
- 主要ルート回帰テストが green
