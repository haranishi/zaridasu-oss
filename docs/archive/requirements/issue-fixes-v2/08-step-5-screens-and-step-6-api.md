## Step 5: 画面仕様

本タスクは既存画面の品質改善のため、新規画面はなし。変更が入る画面を列挙：

### SC-001: エラーページ（新規）
- **URL:** 全ルート（error.tsx）
- **用途:** 未ハンドルエラーのフォールバック表示
- **レイアウト:**
  ```
  +---------------------------+
  | 🦞 ザリダスロゴ            |
  +---------------------------+
  | エラーメッセージ           |
  | [再試行ボタン]             |
  | [ホームに戻る]             |
  +---------------------------+
  ```
- **状態管理:**
  - エラー発生時: エラーメッセージ + 再試行/ホームリンク表示
  - reset() 呼出し後: ページ再レンダリング試行

### SC-002: オフラインページ（既存改修）
- **URL:** /offline
- **変更:** Service Worker からのフォールバック先として統合
- **追加:** `robots: { index: false }` メタタグ

## Step 6: API仕様

本タスクでは新規 API エンドポイントの追加なし。変更のみ：

### API-001: Supabase RLS ポリシー更新
- **対象:** posts テーブル
- **変更:** `public_insert` ポリシーを DROP し、`auth_insert` のみ残す
- **影響:** 未認証ユーザーは直接 INSERT 不可（既存動作: 匿名投稿は認証済みユーザーの is_anonymous=true で実現）

### API-002: ミドルウェア認証フロー変更
- **対象:** `/admin/*` ルート
- **変更:** `getSession()` → `getUser()` （DB 検証）
- **対象外:** `/dashboard/*` は `getSession()` のまま
