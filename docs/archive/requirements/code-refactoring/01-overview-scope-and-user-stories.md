## 要件概要

### 背景・目的
- コードベースが成長し、一部のファイルが肥大化（最大965行）、型安全性の欠如、コードの重複が発生している
- 新機能追加やバグ修正の際に影響範囲が読みにくく、開発効率が低下している
- 以下の課題を解決し、保守性・開発効率を向上させる：
  1. `Record<string, any>` や `: any` の多用による型安全性の欠如
  2. 400行超のファイルが10個存在し、責務が不明確
  3. フォーカストラップ・天気アイコン・日付ロケールなどの重複コード
  4. `@/` エイリアスと相対パスの混在
  5. 管理画面のハードコード日本語文字列（i18n未対応）
  6. `themeClasses` ヘルパーの不統一な利用

### スコープ
**今回対象：**
- 型定義の整備と `any` 型の排除
- 400行超ファイルの分割・責務分離
- 重複コードの共通化（フォーカストラップ、天気アイコン、日付ロケール）
- インポートパスの統一（`@/` エイリアス）
- 定数ファイルの分割
- テーマクラスヘルパーの統一適用

**対象外：**
- 機能追加・UI変更
- DB スキーマ・マイグレーション変更
- テストの追加（別タスクとして管理）
- i18n の管理画面対応（別タスクとして管理）
- パフォーマンス最適化

### 前提条件・制約
- Next.js 15 App Router + React 19 のアーキテクチャを維持
- 既存の動作・UI を変更しない（リファクタリングのみ）
- Supabase クライアントの呼び出しパターンは維持
- ビルドが通ること、既存テストが通ることを確認

## ユーザーストーリー

### US-001: 型安全な開発体験
**As a** 開発者,
**I want to** すべての Post 関連データに適切な型定義があってほしい,
**So that** IDE の補完が効き、ランタイムエラーを事前に防げる.

**受け入れ条件:**
- [ ] AC-1: `Record<string, any>` が全ファイルから排除されている
- [ ] AC-2: Post の型バリエーション（PostWithAI, PostWithMetadata 等）が `src/types/` に定義されている
- [ ] AC-3: `tsc --noEmit` がエラーなしで通る

**優先度:** 高
**見積もり:** M

### US-002: コンポーネントの責務分離
**As a** 開発者,
**I want to** 各ファイルが300行以内に収まり、単一責務であってほしい,
**So that** 変更時の影響範囲を局所化でき、コードレビューしやすくなる.

**受け入れ条件:**
- [ ] AC-1: 400行超のファイルがすべて分割されている
- [ ] AC-2: 分割後もUIと動作が変わらない
- [ ] AC-3: 各コンポーネントが単一の責務を持つ

**優先度:** 高
**見積もり:** L

### US-003: DRY原則の適用
**As a** 開発者,
**I want to** 重複コードが共通モジュールに集約されていてほしい,
**So that** 修正が1箇所で済み、不整合が起きない.

**受け入れ条件:**
- [ ] AC-1: フォーカストラップが共通フック `useFocusTrap` に統一されている
- [ ] AC-2: `WEATHER_ICONS` と `DATE_LOCALES` が1箇所に定義されている
- [ ] AC-3: 重複定義が全ファイルから排除されている

**優先度:** 高
**見積もり:** S

### US-004: 一貫したコードスタイル
**As a** 開発者,
**I want to** インポートパスとテーマ適用方法が統一されていてほしい,
**So that** コードの可読性が高く、新規参入者も迷わない.

**受け入れ条件:**
- [ ] AC-1: 全ファイルで `@/` エイリアスが使用されている
- [ ] AC-2: ダークモードの適用に `themeClasses` ヘルパーが使用されている
- [ ] AC-3: 相対パス `../` のインポートが排除されている

**優先度:** 中
**見積もり:** M
