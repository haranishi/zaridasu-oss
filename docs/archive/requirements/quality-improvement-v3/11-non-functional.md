## Step 4: 非機能要件

### パフォーマンス

| 指標 | 目標値 | 備考 |
|------|--------|------|
| FCP (First Contentful Paint) | < 1.5秒 | モバイル4G回線基準 |
| LCP (Largest Contentful Paint) | < 2.5秒 | 地図描画を含む |
| TTI (Time to Interactive) | < 3.5秒 | 投稿フォーム操作可能まで |
| JS Bundle (メイン) | < 200KB (gzipped) | 地図ライブラリを除く |
| メモリ使用量 | 安定（リーク無し） | 30分操作後も増加なし |
| RPC レスポンス | < 2秒 | get_user_profile, get_user_ranking |
| 画像処理 | < 5秒/枚 | Worker 処理 + アップロード |
| オフラインキュー送信 | < 10秒/件 | 写真3枚含む |

### セキュリティ

| 項目 | 要件 |
|------|------|
| CSP | nonce ベース、unsafe-inline/unsafe-eval 除去 |
| HSTS | max-age=63072000; includeSubDomains; preload |
| 認証 | Supabase Auth（JWT）、管理者は `getUser()` で DB 検証 |
| RLS | 全テーブルで有効、ポリシーはスキーマと整合 |
| 入力サニタイズ | クライアント + DB 制約の2層バリデーション |
| ファイルアップロード | 画像のみ、最大5MB、EXIF除去、リサイズ |
| レートリミット | DB トリガー（投稿5件/24h、調査依頼3件/24h） |

### 可用性・信頼性

| 項目 | 要件 |
|------|------|
| 稼働率 | Vercel SLA 準拠（99.99%） |
| オフライン対応 | Service Worker + IndexedDB でオフライン投稿保持（最大10件） |
| エラー復旧 | エラーバウンダリ（グローバル + 管理画面）でグレースフルデグレード |
| データバックアップ | Supabase 自動バックアップ（日次） |
| 監視 | Sentry でクライアント/サーバーエラーを自動収集 |

### アクセシビリティ

| 項目 | 要件 |
|------|------|
| WCAG レベル | 2.1 AA 準拠 |
| フォーカス管理 | 全モーダルにフォーカストラップ |
| 色コントラスト | 4.5:1 以上（通常テキスト）、3:1 以上（大テキスト） |
| フォーム | 全入力に `<label>` 要素 |
| 画像 | 全 `<img>` / `<Image>` にコンテキスト付き alt |
| ARIA | インタラクティブ要素に適切な aria-label |
| ライブリージョン | Toast に `aria-live="polite"` + `aria-atomic="true"` |

### レスポンシブ対応

| ブレークポイント | 対応 |
|-----------------|------|
| < 640px (sm) | モバイルファースト基準 |
| 640-768px (md) | タブレット |
| 768-1024px (lg) | デスクトップ |
| > 1024px (xl) | ワイドスクリーン |
